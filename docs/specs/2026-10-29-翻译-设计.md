# xPaste 翻译 设计

**版本：** v0.2　**状态：** 待评审　**日期：** 2026-10-29
**依据：** 功能规格说明 v0.1.24（1.2、5.2、第 8 章、M08、M13、M15、M19、M22、M23）
**目标阶段：** 阶段 15（规格说明新增 M26）

## 1. 意图

用户常在浏览器或终端里复制一段英文，想马上看中文意思；截图里的英文报错、界面文字也一样。现在只能另开翻译软件粘进去。

翻译做成两个入口，都是**用户手动触发**：

1. 面板里选中一条记录，按一个键，在预览区原文下方看到译文，可以复制。
2. 截图框选后按 `T`，识别文字并翻译，译文卡片直接出现在选区旁边，不用打开面板。

翻译有两种方式，在设置里选（**用户确认，本期两种都做**）：

- **系统翻译（本机）**：macOS 26 及以上用系统的 Translation 框架，完全离线，不需要配置，只需要在系统设置里下载语言包。Windows 没有系统翻译接口，不提供这一项。
- **OpenAI 兼容接口**：Chat Completions，流式输出；Base URL、API Key、模型 ID 由用户配置。Base URL 指向本机的 Ollama、LM Studio 时同样不出本机。

## 2. 目标、非目标、反目标

**目标**

1. 面板：文本、代码记录（含文字类片段），以及有识别文字的图片、文件记录，可以手动翻译，译文显示在预览区，可复制。
2. 截图：截图工具栏新增「翻译」动作（`T`），译文卡片显示在选区旁，可复制。
3. 设置新增「翻译」标签：翻译方式（系统翻译 / OpenAI 兼容接口）、Base URL、API Key、模型 ID、目标语言、测试连接。
4. 翻译结果存进本地数据库，再次选中同一条记录直接显示，不重复请求。

**非目标（本期不做，写进规格说明第 8 章）**

- 自动翻译（复制时、选中时自动发请求）。
- 把译文钉成贴图（贴图只支持图片，钉文字需要新的窗口类型）。
- 多个 OpenAI 兼容服务的配置、切换；Anthropic、Google 等非 OpenAI 格式的接口。
- 内置翻译模型；Windows 的本机翻译。
- macOS 15 上的系统翻译（那一版只能借 SwiftUI 界面调用，见 4.2）。
- 在 xPaste 里下载系统翻译语言包（引导用户去系统设置下载）。
- 译文参与搜索。
- 翻译链接、视频记录。

**反目标（即使功能上能用，出现以下情况也算失败）**

- 用户没有按翻译、没有点「测试连接」，应用却向翻译接口发了请求。
- 发出去的内容不是用户这次要翻译的那一条（例如带上了别的记录、来源应用名、文件路径）。
- 日志里出现原文、译文、API Key 或 Base URL 里的路径和参数。
- 翻译接口慢或不通时，面板的唤起、搜索、粘贴变慢或卡住；截图遮罩在等翻译时无法用 Esc 退出。
- 没配置翻译时，面板和截图里看不出该去哪里配置。

## 3. 交互（已和用户确认）

### 3.1 面板

**可翻译的记录**：文本、代码记录，文字类片段；图片记录和含图片的文件记录在「图中文字」状态为「有文字」时（翻译的是识别文字）。链接、视频、没有识别文字的图片和文件不可翻译，下面的入口都不出现。多选时不可翻译。

**入口**（三个入口都只对可翻译的记录出现）：

- 快捷键 `Mod + T`（macOS `⌘ T`，Windows `Ctrl + T`）。按住不连发。
- 预览顶部按钮「翻译」，放在「置顶」左侧，标注 `⌘T`。
- 右键菜单「翻译」（`Mod + T`），放在按类型的动作之后、「存为片段…」之前。片段的菜单同样有，放在「编辑片段…」之后。
- 图片和文件记录：「图中文字」区块右上角，在「复制文字」右边多一个「翻译」按钮。顶部「翻译」按钮与 `Mod + T` 也可用，效果相同（翻译识别文字）。

**译文区块**：

- 文本、代码记录：显示在原文下方；图片、文件记录：显示在「图中文字」区块下方。样式与「图中文字」区块相同（容器、标题行、右上角按钮），但**默认展开**、不可折叠。
- 标题行：`译文 · <目标语言名>`。右上角按钮：「复制译文」、「重新翻译」。
- 正文：保留换行，可选中；代码记录的译文用等宽字体。
- 翻译中（OpenAI 兼容接口为**流式输出，用户确认**）：区块立即出现，标题行写「翻译中…」，译文随接口返回逐段追加到正文里，按钮隐藏（系统翻译只能整段返回，收到后一次显示）；全部收完后标题换成 `译文 · <语言>`，按钮出现。逐段追加不加动效。翻译中再按 `Mod + T` 不发第二个请求。
- 中途失败（断线、空闲超时）：已收到的部分保留在正文里，标题行写「翻译中断」并在正文下方显示原因（3.4），右上角只有「重新翻译」；不完整的译文不存库。
- 失败：标题行写「翻译失败」，正文位置显示原因（见 3.4），右上角只有「重新翻译」。
- 已有译文的记录，选中时直接显示译文区块；没翻译过的记录不显示区块。
- 已有译文时，`Mod + T`、顶部「翻译」、菜单「翻译」（入口照常显示）只把预览滚到译文区块，**不发请求**，即使译文语言与当前目标语言不同；只有「重新翻译」会再发请求。上次失败时（区块显示「翻译失败」）三个入口等同「重新翻译」。
- 触发翻译后预览区滚动到让译文区块可见（减少动态效果时直接跳过去，M20）。

**复制译文**：只把译文作为纯文本写进剪切板，不新增历史记录、不计使用次数（同「复制文字」，M08 补充规则 4），提示「已复制译文」。

**选中项切换**：翻译进行中切到别的记录，请求不取消；结果回来后照常存库，回到这条记录时显示。界面只在当前预览的仍是这条记录时更新。

### 3.2 截图

- 工具栏在「识别文字（O）」右边新增按钮「翻译」，提示文字「识别文字并翻译  T」，图标由实现定（与现有图标同一线宽、风格）。键盘 `T`（不带修饰键；文字标注输入期间不生效）。
- 按下后：工具栏位置显示「正在翻译…」，状态与识别文字的「busy」相同（其他屏不能框选、不能出第二个动作，Esc 和截图快捷键仍可退出，退出后结果丢弃）。
- 先在本机识别选区文字（与 O 相同，长边缩到 8000 px，不落盘），再翻译识别文字。
- 识别完成、收到第一段译文时（系统翻译为整段译文到达时），选区右侧出现**译文卡片**，之后的译文逐段追加进卡片（流式）。卡片位置在出现时定一次：右侧放不下依次试左侧、下方、上方，都放不下时盖在选区内右上角；之后随内容变高，不再挪位置，最高到所在屏可用空间，超出时卡片内滚动并跟到最新一段。卡片宽度 240–360 逻辑像素。收完之前「复制译文」不可用；中途失败时卡片保留已收到的部分并显示原因，「复制译文」仍不可用。卡片：
  - 正文为译文，可选中；
  - 底部按钮「复制译文 ↵」「关闭 Esc」。
  - 卡片出现后工具栏隐藏，选区不能再调整、不能标注。
- 复制译文（点按钮或回车）：译文按普通写入写进剪切板，由剪切板监听作为一条文本记录入库（与 O 一致，M01 照常生效）；遮罩按现有成功流程淡出，提示条「已复制译文 · N 字，已加入历史」。
- 关闭（Esc、点「关闭」、再按截图快捷键）：直接退出截图，不写剪切板。
- 选区里没识别到文字：回到选区，提示条「选区里没有识别到文字」（同 O）。
- 翻译失败或没配置：回到选区，提示条显示原因（3.4），可以重试或改用别的动作。
- 卡片显示期间遮罩仍是冻结画面、仍占着键盘，平安心跳照常（M23 规则 1）。

### 3.3 设置：新增「翻译」标签

标签栏顺序：通用 · 记录 · 搜索 · 截图 · **翻译**。

| 设置项 | 控件 | 默认值 | 说明与校验 |
| --- | --- | --- | --- |
| 翻译方式 | 两段选择：系统翻译（本机）/ OpenAI 兼容接口 | macOS 26+ 为「系统翻译」，其余为「OpenAI 兼容接口」 | 仅 macOS 显示；低于 macOS 26 时「系统翻译」不可选，说明「需要 macOS 26」。选系统翻译时下面三项（Base URL、API Key、模型 ID）置灰，保存时照常带上；并在本项下方显示语言包状态：「英语 ↔ <目标语言>：已下载」或「需要下载语言包」加按钮「打开系统设置」（跳到 语言与地区 › 翻译语言） |
| 接口地址（Base URL） | 文本输入 | `https://api.openai.com/v1` | 说明：「兼容 OpenAI 接口的地址。用本机的 Ollama 可填 `http://localhost:11434/v1`，翻译不出本机」。必须以 `http://` 或 `https://` 开头，否则「请输入 http:// 或 https:// 开头的地址」。末尾的 `/` 去掉后保存 |
| API Key | 密码输入，带显示 / 隐藏按钮 | 空 | 说明：「只保存在本机」。可以为空（本机服务多数不需要），为空时请求不带 `Authorization` 头 |
| 模型 ID | 文本输入 | 空，占位 `gpt-4o-mini` | 为空视为「未配置」 |
| 目标语言 | 下拉 | 简体中文 | 简体中文、繁體中文、English、日本語、한국어 |
| 测试连接 | 按钮 | — | 用**当前表单里**（未保存）的值翻译固定短句 `Hello, world.`，按钮旁显示「✓ 连接正常：<译文>」或失败原因（3.4）。测试期间按钮不可再点 |

- 标签顶部一行说明（隐私）：选 OpenAI 兼容接口时「翻译时，只把你选中要翻译的那段文字发送到上面的接口；不按翻译就不会发送任何内容」；选系统翻译时「在本机完成，不上传」。
- 「未配置」：OpenAI 兼容接口时为模型 ID 为空或 Base URL 为空；系统翻译不存在未配置（缺语言包见 3.4）。
- 测试连接对两种方式都可用：系统翻译时用当前目标语言翻译 `Hello, world.`。
- 保存规则沿用 M15 交互规则 5（红点、跳到出错标签）。

### 3.4 错误与提示文案

| 情况 | 文案 |
| --- | --- |
| 未配置 | 「请先在设置的“翻译”里配置接口」；面板里的提示条带「去设置」按钮，打开设置并切到「翻译」标签；截图里只显示文字 |
| HTTP 401 / 403 | 「API Key 无效或没有权限」 |

| 系统翻译：这对语言不支持（含识别不出源语言） | 「系统翻译不支持这种语言」 |
| 系统翻译：系统低于 macOS 26（换回旧系统后设置里仍是系统翻译） | 「系统翻译需要 macOS 26，请在设置里改用 OpenAI 兼容接口」，带「去设置」 |
| 系统翻译：其他错误、30 秒没有结果 | 「系统翻译失败」/「翻译超时」 |
| 原文超过上限（3.5） | 「内容太长，最多翻译 10000 字」 |

### 3.5 翻译规则

- **方向**：原文的语言与目标语言相同时，改翻成英文；目标语言是英文且原文是英文时，改翻成简体中文。原文语言按以下顺序判断（简体与繁体不区分，都算中文）：
  1. 含假名 → 日文（日文里汉字常比假名多，不能按占比）；
  2. 含谚文 → 韩文；
  3. 汉字多于拉丁字母 → 中文；拉丁字母多于汉字 → 英文；
  4. 其他情况（打平、只有数字符号、俄文等其他文字）→ 视为「不是目标语言」，照常翻成目标语言。

  实际翻成的语言记在译文上，区块标题显示实际语言。
- **长度上限**：原文最多 10000 个字符，超过时不发请求，按 3.4 提示。
- **系统翻译的源语言**：由 Swift 侧用 NaturalLanguage 的 `NLLanguageRecognizer` 识别原文主要语言作为源语言；目标语言用上面方向规则算出的结果。
- **提示词**（OpenAI 兼容接口）：system 消息要求「把用户消息翻译成 <语言>，只输出译文，保留原有换行和格式，代码、命令、URL、路径、变量名原样保留，不加解释」；user 消息为原文。`temperature` 设为 0。具体措辞由实现定。
- **缓存**：每条记录只存最新的一份译文和它的语言。改了目标语言后，已有译文照常显示（标题写着它的语言），点「重新翻译」按新设置翻译并覆盖。
- **译文失效**：片段内容被编辑、图片「重新识别」得到新文字时，清掉这条记录的译文。记录删除、清空历史时译文随之删除。

## 4. 实现

### 4.1 网络请求（`src-tauri`）

- 请求只从 Rust 侧发出，前端不直接访问网络，CSP 不改。
- `POST {base_url}/chat/completions`，JSON：`{ model, temperature: 0, stream: true, messages: [system, user] }`。API Key 非空时带 `Authorization: Bearer <key>`。
- 按 SSE 读响应：逐行取 `data: ` 后的 JSON，拼接 `choices[0].delta.content`，遇到 `data: [DONE]` 结束；收完后整体去掉首尾空白再存库。有的兼容服务忽略 `stream`、直接回整段 JSON：响应的 `Content-Type` 不是 `text/event-stream` 时按非流式解析 `choices[0].message.content`，当作一段一次性给出。
- 后端把增量合并后再发给前端（约每 50 ms 或攒满一定字数一发，由实现定），不每个 token 发一次事件。
- 超时：30 秒内没收到第一段，或两段之间超过 30 秒，判为超时；没有总时长上限。不自动重试。
- **代理（用户确认）**：跟随系统代理（macOS 网络设置、Windows 的 Internet 代理设置），不在设置里另加代理项。Base URL 的主机是 `localhost`、`127.0.0.1`、`::1` 时始终直连，不进代理。从访达 / 开始菜单启动的应用读不到终端的 `HTTPS_PROXY`，所以必须读系统设置，只认环境变量不够；`reqwest` 能否直接读到系统代理、要开哪个 feature，由实现在两端验证。
- HTTP 客户端：`Cargo.lock` 里已经由 `tauri` 间接引入 `reqwest`，直接依赖同一个版本，不再引入第二个 HTTP 库。树里的 `reqwest` 没开 TLS，需要新增 TLS 后端，选哪个由实现定。
- 请求在后台线程 / async 任务上执行，不占剪切板监听、面板命令的线程。
- 日志：`translate id=N chars=C ms=T ok` / `translate id=N 失败 http=401 ms=T` / `translate shot chars=C ms=T`；不写原文、译文、Key、Base URL。

### 4.2 系统翻译（`crates/xpaste-platform`，仅 macOS）

**已做的验证（2026-10-29，本机 macOS 27.2，Xcode SDK 27.0）**：写一个没有界面的命令行 Swift 程序，`LanguageAvailability().status(en → zh-Hans)` 返回 `supported`，`supportedLanguages` 21 种（含本设计用到的五种）；`TranslationSession(installedSource:target:)` 能在没有 SwiftUI 的进程里创建，因为本机没下载语言包，`translate` 返回 `TranslationError.notInstalled`。所以：无界面调用可行；语言包需要用户自己下载；实际翻译耗时还没测到，实施第一步装上语言包补测。

- 框架只有 Swift 接口（没有 Objective-C 接口，`objc2` 调不到）。写一个 Swift 源文件（如 `crates/xpaste-platform/swift/translate.swift`），用 `@_cdecl` 导出 C 函数：
  - `availability(target) -> 状态`：系统版本是否 ≥ 26、英语 ↔ 目标语言是否已下载 / 可下载 / 不支持（给设置页显示用）；
  - `translate(text, target, ctx, callback)`：在 Swift 里用 `NLLanguageRecognizer` 定源语言，`TranslationSession(installedSource:target:)` 翻译，结果或错误码通过 C 回调交回。Rust 侧在后台线程上用 channel 等回调，30 秒超时。
- 构建：`xpaste-platform` 的 `build.rs` 在 macOS 目标上调 `swiftc` 把它编成静态库并链接；`Translation`、`NaturalLanguage` 框架**弱链接**（`-weak_framework`），Swift 侧所有入口都用 `if #available(macOS 26, *)` 保护，保证 macOS 26 以下照常启动。应用最低系统版本不变。
- 无界面的 `TranslationSession(installedSource:target:)` 是 macOS 26 才有的；macOS 15 只能通过 SwiftUI 的 `.translationTask` 拿会话，要挂一个隐藏窗口，不做。
- 构建机与 CI 的 macOS 任务需要 Xcode 26 及以上的 SDK；Windows 交叉 clippy 不受影响（只在 `cfg(target_os = "macos")` 下编译）。
- 不能流式，整段返回。
- 平台层导出与 OCR 一致的同名函数风格：`translate_available()`、`translate_text()`；Windows 上返回「不支持」。
- 日志：`translate system id=N chars=C ms=T ok` / `translate system 失败 notInstalled`，不写原文与译文。

### 4.3 设置（`crates/xpaste-core/src/model.rs` 的 `Settings`）

### 4.5 命令与事件

- `translate_record(id)`：读记录的原文（文本、代码取全文，不受预览截断影响；图片、文件取 `ocr_text`），按 3.5 翻译。过程中向面板发事件 `translate-delta { id, lang, text }`（`text` 为本次新增的部分），结束时发 `translate-done { id, lang, ok, error? }`；成功时存库。同一条记录已有请求在途时不发第二个请求。
- 前端按 `id` 累积增量（存在内存里的一张表），所以翻译中切走再切回来，能接着显示已收到的部分；当前预览的是这条记录时才更新界面。
- `translate_record` 按设置里的翻译方式分发：系统翻译整段返回时，也发一次 `translate-delta`（整段）再发 `translate-done`，前端不用区分两种方式。
- `translate_test(engine, base_url, api_key, model, lang)`：测试连接，不存任何东西。
- `translate_status(lang)`：给设置页查系统翻译的可用性与语言包状态；`open_translation_settings()`：打开系统设置的翻译语言页面（具体 URL 由实现在 macOS 26+ 上验证）。
- 截图：`shot_finish` 新增动作 `translate`：识别 → 流式翻译，增量以事件发给发起的遮罩窗口，命令在收完（或失败）时返回完整译文；**不写剪切板、不进入提示条模式**。复制译文时由遮罩调新命令（如 `shot_copy_text`）写剪切板，然后走现有的成功流程。被 Esc 结束的判断沿用 `session(app).is_current(generation)`：识别后、每段增量发出前都检查一次，截图已结束就中止请求、不再发事件。
- 注意：现有的识别动作在成功后会进入提示条模式（`enter_toast`）；翻译动作在卡片阶段不能进入，复制译文后才进入。

## 6. 我替用户做的决定（请评审时确认）

1. **API Key 存在本地数据库，不放系统钥匙串。** 讨论时说过放钥匙串，写设计时改了：安装包未签名，macOS 钥匙串按代码签名授权，每次更新版本都会弹「xPaste 想要访问钥匙串」；而且数据目录里本来就是明文的剪切板历史，钥匙串带来的额外保护有限。以后做本地数据加密（第 7 章 Q7）时再一起迁进钥匙串 / DPAPI。
2. 可翻译的类型：文本、代码、文字类片段、有识别文字的图片和文件；链接、视频不可翻译。
3. 译文每条只存一份，改目标语言后不自动重翻。
4. 原文上限 10000 字；首段与段间各 30 秒超时，不设总时长；不重试；中途失败保留已收到的部分但不存库。
5. 目标语言五种，自动反向时的另一方固定为英文（目标是英文时为简体中文）。
6. 截图译文卡片出现后不能再调整选区、不能标注；卡片里不做「钉住」。
7. 原文语言判断：含假名算日文、含谚文算韩文，其余比汉字和拉丁字母的数量；判断不出时照常翻成目标语言（3.5）。
8. 已有译文时，`⌘T`、「翻译」按钮、菜单项只滚到译文，不重新请求；要重翻点「重新翻译」（3.1）。
9. 「翻译方式」默认值：macOS 26+ 默认系统翻译（开箱即用、不出本机），其余默认 OpenAI 兼容接口。
10. 系统翻译只支持 macOS 26+；语言包只引导到系统设置下载，不在 xPaste 里下载。
