# xPaste 截图与录屏 设计

**版本：** v0.2　**状态：** 阶段 12 已实现（截图与贴图，回写为规格说明 v0.1.20 的 M23）；阶段 13 录屏仍为草案　**日期：** 2026-10-28
**依据：** 功能规格说明 v0.1.19（M04、M15、M17、M18、M22）、本机 iShot 2.6.9 的产物分析（附录 A）
**目标阶段：** 阶段 12（截图）、阶段 13（录屏）
**交互原型：** [2026-10-28-截图与录屏-原型.html](2026-10-28-截图与录屏-原型.html)（本地打开）

## 1. 意图

xPaste 已经把“复制过的东西”都收进了历史，截图却还得靠系统自带工具或第三方截图软件（iShot 等）。把截图和录屏做进 xPaste，就能少装一个常驻工具，而且截出来的图、录好的视频直接进剪切板历史：有缩略图、能按图中文字搜索（M22）、能粘贴到任何地方。

iShot 只当作交互和能力的参考，不复刻它的界面和功能清单。我们只取最常用的那条主路径：按快捷键，框选，标注，然后复制或保存。

## 2. 目标、非目标、反目标

**目标**

1. 区域截图：用一个快捷键冻结当前屏幕，可以框选区域，也可以把鼠标停在窗口上一键选中整个窗口，然后做基本标注，按回车复制，按 ⌘S 保存。
2. 截图写进剪切板后，按普通图片记录进入历史，现有的缩略图、OCR 和搜索流程全部照常生效，不需要新的入库代码。
3. 贴图：截好的图可以钉在屏幕最上层，作为对照参考。可以拖动、用滚轮缩放、双击关闭，能同时钉多张。
4. 录屏（macOS）：录制区域或整块屏幕，输出 MP4，可以带系统声音和麦克风。录完后视频文件写进剪切板，作为视频记录进入历史。
5. 性能：从按下截图快捷键到遮罩出现不超过 300 ms〔建议值〕，冻结的那一帧与按键时刻一致，菜单和悬停提示都要截进去。
6. 隐私：截图和录屏全部在本机处理。日志只记尺寸、字节数、耗时和记录 id，不记文件路径、窗口标题和应用之外的内容（沿用横切约束）。

**非目标（本期不做，写进规格说明第 8 章）**

- 长截图（滚动拼接）、带壳截图、延时截图、截上次区域、预设尺寸截图
- 贴图库（历史贴图的列表）、一键隐藏 / 显示全部贴图、贴图透明度、重启后恢复贴图
- 取色器、截图翻译
- GIF 输出、转码（iShot 为此自带了 ffmpeg，约 60 MB）、录音
- 录屏时显示按键、高亮鼠标点击、摄像头画中画、暂停后继续
- Windows 录屏（单独一期：Windows.Graphics.Capture 加 Media Foundation 编码）

**反目标（即使功能上能用，出现以下情况也算失败）**

- 截图快捷键拖慢剪切板面板的唤起，或者让面板的单实例和焦点行为出问题。
- 遮罩冻结的画面和按键时刻不一致，比如截不到下拉菜单，或者遮罩自己被截了进去。
- 录屏结果里出现 xPaste 自己的窗口（区域边框、控制条）。
- 为截图功能给安装包加上几十 MB 的依赖。

## 3. 约束

- 支持 macOS 13 及以上（`tauri.macos.conf.json`）和 Windows 10 1809 及以上。截图两端都做，录屏只做 macOS。
- 依赖方向不变：截屏、窗口列表、录屏编码放平台层（`xpaste-platform`），遮罩窗口和命令放应用层（`src-tauri`），选区和标注的界面用前端 TS。
- 只有 `src/api/` 能调用 Tauri。遮罩页面的 Tauri 调用同样放在 `src/api/` 下。
- 平台层沿用 objc2 0.6 加 objc2-* 0.3 体系，Windows 沿用 `windows` 0.62。不引入 ffmpeg，也不引入 GUI 框架。
- 截图入库走现有的剪切板监听：把 PNG 按普通写入（**不**经过 `write_marked`）写进剪切板，由监听器像对待 `screencapture -c` 一样入库（验收记录里这条路径已经验证过）。因此暂停记录、忽略应用、50 MB 上限这些规则对截图同样生效，这是有意的。

## 4. 已决定的方案

以下都是我的取舍，用户还没有逐条确认过。

### 4.1 整体流程

```
快捷键 → 平台层冻结所有显示器（每块屏一张图）+ 取窗口列表
       → 每块屏显示一个全屏遮罩 webview（预先创建好、隐藏着），背景是冻结图
       → 前端：框选 / 吸附窗口 → 标注 → 动作
       → 前端在 canvas 上按物理像素合成 PNG → 命令 shot_finish(png, action)
       → 应用层：写剪切板（进历史）/ 存文件 / OCR 复制文字 / 建贴图窗口 → 隐藏遮罩
```

录屏复用同一个遮罩做选区。选好后遮罩隐藏，平台层开始录制，结束时把 MP4 存好，再把文件引用写进剪切板。

### 4.2 冻结屏幕（平台层）

- macOS（13–15 同一条路）：按显示器调用 `CGDisplayCreateImage`（用 `extern "C"` 声明，与现有的 `AXIsProcessTrusted` 写法一致）。冻结发生在遮罩显示之前，不需要排除任何窗口；贴图是普通窗口，自然会被截进去。选它而不是 `SCScreenshotManager`（macOS 14+，异步）的理由：同步、一条路径，300 ms 预算里最大的一块就在这里，也不用新增 crate。实测每块 2880 × 1800 的屏 55–78 ms（含转换到 sRGB，见第 8 节）。iShot 两套都链接了（附录 A-3）。<!-- ponytail: CGDisplayCreateImage 在 macOS 15 SDK 已标记废弃；Apple 真正移除或截图出现异常时换 SCScreenshotManager，平台层签名不变 -->
- 窗口列表：`CGWindowListCopyWindowInfo(onScreenOnly, excludeDesktop)`，取 layer 0 的普通窗口加上 xPaste 的贴图窗口，返回 bounds、层级顺序和所属应用名，供前端在鼠标悬停时吸附窗口。不返回窗口标题，因为前端用不到，也省得进日志。
- Windows：用 GDI `BitBlt` 截全虚拟桌面再按显示器切开（`GetDC`、`GetDIBits` 已经在用），窗口列表用 `EnumWindows` 加 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`，过滤掉不可见和 cloaked 的窗口。
- 对外接口两端同名：

```rust
/// 坐标为“原生单位”：macOS 是全局点坐标（主屏左上为原点），Windows 是虚拟桌面物理像素。
pub struct Frame { pub origin: (f64, f64), pub size: (f64, f64), pub scale: f64, pub px: (u32, u32), pub rgba: Vec<u8> }
pub struct WinRect { pub x: f64, pub y: f64, pub w: f64, pub h: f64 }
pub fn freeze_displays() -> Result<Vec<Frame>, PlatformError>;
pub fn window_rects() -> Vec<WinRect>;   // 由前到后
pub fn screen_capture_granted() -> bool; // macOS: CGPreflightScreenCaptureAccess；Windows 恒为 true
pub fn request_screen_capture();         // CGRequestScreenCaptureAccess + 打开系统设置“屏幕录制”页
```

### 4.3 遮罩窗口（应用层）

- 每块显示器一个 webview 窗口，标签为 `shot-<序号>`，加载 `shot.html`（Vite 多入口）。启动时预先创建并隐藏，显示器变多时补建、变少时只隐藏不销毁（见第 8 节），避免每次截图都要新建 webview（这部分开销远超 300 ms 的预算）。
- macOS：转成 NSPanel 后加 NonactivatingPanel 样式（沿用 `panel.rs` 的 tauri-nspanel 用法），层级设在菜单栏之上（`NSScreenSaverWindowLevel`），collection behavior 为 `CanJoinAllSpaces | FullScreenAuxiliary`，覆盖整块屏幕，包括菜单栏和刘海区域。显示遮罩时不能激活 xPaste，否则会把面板顶出来，也会抢走前台应用的焦点。
- 冻结图传给前端：用 Tauri 2 的原始字节响应（`tauri::ipc::Response`）直接传像素（实现为前 8 字节宽高加 RGBA，命令 `shot_frame`），前端用 `ImageData` 加 `putImageData` 画到 canvas 上，不在热路径上做 PNG 编解码。如果实测超出预算，再换成写临时文件、走 asset 协议。
- 多显示器：选区只能落在一块屏内，其他屏的遮罩只显示暗色蒙层。光标进入哪块屏，哪块屏就成为活动屏。复用 `panel.rs` 里 `cursor_monitor` 和 `monitor_contains` 的坐标换算。
- capabilities：在 `default.json` 的 `windows` 里加上 `shot-*` 和 `pin-*`；`lib.rs` 里 `on_window_event` 对非 panel 窗口提前返回的逻辑保持不变。

### 4.4 遮罩交互（前端 `src/shot/`）

参照 iShot 的默认键位（附录 A-2），但只做下面这些：

| 阶段 | 操作 | 行为 |
| --- | --- | --- |
| 选区前 | 移动鼠标 | 高亮光标下的窗口（吸附），旁边显示放大镜和坐标、尺寸 |
| | 单击 | 选中高亮的窗口 |
| | 拖动 | 框出矩形选区 |
| | F | 选中整块屏 |
| 选区后 | 拖动 8 个手柄 / 拖动选区内部 | 调整大小 / 移动选区；方向键移动 1 px，按住 Shift 调整大小 |
| | 工具栏 1–7 | 矩形、椭圆、箭头、画笔、马赛克、文字、序号标注 |
| | ⌘Z / ⇧⌘Z | 撤销 / 重做标注 |
| 动作 | 回车 / 双击选区 | 复制到剪切板（进入历史）并退出 |
| | ⌘S | 保存到截图文件夹并退出（同时复制，可在设置中关闭） |
| | O | 识别选区里的文字并复制（实现改为进入历史，见 §8 第 15 条） |
| | P | 钉在屏幕上（贴图），不写剪切板 |
| 任何时候 | Esc | 直接退出截图（实现按真机反馈改，见 §8 第 28 条） |
| 任何时候 | 右键 | 有选区时先取消选区，没有选区时退出截图 |

- 标注画在叠加的 canvas 上，坐标按物理像素保存，导出时与冻结图在同一块 canvas 上合成，所以 Retina 屏导出的是 2x 原尺寸。
- 颜色和粗细只给一行固定选项：6 种颜色、3 档粗细。不做 iShot 那种上百种命名颜色的取色板。
- 视觉风格沿用面板的设计变量（暗色、品牌色描边），动效遵守 M20 和 reduced-motion。

### 4.5 输出

- **复制**：调用 `xpaste_platform::write(&[public.png])`。监听器会把它作为图片记录入库，自动标题为“截图 YYYY-MM-DD HH.MM.png”，随后生成缩略图并做 OCR。来源应用记为截图时的前台应用。
- **保存**：保存到 `截图文件夹`，默认 `~/Pictures/xPaste`，Windows 为“图片\xPaste”。文件名与自动标题一致，重名时加 ` 2`、` 3`。
- **贴图**：选区原地变成一个贴图窗口，遮罩随后淡出，画面不跳动。贴图本身不写剪切板，避免历史里多出一条用户没要的记录。
  - 窗口：每张贴图一个 webview 窗口（标签 `pin-<序号>`），无边框、6 px 圆角加阴影、始终在普通窗口之上、低于遮罩；macOS 上为不激活的 NSPanel，点它不会把 xPaste 面板带出来，也不抢前台应用的焦点。<!-- ponytail: 每张贴图一个 webview，内存约几十 MB；有人同时钉十几张时再换原生 NSImageView / 分层窗口 -->
  - 交互：拖动移动（至少留 40 px 在屏幕内）；滚轮以光标为锚点缩放，范围 20%–400%，缩放时右上角短暂显示百分比；双击或 Esc 关闭；右键菜单为复制（`Mod+C`，进入历史）、保存（`Mod+S`，同截图的保存规则）、恢复原始大小（`Mod+0`，只在缩放过时出现）、关闭。点哪张，哪张置顶。
  - 图像按原物理像素保存，缩放只改窗口尺寸，复制和保存始终输出原图，不含缩放。
  - 生命周期：只在本次运行内有效，退出 xPaste 时全部关闭（贴图库和重启恢复都不做，见第 2 节）。
- **识别文字**：把 PNG 写进临时文件后调用 `xpaste_platform::ocr_png`。进程里第一次识别较慢（M22 规则 12），这期间遮罩显示“正在识别…”，不阻塞关闭。

### 4.6 录屏（macOS，阶段 13）

- 用录屏快捷键进入遮罩的选区模式（工具栏只有“开始录制”和声音开关）。按回车或点“开始”后，倒计时 3 秒再开始录制。
- 平台层：`SCStream`，过滤器为 `initWithDisplay:excludingWindows:`，只排除录制边框窗口（贴图要能录进去，用户常把参考图钉着边看边录），`sourceRect` 设为选区，帧率 30，`showsCursor = true`，`capturesAudio` 跟随“录制系统声音”开关。采样缓冲交给 `AVAssetWriter`（H.264 MP4 加 AAC），iShot 的做法相同（附录 A-3）。
- 麦克风：macOS 15 及以上用 `SCStreamConfiguration.captureMicrophone`。macOS 13–14 本期不支持麦克风，开关显示为不可用，提示“需要 macOS 15”。<!-- ponytail: 13–14 的麦克风要另接 AVCaptureSession 并与 SCStream 的时钟对齐，有用户要再做 -->
- 录制中：选区四周显示一个可点击穿透的边框窗口（被录制过滤器排除），托盘图标切换为录制状态并显示计时，菜单里有“停止录制”。再按一次录屏快捷键也会停止。
- 结束：文件保存到 `录屏文件夹`（默认 `~/Movies/xPaste`），然后把文件引用写进剪切板，作为视频记录进入历史（现有的视频封面逻辑会生成缩略图）。设置里可以关掉“录完复制到剪切板”。
- 权限：屏幕录制（与截图相同）、麦克风（新增 `src-tauri/Info.plist`，写入 `NSMicrophoneUsageDescription`）。

### 4.7 设置（M15 增加的行）

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 截图快捷键 | `Alt+Shift+A` | 留空表示不启用 |
| 录屏快捷键（macOS） | `Alt+Shift+R` | 留空表示不启用 |
| 截图文件夹 | 见 4.5 | |
| 保存截图时同时复制 | 开 | |
| 录屏文件夹（macOS） | 见 4.6 | |
| 录制系统声音 / 麦克风（macOS） | 关 / 关 | |
| 录完复制到剪切板（macOS） | 开 | |

- 默认快捷键是我选的。iShot 用 ⌥A，但这台机器装着 iShot，⌥A 会冲突；Windows 上微信截图用 Alt+A。注册失败沿用现有的处理（托盘标记 + 提示）。
- `Settings` 新增字段都加 `#[serde(default)]`（结构体本身已经是 `default`），旧的设置 JSON 能直接读出，不需要数据库迁移。
- `hotkey.rs` 先 `unregister_all`，再把唤起与截图快捷键成对注册（截图为空则跳过）；改了任一个就两个一起重新注册，失败时恢复原来那一对。`lib.rs` 的 handler 按触发的是哪个快捷键分派（`role_of`）。（原方案为按快捷键分别注册和注销，实现时改为成对注册，见第 8 节。）

### 4.8 权限（M18）

- macOS 每次截图时用 `CGPreflightScreenCaptureAccess` 检查屏幕录制权限。没有权限时不显示遮罩，而是唤起面板弹出确认框（“截图需要屏幕录制权限”，按钮“以后再说” / “前往授权”），“前往授权”调用 `request_screen_capture` 并隐藏面板。系统要求授权后重启应用，正文里写明，并按系统版本写对系统设置的页名（macOS 15 起“录屏与系统录音”，之前“屏幕录制”）。
- 设置页的权限区仿照“自动粘贴权限”那一行，加一行“屏幕录制权限”。不放进首次启动引导，因为不用截图的人不需要这个权限。

## 6. 阶段划分

- **阶段 12 截图**：平台层冻结屏幕和窗口列表（两端）、遮罩窗口、前端选区和标注、四种输出（复制、保存、识别文字、贴图）、贴图窗口、截图快捷键、屏幕录制权限、设置项、规格回写。先在 `docs/` 下做一个本地 HTML 交互原型（遮罩、工具栏、放大镜），对照它实现，遵守面板 UI 的还原标准。
- **阶段 13 录屏（macOS）**：SCStream 加 AVAssetWriter、录制边框窗口、托盘录制状态、录屏快捷键、麦克风权限、设置项、规格回写。

两个阶段各写一份实施计划，放在 `docs/plans/`。

## 7. 留给实现者决定

- 冻结图传输方式最终选原始字节还是临时文件，以实测延迟为准（4.3）。
- 窗口吸附是否包含窗口的阴影区域（建议不含，与 iShot 的默认设置 `needShadowOfnotSingleWindow` 不同，因为我们不做阴影美化）。
- 马赛克的实现（像素块大小、是否用 `ctx.filter`）。
- 遮罩预创建时机：放在启动就绪后的空闲时刻，不影响 M04 的唤起指标。
- 平台层是加 `objc2-screen-capture-kit` crate，还是手写少量 `msg_send!`。优先用现成的 crate，前提是它的特性开关能把编译体积控制住。

## 8. 实现与设计不同的地方（阶段 12）

阶段 12 按[实施计划](../plans/2026-10-28-阶段12-截图与贴图.md)实现，回写为规格说明 v0.1.20 的 M23。下面是实现时与上文不同或上文没写到的地方。

**平台层**

1. macOS 冻结帧是显示器的色彩空间，前端按 sRGB 画会偏色，所以冻结后转换到 sRGB。每块 2880 × 1800 的屏 55–78 ms，进程里第一次约 135 ms，比 4.2 估计的 20 ms 慢。超预算时可以加“已是 sRGB 就跳过转换”。
2. 窗口列表按窗口标题排除遮罩（`xpaste-shot`），保留贴图（`xpaste-pin`）；Windows 另外去掉桌面窗口和全透明的分层窗口。
3. 平台层另加了几个函数，两端同名：`activate_window`（Windows 把前台交回截图前的窗口，macOS 为空）、`mouse_button_down`（贴图拖动结束的判断）、`macos_version`（选权限页名）、`png_flavors`（PNG 的剪切板格式）、`ocr_png_bytes`（识别内存里的 PNG，`ocr_png` 读文件后也走它）。Windows 的 `foreground_window` 在本进程窗口（如刚点过的贴图）是前台时，返回最后一个成为前台的外部窗口：剪切板监听线程上挂了 `EVENT_SYSTEM_FOREGROUND` 钩子（`WINEVENT_SKIPOWNPROCESS`，借用该线程已有的消息循环）记下它。

**遮罩与会话**

4. 显示器变少时，多出的遮罩只隐藏不销毁。tauri-nspanel 按标签存着没有额外 retain 的指针，同名重建会再释放一次。代价是多占一个隐藏的 webview。
5. 启动时只预建遮罩，不预热 `freeze_displays`：没有用户操作就截屏，可能在登录时触发 macOS 15 起的定期再次确认，也不合隐私上的预期。代价是进程里第一次截图的冻结多花几十毫秒（约 135 ms）。
6. 冻结结果除了推送 `shot-begin`，前端还会用 `shot_begin_payload` 拉一次，两路按会话代数去重，避免新建的遮罩错过推送。`shot_ready`、`shot_cancel` 带代数，上一次截图迟到的就绪与退出（提示条、淡出计时）不算。`shot_frame` 的响应体（8 字节宽高加 RGBA）在冻结时于锁外拼好，每块屏只能取一次，取走时原样移交、不再拷贝。
7. 会话 3 秒内没有全部上屏（遮罩页面出错等），或者已全部上屏但某块屏的遮罩已隐藏或不在了，再按快捷键时撤下旧遮罩、重新开始，不会一直卡住。遮罩的 `CloseRequested`（Windows 上 Alt+F4）被拦下并当作退出截图；macOS 上遮罩页面进程退出（`on_web_content_process_terminate`）时结束会话并重新加载页面。Windows 的 WebView2 没有对应的钩子，见已知限制。
8. 动作完成后会话保持到 `shot_cancel`（提示条结束时调用），只先释放冻结帧。否则提示条期间再按快捷键，会把仍在屏上的提示条冻进新截图。同一次截图第二次调用 `shot_finish` 会被拒绝。
9. 多显示器：遮罩之间用前端事件 `shot-claim` 协调。一块屏出了选区，其他屏放弃选区；一块屏在识别文字，其他屏锁住、只留蒙层；退出或完成时其他屏一起淡出并放掉像素。
10. 遮罩与贴图的主题跟随 xPaste 的外观设置：后端对 `shot-*`、`pin-*` 窗口 `set_theme`（与面板相同），不是跟随系统。
11. 焦点：macOS 的遮罩与贴图都是不激活的 NSPanel；动作完成时把持有键盘的遮罩 `orderOut` 再 `orderFrontRegardless`，键盘回到仍是激活状态的原应用。Windows 的遮罩在截图期间持有焦点，动作完成时用 `activate_window` 把前台交回截图前的窗口；贴图在创建时就以可见、不聚焦的方式建出（tao 只在创建时用 `SW_SHOWNOACTIVATE`），可能在近似位置闪一帧再摆正。

**前端**

12. 动作结果的提示条在左下角（原型在底部居中，是为了避开原型的控制台）。键盘触发（F、数字键）时工具栏不浮入（M20 原则 2）；识别文字期间 Esc 可以退出（4.5“不阻塞关闭”）；退出时遮罩先淡出 160 ms。
13. 马赛克底图在第一次用马赛克时才生成，不占上屏时间。遮罩隐藏后放掉冻结帧、标注和马赛克底图的像素。
14. 工具栏的保存提示按“保存截图时同时复制”显示“保存并复制”或“保存”，这个设置随 `shot-begin` 载荷带给遮罩。

**输出与贴图**

15. 保存用“不存在才创建”的方式写文件，重名时加序号重试，不会覆盖；截图文件夹设成相对路径时按默认文件夹处理。识别文字把 PNG 字节直接交给 `ocr_png_bytes`，不写临时文件（与 4.5 不同）；识别出的文字按普通写入写剪切板，作为文本记录进入历史（用户真机验收后要求，原设计为不进历史）；长边上限 8000 px（历史识别为 2000 px），否则 5K 整屏截图缩到约 39%，界面上的小字认不出。
16. 贴图页面的地址带 `src` 参数（编码后的 asset 地址），前端不自己拼数据目录路径。macOS 上贴图用 `RawNSPanel::from_window` 转换，不登记到插件里（理由同第 4 条）。
17. 贴图的窗口尺寸与位置由 Rust 命令 `pin_set_bounds` 一次改完（两端改尺寸和位置的先后顺序不同），没有给前端开 `set-size`、`set-position` 权限。窗口每边不超过 16384 物理像素：前端按这个上限夹住缩放（`maxZoom`，锚点才对得上），后端再兜底等比缩小并返回实际系数，前端的缩放比例以它为准。
18. 贴图的拖动交给系统，出屏要等松开鼠标（`mouse_button_down`）后才拉回所在显示器的工作区，而不是拖动中实时夹住。顶边不超出工作区：上下排列的多块显示器、macOS 菜单栏那一行都受这个限制。
19. 滚轮按距离计格：停顿 150 ms 后的第一下算一格，连续滚动每 50 px 一格，一个事件最多一格。
20. 贴图的复制、保存结果显示在右上角的小标签里（“已复制”“已保存并复制”“已保存”），不弹全局提示条。阴影用系统窗口阴影，描边画在图片内侧。

**设置、快捷键与权限**

21. 快捷键成对注册（见 4.7）。只有两个快捷键，恢复逻辑更简单；代价是注销到重新注册之间的极短时间里，其他应用可能抢走快捷键，以及某一个从启动起就被占用时，只改另一个也会保存失败。
22. 启动时截图快捷键被占用只发系统通知，不标记托盘；两个都被占用时合成一条通知。之后保存设置时，截图快捷键没注册上也会顺带尽力重试一次（同唤起快捷键启动失败后的重试）。升级前唤起快捷键就是 `Alt+Shift+A` 的，读设置时截图快捷键置为空（不启用），不然整份设置校验不过、回落到默认值。
23. 设置或确认对话框开着且面板可见时，截图快捷键不开始截图（开始截图会隐藏面板、关掉对话框）：面板有焦点时送到面板，截图快捷键录制框聚焦时写入录制框（网页收不到被全局注册拦下的按键）；面板失焦时只把面板拉回焦点（`hotkey::shot_route`）。
24. 设置页“截图与贴图”分组：截图快捷键、截图文件夹（“更改…”用 `tauri-plugin-dialog` 的选择文件夹窗口，权限只给面板窗口）、保存截图时同时复制、屏幕录制权限。

**真机验收后补的兜底**

25. 遮罩已全部上屏时再按截图快捷键退出截图（同 Esc），而不是忽略（`Session::try_begin_at` 返回 `Press::Exit`，由 `begin` 结束会话）；冻结中、未全部上屏与提示条期间仍按第 7、8 条处理。
26. 遮罩心跳看门狗：一次 `make dev` 运行里遮罩上屏后页面不再响应（怀疑开发服务器热更新刷坏了页面，没有复现），遮罩在最上层截走全部输入，只能结束进程。现在已上屏的遮罩页每秒调一次 `shot_alive`（不走主线程，多屏时任一屏的心跳都算），全部上屏后起一个线程每秒检查一次，3 s 没有心跳就撤下遮罩、交还键盘、释放冻结帧（`Session::unresponsive_at`），然后在主线程对每个遮罩 `reload()`：卡死的页面不会再回应 `shot-begin`，还拿着冻结帧；窗口与标签不变，NSPanel 不重建（同 macOS 页面进程退出的处理）。会话结束、换代或进入提示条模式时线程退出，睡眠时不持锁。后端结束会话（再按快捷键、看门狗、Alt+F4、`shot_cancel`）后给每个遮罩发 `shot-end`（载荷为结束的那一代），页面立即放掉像素，马上再按快捷键时旧画面不会闪出来；`shot_alive` 的返回值（会话是否仍在进行）作为事件丢失时的兜底。权限检查排在“再按退出”之后：截图期间权限被撤销，快捷键也能退出屏上的遮罩。提示条期间不判（遮罩已鼠标穿透、交还键盘，另有第 7 条的 3 秒兜底）。Windows 上 WebView2 进程退出后遮罩也会在 3 s 内撤下并尝试重新加载页面，能否恢复待 Windows 实机确认（已知限制）。
27. 识别模型预加载：进程里第一次识别要加载 Vision 模型（真机日志 `shot 识别 84 字 9349ms`，之后 266–355 ms）。每个进程第一次按截图快捷键、确实开始冻结时，在后台低优先级线程识别一张 8×8 白色 PNG（`std::sync::Once` 保证只做一次，引擎不可用时跳过，失败只记 debug 日志）。启动时不做：不截图的人不付这几秒 CPU。本机实测预热 8.6 s 后，真实识别 118 ms。
28. Esc 直接退出截图，有选区也不先取消选区（原设计照 iShot 的右键行为，Esc 要按两次才退出，真机反馈不顺手）；取消选区只用右键。文字标注输入期间 Esc 仍只完成输入。

分析对象为 `/Applications/iShot.app`（`cn.better365.ishot`，构建号 20260831001，universal x86_64/arm64，ObjC/AppKit 原生应用）。只做了静态读取：Info.plist、DefaultPreferences.plist、本地化 strings、链接表、导入符号和字符串表。没有运行，也没有反编译（本环境没有注册 REA 的 MCP）。下面分成“观察到的”和“推断的”两类。
