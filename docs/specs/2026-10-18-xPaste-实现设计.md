## 1. 范围

**本期实现**：规格说明中全部 P0 和 P1 功能，macOS 与 Windows 两端。

## 2. 待确认问题的实现取值

规格说明第 7 章的问题还没有定论。为了不阻塞开发，先按下表实现。每一项都改动很小，结论有变化时再调整。

| 问题 | 本期实现 | 改动成本 |
| --- | --- | --- |
| Q1 Enter 的行为 | 复制并自动粘贴到上一个应用；无法粘贴时降级为只复制并提示。不提供“只复制”开关 | 加开关只改设置和 `copy` 命令的一个参数 |
| Q2 默认快捷键 | 保持规格说明的默认值 `⌘ ⇧ V` / `Ctrl + Shift + V`，可在设置中修改 | 改一个常量 |
| Q3 外部重复复制是否计入使用次数 | 计入 | 去掉一行 `uses + 1` |
| Q4 一次复制多个文件 | 一条记录；预览列出全部文件 | — |
| Q5 唤起时保留什么 | 保留分类，清空搜索词，选中第一条 | — |
| Q6 自动更新 | 本期不做 | 后续接入官方 `tauri-plugin-updater` |
| Q7 数据库加密 | 本期不做 | 数据库访问集中在 `xpaste-core::store`，后续可换成 SQLCipher |
| Q8 macOS 剪切板隐私提示 | 阶段 1 技术验证时测量，结论写回 ADR-001 和规格说明 M18 | — |
| Q9 验证码识别 | 不做（P2） | — |

**发现的规格说明问题，需要回写**：

1. **使用次数从几开始算**：AC-M11-01（通过 xPaste 复制 3 次进入常用）和 AC-M11-02（外部复制同一内容 3 次进入常用）不能同时成立。本期取值：**首次复制生成记录时使用次数为 0，之后每次重复使用 +1**，与原型数据一致。按这个取值，AC-M11-02 应改为“复制 4 次”，或者改用“首次复制记为 1”的口径。**定稿（阶段 4）：AC-M11-02 改为 4 次**（规格说明 v0.1.4）；“首次记为 1”会让 AC-M11-01 在第 2 次经 xPaste 复制时就进入常用，与原型数据不符。
2. **新记录在面板打开时进入**：原型的“模拟一次复制”会清空搜索、切换到“全部”并选中新记录，这是演示用的行为。正式版里，面板打开时外部产生的新记录只按 M20 的“新记录进入”动效插入列表，**不改变搜索、分类和选中项，也不弹提示条**。
3. **macOS 开机启动**：规格说明 M15 写的是 SMAppService。本期使用官方 autostart 插件的 LaunchAgent 方式，两端只维护一套代码。用户看到的效果相同，系统设置的“登录项”里都会显示 xPaste。如果验收时发现显示名称或系统提示不符合要求，再改用 SMAppService（约 20 行代码）。**阶段 5 维持 LaunchAgent**（`MacosLauncher::LaunchAgent`）；开发构建不改登录项（见第 10 节），实际效果在正式 `.app` 中验收（AC-M15-06）。
4. **macOS 卸载时询问是否删除数据（5.2.4）**：`.dmg` 拖入废纸篓的卸载方式无法弹出询问，macOS 上做不到。Windows 使用 Tauri NSIS 卸载程序自带的“删除应用数据”勾选框。**已实现（阶段 8）**：Tauri 自带的勾选只删以 bundle id 命名的目录，删不到 `%APPDATA%\xPaste`，由 `src-tauri/windows/hooks.nsh` 的 `NSIS_HOOK_POSTUNINSTALL` 在勾选时删除；覆盖安装（更新模式 `$UpdateMode`）不删。开机启动的注册表 Run 值在真正卸载时一律删除，更新模式下保留。macOS 的卸载步骤（手动删数据目录与 LaunchAgent plist）写在 README。
5. **大文本预览**：超过 200 KB 只显示前 200 KB，新增一句提示文案“仅显示前 200 KB，复制时为完整内容”，需要补进规格说明附录。
6. **“已加入常用”提示与自动粘贴冲突**：M09 规则 2（粘贴成功隐藏面板）与规则 4（首次进入常用时提示）在粘贴成功时冲突——面板已隐藏，提示看不到。本期粘贴成功时不提示；仅复制（面板仍可见）时提示合并为一句“这条已经用了 3 次，已加入“常用”；在目标应用中按 Mod + V 粘贴”。**定稿（阶段 4）：粘贴成功时不提示；下次唤起可在列表看到“用过 N 次”**（规格说明 v0.1.4 M09 规则 4）。不再为此弹系统通知（notification 插件只用于第 10 节的启动时快捷键注册失败）。

## 3. 总体架构

### 3.1 分层

```
┌─ 前端（WebView，常驻、隐藏时不销毁）────────────────────────────────────────────┐
│  src/main.ts 等        键盘、状态、渲染（由原型迁移）                             │
│  src/api/              唯一引用 @tauri-apps/* 的目录：命令封装、事件封装、类型     │
└──────────────────────────────▲──────────────────────┬───────────────────────────┘
                               │ 事件                  │ 命令
┌─ 应用层 src-tauri/（依赖 tauri，是唯一依赖 tauri 的 crate）────▼───────────────────┐
│  lib.rs 组装 Builder   commands/ 命令   panel.rs 面板窗口   tray.rs 托盘            │
│  clipboard.rs 监听接线   enrich.rs 补全线程   housekeeping.rs 定时清理               │
│  error.rs 错误类型   state.rs 托管状态                                               │
├─ 核心层 crates/xpaste-core/（不依赖 tauri，不依赖系统接口，任何平台都能 cargo test）──┤
│  model.rs 类型   detect.rs 类型识别   capture.rs 快照 → 记录   store.rs SQLite      │
├─ 平台层 crates/xpaste-platform/（不依赖 tauri；按 #[cfg(target_os)] 编译不同实现）───┤
│  macos.rs   objc2 系列                  windows.rs   windows 库                     │
└──────────────────────────────────────────────────────────────────────────────────┘
```

把核心层和平台层拆成独立的 crate，而不是 `src-tauri/src/` 下的模块，目的是让编译器替我们执行 ADR-001 第 3 条约定（“核心逻辑不依赖 Tauri”）：这两个 crate 的 `Cargo.toml` 里没有 `tauri`，谁想在里面调 Tauri 都编译不过。Tauri 官方的项目结构只规定了 `src-tauri/` 内部的布局，对外层用 Cargo 工作区没有限制；Tauri CLI 通过 `tauri.conf.json` 定位应用 crate，工作区放在仓库根目录即可。

### 3.2 线程

| 线程 | 职责 | 所在层 |
| --- | --- | --- |
| 主线程 | Tauri 事件循环、窗口、托盘、全局快捷键。macOS 上所有 AppKit 调用（NSPanel、模拟粘贴前的窗口操作）必须在这里执行 | 应用层 |
| 监听线程 | macOS：每 300 ms 读一次 `changeCount`；Windows：一个隐藏的消息窗口接收 `WM_CLIPBOARDUPDATE`。检测到变化后读取快照，调用 `xpaste_core::capture::process` 写库，再通过 `AppHandle::emit` 通知前端 | 平台层提供监听，应用层 `clipboard.rs` 接线 |
| 补全线程 | 生成图片缩略图、视频封面和元数据、来源应用图标。完成后更新记录，发出 `record-updated`。一个线程加 `std::sync::mpsc` 队列 | 应用层 `enrich.rs`（`clipboard.rs` 投递任务） |
| 命令 | 所有访问数据库或剪切板的命令都声明为 `#[tauri::command(async)]`（或 `async fn`），由 Tauri 的异步运行时在工作线程上执行。**不加 `async` 的命令在主线程上执行**，一次几十毫秒的 SQLite 查询就会让界面掉帧 | 应用层 |
| 定时任务 | 每小时清理一次过期记录；软删除 5 秒后彻底删除。`housekeeping.rs` 用 `std::thread` 加 `thread::sleep`：一个常驻线程负责每小时清理，每次软删除起一个短命线程 | 应用层 |

数据库连接只有一个，封装在 `Store` 里，放在托管状态 `AppState` 的 `Mutex<Store>` 里（`std::sync::Mutex`，锁内没有 `await`），通过 `tauri::State<'_, AppState>` 注入到命令，不用全局变量。
`// ponytail: 单连接全局锁；如果补全线程写库与面板读取出现可感知的等待，再拆成读写两个连接（WAL 模式支持）`

### 3.3 为什么不用这些官方插件

| 插件 | 原因 |
| --- | --- |
| `tauri-plugin-clipboard-manager` | 只能读写文本、HTML 和图片，没有变化监听、读不到全部原始格式和敏感标记，满足不了 M01 |
| `tauri-plugin-sql` | 面向前端直接写 SQL 的场景；我们的数据逻辑都在 Rust 里，用 rusqlite 直接访问更简单，也方便测试 |
| `tauri-plugin-store` | 设置和历史放在同一个 SQLite 里，一处备份、一个事务；不值得再引入一个 JSON 文件 |
| `tauri-plugin-window-state` | 它会连同位置一起恢复，与“面板出现在鼠标所在显示器”冲突；尺寸记忆自己写只有十几行 |
| `tauri-plugin-positioner` | 面向托盘旁定位，我们按鼠标所在显示器定位 |

## 5. 核心层（`crates/xpaste-core`）

### 5.1 数据模型

```sql
PRAGMA journal_mode = WAL;      -- 进程被强制结束时已提交的事务不丢（AC-M03-04）
PRAGMA synchronous = NORMAL;
PRAGMA foreign_keys = ON;
-- 表结构版本记在 PRAGMA user_version，启动时按版本号依次执行迁移

CREATE TABLE records (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,  -- id 不复用：已删除记录的 id 不会分给新记录
  hash        BLOB    NOT NULL UNIQUE,   -- 去重哈希，见 5.4
  kind        TEXT    NOT NULL,          -- text | link | code | image | video | file
  title       TEXT    NOT NULL,          -- 列表标题，按 M07 规则 3 在采集时算好
  text        TEXT,                      -- 纯文本内容（文本、链接、代码）
  paths       TEXT,                      -- JSON 数组：文件引用的路径（图片文件、视频、文件）
  link_title  TEXT,                      -- 链接的页面标题，只来自剪切板数据
  lang        TEXT,                      -- 代码语言：JavaScript | Shell | SQL | …，识别不出为 NULL
  size        INTEGER NOT NULL,          -- 字节数，见 5.3
  meta        TEXT,                      -- JSON：图片 w/h；视频 duration/w/h/fps/codec（扁平）
  search_text TEXT    NOT NULL,          -- 小写后的“内容 + 链接标题 + 文件名与路径 + 来源应用名”
  app_id      TEXT REFERENCES apps(id),  -- 来源应用；NULL 表示“未知来源”
  copied_at   INTEGER NOT NULL,          -- 毫秒时间戳，决定排序和分组
  uses        INTEGER NOT NULL DEFAULT 0,
  pinned      INTEGER NOT NULL DEFAULT 0,
  deleted_at  INTEGER                    -- 软删除时间，非 NULL 的记录不对前端返回
);
CREATE INDEX records_copied_at ON records(copied_at);

-- 剪切板原始格式，粘贴时原样写回（M01 规则 2、10）
CREATE TABLE flavors (
  record_id INTEGER NOT NULL REFERENCES records(id) ON DELETE CASCADE,
  item      INTEGER NOT NULL CHECK (item < 65536),   -- macOS 的 NSPasteboardItem 序号；Windows 固定为 0
  format    TEXT    NOT NULL,   -- macOS 为 UTI；Windows 为格式名（标准格式用 "CF_UNICODETEXT" 这类名字）
  data      BLOB,               -- ≤ 1 MB 时直接存库
  file      TEXT,               -- > 1 MB 时存为 blobs/<record_id>/<序号>，这里记相对路径
  PRIMARY KEY (record_id, item, format)
);

CREATE TABLE apps (
  id   TEXT PRIMARY KEY,        -- macOS bundle ID；Windows 可执行文件完整路径
  name TEXT NOT NULL,
  icon_path TEXT                -- 图标 PNG 的绝对路径（icons/<哈希>.png），由补全线程填入。存为文件而不是 BLOB，供 asset 协议读取
);

CREATE TABLE kv (key TEXT PRIMARY KEY, value TEXT NOT NULL);  -- 设置（JSON）、是否完成首次引导等
```

**迁移**（`store.rs` 的 `MIGRATIONS`，只往末尾追加，`PRAGMA user_version` 记已执行到第几条）：

| user_version | 内容 |
| --- | --- |
| 1 | 建表（上面的结构） |
| 2（阶段 9） | 删除颜色类型：`UPDATE records SET kind = 'text', title = trim(text, ' ' \|\| char(9, 10, 13)) WHERE kind = 'color';`。不加这条，`Kind::parse` 遇到 `'color'` 会让 `list_summaries` 和 `bootstrap` 失败，整个历史读不出来。`trim` 去空格、制表与换行，与旧的颜色判定（Rust `trim()`）一致。`hash` 不动：颜色和文本的规范化内容本来都是 `"text\n"` + 文本，去重照样命中 |

`store.rs` 只接收一个数据目录路径，不知道这个路径怎么来的。应用层用 Tauri 的 `path().data_dir()`（macOS 为 `~/Library/Application Support`，Windows 为 `%APPDATA%`）拼上 `xPaste/` 后传进来。不要用 `app_data_dir()`，它会按应用标识生成 `com.xpaste.app` 目录名，与规格说明 M03 不符。

```
xPaste/
  xpaste.db (+ -wal, -shm)
  blobs/<record_id>/…        大于 1 MB 的原始格式数据
  images/<record_id>.png     位图记录的 PNG（预览用）
  thumbs/<record_id>.png     图片缩略图和视频封面，长边 320 px
  icons/<哈希>.png           来源应用图标，文件名为应用 id 的 SHA-256 前 16 字节（32 位小写 hex）
  logs/                      tauri-plugin-log 的日志文件
```

删除记录时，同时删除它在 `blobs/`、`images/`、`thumbs/` 下的文件。

### 5.2 采集流程（`capture.rs`）

平台层把剪切板读成一个与平台无关的快照（类型定义在 `model.rs`）：

```rust
pub struct Snapshot {
    pub flavors: Vec<Flavor>,         // (item, format, data)
    pub text: Option<String>,         // 纯文本，换行统一为 \n
    pub html: Option<String>,
    pub file_paths: Vec<PathBuf>,
    pub bitmap: Option<Vec<u8>>,      // PNG 字节；macOS 的 TIFF、Windows 的 DIB 在平台层转换
    pub url_title: Option<String>,    // 见 5.3
    pub sensitive: bool,              // 平台层已检测到敏感标记（开关关闭时内容照常读出，仍为 true）
    pub source: Option<AppInfo>,      // id、name
}
```

`capture::process(snapshot, &settings, paused, &mut store, now_ms) -> Result<Outcome, CoreError>`，`Outcome` 为 `Skipped(原因)`、`Added(id, removed)` 或 `Merged(id, removed)`（`removed` 为容量清理删除的 id）。依次执行，任何一步返回“跳过”就结束：

1. 已暂停 → 跳过（M01 规则 8）。
2. `sensitive && settings.skip_sensitive` → 跳过（规则 6）。平台层 `read_snapshot(skip_sensitive)` 在开关开启时遇到敏感标记只返回标记、不读内容；开关关闭时照常读出内容并保留 `sensitive = true`，这一步放行，按普通内容入库（AC-M01-08）。
3. 来源应用在忽略列表中 → 跳过（规则 7）。忽略列表按应用名称匹配（`capture::is_ignored_app`：去首尾空白、不区分大小写）。P0 阶段设置里是逗号分隔的文本，这样匹配最直接。

第 1、3 步在监听回调里先做一次：已暂停，或 `frontmost_app()` 的名称命中忽略列表时，**不读取剪切板**直接跳过；`process` 里保留同样的检查兜底。
4. 超过大小上限 → 跳过（规则 9）：纯文本超过 5 MB，或位图超过 50 MB。
5. 快照里既没有文本，也没有文件和位图 → 跳过。例如只包含私有格式的复制，没有可以展示的内容。
6. 用 `detect::kind()` 判定类型，计算哈希。哈希已存在时更新原记录（5.4）并返回 `Merged`，否则新建记录返回 `Added`。
7. 一个事务内写入 `records`、`flavors` 和 `apps` 的名称；超出“最多保存条数”的部分在同一事务里删除（5.5），被删除的 id 一并返回。

补全任务（位图生成 PNG 和缩略图、视频封面与元数据、来源应用图标）由应用层根据 `Outcome` 放进队列，核心层不管线程。

**自身写入不记录**（规则 5）：平台层写剪切板后返回写入后的序号（macOS 为 `changeCount`，Windows 为 `GetClipboardSequenceNumber()`），应用层记在 `AppState`。监听线程遇到这个序号时直接跳过，不读取剪切板。

### 5.3 字段计算

| 字段 | 规则 |
| --- | --- |
| `title` | 文本：第一个非空行，截断到 200 字符；链接：`link_title`，没有时用 URL；图片、视频、文件：第一个文件名，多个文件时为“文件名 等 N 个”；位图：`截图 YYYY-MM-DD HH.mm.png`，按复制时间生成。时间戳目前为 UTC（核心层不引入时区库），前端按 `copiedAt` 本地化显示 |
| `size` | 文本类：纯文本的 UTF-8 字节数；位图：PNG 字节数；文件引用：各文件大小之和（文件夹不递归统计，大小记 0，界面显示“—”） |
| `link_title` | 按顺序取第一个能取到的：macOS 的 `public.url-name`；HTML 内容恰好是一个 `<a href="同一 URL">标题</a>` 时取其中的文字；Windows 的 `UniformResourceLocatorW` 搭配 `FileGroupDescriptorW` 中的文件名（去掉 `.url` 后缀）。都取不到时为 NULL。**不联网**（M08 补充规则 1） |
| `lang` | P1。按顺序判断：以 `$ `、`git `、`npm `、`pnpm ` 开头为 Shell；以 `SELECT`、`INSERT`、`UPDATE`、`WITH` 开头（不区分大小写）为 SQL；包含 `const `、`let `、`function `、`=>`、`import ` 为 JavaScript；其余为 NULL |
| `search_text` | 文本内容、`link_title`、所有文件名和完整路径、来源应用名，用换行连接后整体转小写（Rust `to_lowercase()`） |

### 5.4 类型识别与去重

`detect::kind(&Snapshot) -> Kind` 严格按规格说明 M02 表格的顺序判断。规则 4 只在没有非空白文本时把位图判为图片；Numbers、Pages 等复制单元格或段落时会同时放入文本和渲染图，这时继续按文本规则（链接、代码、文本）判定，位图仍写入 `images/` 供预览，哈希按文本计算。扩展名列表、代码编辑器名单和正则都写成常量，放在这个文件里。代码前缀（`$ `、`git `、`SELECT` 等）按规格说明原文的大小写精确匹配：不区分大小写会把 “Let me…” 这类普通句子误判为代码。代码编辑器名单按 bundle ID（macOS）和可执行文件名（Windows）匹配：

```
com.microsoft.VSCode  com.todesktop.230313mzl4w4u92(Cursor)  com.jetbrains.*  com.apple.dt.Xcode
com.sublimetext.*  com.apple.Terminal  com.googlecode.iterm2
Code.exe  Cursor.exe  idea64.exe 等 JetBrains *64.exe  sublime_text.exe  WindowsTerminal.exe  powershell.exe  pwsh.exe
```

一次复制多个文件时：全部是视频则为视频，全部是图片则为图片，否则为文件。

阶段 9 删除了颜色规则（`is_color`）：`#6F8BFF` 这类文本按文本判定，来源是代码编辑器时为代码（测试 `ac_m02_01_hex_colors`）。

**哈希**：对“规范化内容”计算 SHA-256（使用 `sha2` 库，0.11）。不使用标准库的 `DefaultHasher`，因为它的结果在不同 Rust 版本之间不保证一致，而哈希要写入数据库长期使用。

| 类型 | 规范化内容 |
| --- | --- |
| 文件引用（图片文件、视频、文件） | `"files\n"` + 排序后的路径，用 `\n` 连接 |
| 位图（类型为图片，即没有非空白文本） | `"bitmap\n"` + 平台层转换出的 PNG 字节 |
| 其他 | `"text\n"` + 纯文本（换行已统一为 `\n`，不去首尾空白） |

**命中已有记录时**（M01 规则 4）：`uses + 1`；非置顶记录同时把 `copied_at` 更新为当前时间；如果记录处于软删除状态，先恢复。原始格式保留首次的数据，不覆盖。

### 5.5 清理

| 时机 | 动作 |
| --- | --- |
| 启动时 | 彻底删除所有 `deleted_at` 非 NULL 的记录（上次退出前没来得及删除的软删除）；执行一次保留时长清理 |
| 每小时 | 保留时长清理：删除 `copied_at` 早于“现在 − 保留时长”的非置顶记录。保留时长为“永久”时跳过 |
| 每次新建记录 | 非置顶记录数超过“最多保存条数”时，按 `copied_at` 从旧到新删除多出的部分。“最多保存条数”只计非置顶记录，置顶记录不占名额 |
| 保存设置前 | 前端调用 `prune_preview(retention, max)` 获取将被删除的条数（保留时长与最多条数两条规则命中记录的并集，同一条不重复计数）；大于 0 时先弹确认“将删除 N 条记录”，用户确认后才保存（M03 规则 5） |

清理导致记录被删除时，向前端发出 `records-removed` 事件。

### 5.6 删除与撤销

- `delete(id)`：设置 `deleted_at = now`，应用层同时启动一个 5 秒定时器；5 秒后如果 `deleted_at` 仍是这个值，就彻底删除。
- `undo_delete(id)`：把 `deleted_at` 设为 NULL。置顶状态和使用次数都在记录里，恢复后自然保持不变。
- 前端只保留最近一次删除的撤销入口。连续删除多条时，前面几条在各自的 5 秒后彻底删除（AC-M20-03）。

### 5.7 设置

设置以一个 JSON 对象存在 `kv` 表的 `settings` 键下，用 serde 读写，`#[serde(default)]` 让缺少的字段取默认值：

```rust
#[derive(Serialize, Deserialize)]
#[serde(rename_all = "camelCase", default)]
pub struct Settings {
    pub hotkey: String,              // Tauri 快捷键格式，默认 "CommandOrControl+Shift+V"
    pub retention_days: Option<u32>, // 7 | 30 | 90，None 表示永久；默认 Some(30)
    pub max_records: u32,            // 50..=5000，步长 50，默认 500
    pub ignored_apps: Vec<String>,   // 默认值按平台不同，见 M15
    pub skip_sensitive: bool,        // 默认 true
    pub move_to_top: bool,           // 默认 true
    pub launch_at_login: bool,       // 默认 true
    pub appearance: Appearance,      // System | Light | Dark，默认 Dark（阶段 9.1；已保存的值不变）
    pub panel_size: (f64, f64),      // 逻辑像素，默认 (960, 640)
    pub last_filter: String,         // 默认 "all"（Q5：保留分类）；旧值 "color" 不在分类里，前端启动时退回 "all"
    pub spectrum_collapsed: bool,    // 默认 false（M14 规则 9）；由前端 persistUi 保存
    pub frequent_min_uses: u32,      // 2..=99，默认 3（阶段 9.1）：uses ≥ 它即属“常用”；只在前端用（view.ts / format.ts isFav），保存后立即重绘列表与计数
}
```

新增字段必须带默认值，并同步 `commands/settings.rs` 的 `changed_fields`、`src/api/types.ts` 与 `model.rs` 的默认值测试。

**暂停状态**不在 `Settings` 里，单独存在 `kv` 的 `paused` 键（`"1"` 为暂停，`"0"` 为记录）：`set_paused_inner` 改原子标志后写入（写失败只记 warn，本次运行照样暂停）；`AppState::new` 启动时读取，读不到或出错都按未暂停。托盘初始文字与图标、`bootstrap` 的 `paused` 都读这个原子，所以三处一致（M01 规则 8）。

`Settings::validate()` 在核心层实现，`save_settings` 命令调用它。前端用同样的规则先校验一遍，方便即时提示。

**`codec_label(&str) -> String`**（`lib.rs`，两个平台共用的纯函数）给出编码的显示名。macOS 传 FourCC（`avc1`），Windows 传子类型名（`H264`）；不区分大小写，去掉首尾空白。映射：`avc1` / `avc3` / `h264` / `x264` → H.264；`hvc1` / `hev1` / `hevc` / `h265` → HEVC；ProRes 的六个 FourCC → ProRes；`vp08` / `vp80` → VP8；`vp09` / `vp90` → VP9；`av01` → AV1；`mp4v` → MPEG-4；`jpeg` / `mjpg` / `mjpa` → Motion JPEG；`wmv3` → WMV。不认识的原样转成大写，空串返回空串。`VideoMeta` 的字段为 `duration_sec`（serde 名为 `duration`）、`w`、`h`（按显示方向）、`fps`、`codec`，未知时填 0 或 `""`；写入 `records.meta` 时用扁平键（5.1）。摘要读 `duration` 时把 ≤ 0 当作没有（`duration_sec` 为 None），界面不显示 `00:00`，选中时会像缺 meta 一样每次运行补跑一次。

`kVK_ANSI_V` 是物理按键位置。使用 Dvorak 等非 QWERTY 键盘布局时，这个键位可能不是 V。`// ponytail: 固定键码；有用户反馈时再用 UCKeyTranslate 按当前布局查出 V 的键码`

**Windows 不保存的格式**（`winfmt::formats_to_read`）：基于 GDI 句柄的格式不能按内存块读写，读到的是句柄而不是数据，跳过 `CF_BITMAP`、`CF_METAFILEPICT`、`CF_ENHMETAFILE`、`CF_PALETTE`、`CF_DSPBITMAP`、`CF_DSPMETAFILEPICT`、`CF_DSPENHMETAFILE`、`CF_OWNERDISPLAY`（id 2、3、14、9、0x82、0x83、0x8E、0x80）。由系统自动合成的 `CF_TEXT`、`CF_OEMTEXT`（id 1、7）也不保存，写回 `CF_UNICODETEXT` 后系统会重新合成。OLE 的 `DataObject`、`Ole Private Data` 按名字跳过：它们是源进程里 OLE 对象的令牌，写回后对象已不存在，原样写回会让资源管理器粘贴失败。`CF_DIB` 与 `CF_DIBV5` 只读枚举中先出现的那个（后出现的是系统合成的）。Office 的 `Link Source`、`Embed Source`、`Object Descriptor` 不预先跳过，等 Windows 验收（验收记录 阶段6-W7）证明有问题再加进跳过列表。

**单个格式超过 50 MB 时跳过该格式**，不放弃整条记录。它通常是 Office 等应用写入的私有格式，跳过后仍可以按文本或图片粘贴。

## 7. 面板窗口（`src-tauri/src/panel.rs`）

### 7.1 窗口配置

`tauri.conf.json` 中删除模板生成的 `main` 窗口，改为一个 `panel` 窗口，并在启动时预先创建好：

```json
{
  "label": "panel", "url": "index.html",
  "width": 960, "height": 640, "minWidth": 720, "minHeight": 520,
  "visible": false, "decorations": false, "transparent": true,
  "alwaysOnTop": true, "skipTaskbar": true, "resizable": true, "shadow": true
}
```

平台特有项放在平台配置文件里，不和共用配置混在一起：

| 文件 | 内容 |
| --- | --- |
| `tauri.macos.conf.json` | `bundle.targets: ["dmg"]`；`bundle.macOS.minimumSystemVersion: "13.0"` |
| `tauri.windows.conf.json` | `bundle.targets: ["nsis"]`；`bundle.windows.nsis.installMode: "currentUser"`（规格说明 5.5.2，不需要管理员权限）；`languages: ["SimpChinese"]`（安装界面只有简体中文，不显示语言选择）；`installerHooks: "./windows/hooks.nsh"`（第 2 节回写项 4） |

`app.macOSPrivateApi: true` 写在共用的 `tauri.conf.json` 里，不放平台文件：tauri-build 会用目标平台合并后的配置校验 Cargo features，放在 macOS 文件里会让 Windows 构建因 `macos-private-api` feature 不匹配而失败。

| 平台 | 启动时的额外处理 |
| --- | --- |
| macOS | 设置 `ActivationPolicy::Accessory`，不显示 Dock 图标（M04 规则 4）。用 `tauri-nspanel` 把窗口转换为 `NSPanel`：样式加 `nonactivatingPanel`，层级设为浮动层级，`collectionBehavior` 设为 `canJoinAllSpaces \| fullScreenAuxiliary`。这样面板能浮在全屏应用之上（AC-M04-02），能接收键盘输入，同时前台应用保持不变，粘贴时不需要切回焦点。`tauri-nspanel` 不在 crates.io 上，用 git 依赖并锁定到具体 commit |
| Windows | `skipTaskbar` 隐藏任务栏按钮。显示前用 `GetForegroundWindow()` 记下上一个窗口，供粘贴使用 |

**毛玻璃材质**（M16 规则 2）使用 `window-vibrancy` 库：

| 平台 | 调用 | 前端 `data-material` |
| --- | --- | --- |
| macOS | `apply_vibrancy(HudWindow, Active, 圆角 16)` | `glass` |
| Windows 11 | `apply_mica`；失败时 `apply_acrylic` | `glass` |
| Windows 10 / 以上都失败 | 不调用 | `opaque` |

Windows 10 的判定是 `apply_mica` 返回 `UnsupportedPlatformVersion`（不读系统版本号），此时不试 Acrylic：规格说明 M16 规则 2 与 AC-M16-03 要求 Windows 10 不透明，而且 Acrylic 在 Windows 10 上拖动、调整尺寸时卡顿；Mica 因其他原因失败才试 `apply_acrylic`。选择逻辑是纯函数 `panel::windows_material`（错误值注入测试），启动时由 `panel::setup_windows` 调用（应用层 `lib.rs` 唯一的 `#[cfg(windows)]`），选为 `opaque` 时记 info 日志 `系统材质不可用，使用不透明背景`。Mica 跟随窗口主题（`dark: None`），`apply_theme` 设置窗口主题时 Mica 明暗随之变化。

前端根据 `data-material` 设置面板背景：为 `glass` 时使用半透明的颜色 token，模糊交给系统材质完成，CSS 里去掉 `backdrop-filter`；为 `opaque` 时使用不透明背景，配色不变（AC-M16-03）。

### 7.2 显示与隐藏

`toggle(app, t0, trigger)` 由全局快捷键（`Trigger::Hotkey`）、托盘（Windows 左键单击，`Trigger::Tray`）、第二次启动应用（single-instance；macOS 重开已运行的 .app 为 `RunEvent::Reopen`；两者都是 `Trigger::Relaunch`）调用。以窗口实际可见性为准，动作由纯函数 `toggle_action` 按以下顺序决定（测试 `toggle_action_by_trigger`）：

1. 可见且有待处理的隐藏请求（快捷键或托盘隐藏的前端淡出途中）：重新唤起（`show_panel`），不重记上一个窗口。此时前台是面板自己，重记会把面板当成粘贴目标，随后的 Enter 就粘贴失败。
2. 可见、引导中或设置 / 确认框打开（`keep_visible = onboarding || dialog_open`）、来源是快捷键：不隐藏，发 `hotkey-pressed`（见下段）。
3. 其他可见情况：请求隐藏（前端淡出，后端 400 ms 兜底）。引导中的托盘单击与再次启动也是隐藏，不算试按。
4. 不可见、来源是托盘、距上次隐藏（任何方式，`hide()` 成功时记时间）不到 `TRAY_AFTER_HIDE_MS`（300 ms）：不重新显示。Windows 上按下托盘图标时面板已因失焦隐藏，松开时的单击事件不应再把它打开；按住超过 300 ms 再松开会重新打开，这是规则本身的代价。
5. 其他不可见情况：显示（记下上一个窗口）；引导中且来源是快捷键时，显示之后再发 `hotkey-pressed`。

**首次引导期间**（`AppState.onboarding`，首次启动在 setup 中置位并直接显示面板，`finish_onboarding` 清除）：面板可见时快捷键不隐藏面板，改发 `hotkey-pressed`；面板隐藏时照常显示，并在显示之后再发一次 `hotkey-pressed`（与 `panel-shown` 同经 `run_on_main_thread` 排队，保证 `panel-shown` 先到）。

**设置或确认框打开期间**（`AppState.dialog_open`，阶段 9）：前端在每次 `showModal` 之后和每个 `close` 事件里调用 `set_dialog_open(open)`，`open` 按 DOM 实际状态（`#settings` 或 `#confirm` 有一个打开）计算，启动时先发一次 false；引导对话框不算（引导里的“授权”要切去系统设置，面板浮在最上层会盖住它）。标志为真时，失焦不隐藏，快捷键按第 2 条不隐藏：面板有焦点时发 `hotkey-pressed`；面板已失焦（用户点去了别的应用）时只把面板拉回焦点（与显示第 3 步同一套 `front_and_focus`），不发 `hotkey-pressed`，前端的录制框另以 `document.hasFocus()` 把关。引导中失焦时同样拉回焦点，但照发 `hotkey-pressed`，试按照样算成功。`set_dialog_open(false)` 只在标志由真变假（`swap` 返回 true）时检查窗口：可见且未聚焦就隐藏（`panel::hide_if_unfocused`），因为对话框在用户切走之后才关闭（Esc 收起计时、异步保存），当时的失焦已被忽略。标志本来就是假（前端启动时的那次 false）时不隐藏，否则首次运行时可见但还没取得焦点的引导面板会被藏起（AC-M18-01）。`panel::hide()` 开头把标志复位为 false，前端漏发（例如开发时重载页面）也不会让失焦隐藏一直失效。

**显示**：

1. 取鼠标位置 `cursor_position()`，在 `available_monitors()` 中找到鼠标所在的显示器。
2. 用设置里的 `panel_size` 设置窗口尺寸；位置水平居中（每次显示都重新定位，所以拖动标题栏只在本次显示有效，规格说明 M04 规则 2），窗口顶边位于工作区高度的 1/6（窗口中心大约在上三分之一处）。全程用逻辑像素计算，最后按该显示器的缩放比例换算为物理像素。macOS 直接设逻辑尺寸与位置；其他平台按目标显示器的缩放自己换算后传物理值（tao 会按窗口当前所在显示器换算逻辑值，混合 DPI 下会落到屏外），并且先移位置再定尺寸：跨缩放比例移动会触发 `WM_DPICHANGED`，系统按比例改窗口尺寸，最终尺寸以后设的为准（验收记录 阶段6-W5）。
3. macOS：`panel.show()` 并设为 key window。Windows：`show()` 后 `set_focus()`。
4. 发出 `panel-shown` 事件（带来源 `trigger`：`hotkey` / `tray` / `relaunch`；托盘菜单项与托盘单击都是 `tray`，粘贴失败后的重新显示按 `hotkey`），前端收到后清空搜索、选中第一条、聚焦搜索框。进入动效：`tray` 是鼠标唤起，按原型 240 / 320 ms 弹性回位；其余来源设 `data-instant`，90 / 120 ms。

**隐藏的触发条件**（M04 规则 3）：快捷键（设置或确认框打开时除外）；前端发起的 `hide_panel`（按 Esc、粘贴完成、设置里“前往授权”成功之后）；窗口失去焦点（`WindowEvent::Focused(false)`，即点击了面板外部），`dialog_open` 为真时不隐藏；对话框全部关闭（`set_dialog_open` 由真变假）时已失焦（见上）。标题栏没有按钮（阶段 9 删除了最小化与关闭）。

**隐藏的淡出**：前端发起的隐藏先把 `data-shown` 置 false。不透明材质与 Windows：网页内容 160 ms 淡出（`opacity 140ms`、`transform 160ms`），播完再调 `hide_panel`。macOS 系统材质的底板是原生窗口，网页淡不掉它：bootstrap 时在 `<html>` 上设 `data-native-fade`（macOS 且非 opaque），此时 `.window[data-shown=false]` 保持 `opacity: 1`、只下移 10 px，前端立即调 `hide_panel(animate)`；后端（`hide_animated`，纯函数 `fade_out_ms` 决定是否淡出，测试 `native_fade_only_for_macos_system_material`）用 `NSAnimationContext` + `animator().setAlphaValue(0)` 在 160 ms 内把整个窗口淡到 0，由窗口 alpha 单独承担整体淡出（内容若也自己淡出，两者叠乘会让内容先消失、只剩底板），到点在主线程确认没被取消后 `orderOut` 并把 alpha 复位为 1。唤起对称（`try_show`，纯函数 `fade_in_ms`，测试 `native_fade_in_mirrors_fade_out`）：面板隐藏中、系统材质、系统没开“减弱动态效果”（`NSWorkspace accessibilityDisplayShouldReduceMotion`）时，上屏前把 alpha 置 0，上屏后 90 ms（托盘 240 ms）淡到 1，内容只按 CSS 上移（120 / 320 ms）；面板已可见（淡出途中重新唤起）时立即置 1。即：进入 = 窗口 alpha 0 → 1 90 ms + 内容位移 120 ms；退出 = 内容位移 160 ms + 窗口 alpha 1 → 0 160 ms。淡出途中算作待处理的隐藏（纯函数 `hide_pending`，`toggle` 的第 1 条：再按快捷键重新唤起，`show_panel` 取消淡出并立即把 alpha 置 1，测试 `reshow_during_native_fade`）；重复的 Esc 不重新开始。开启减少动态效果时 `animate` 为 false，直接隐藏。失焦、粘贴前、400 ms 兜底这些直接隐藏不淡出，也打断进行中的淡出并复位 alpha。Windows 不做原生淡出。

**尺寸记忆**（阶段 5 实现，`panel::remember_size`）：监听 `WindowEvent::Resized`，300 ms 防抖（序号计数，写法同隐藏兜底）。到期时读 `inner_size`、`scale_factor`、`is_visible`：窗口不可见或换算后小于 720 × 520 时不写；与当前 `panel_size` 相差不超过 1 逻辑像素时不写（显示时按设置改尺寸也会触发 Resized，分数缩放有舍入）；否则持 settings 锁改内存并写库（锁序 settings → store，没有反向路径）。`save_settings` 不采用前端传来的 `panelSize`，落库时持锁取当前值，两者并发时不会互相覆盖。

**唤起耗时测量**（AC-M04-07）：开发构建（`#[cfg(debug_assertions)]`）中，Rust 端在收到快捷键时记录时间戳并放进 `panel-shown` 事件；前端在搜索框获得焦点后的下一帧（`requestAnimationFrame`）计算差值并打印到控制台。这只能测到软件内部耗时，最终验收仍要用高速摄像。

## 8. 前后端接口

### 8.1 错误类型

```rust
// src-tauri/src/error.rs
#[derive(Debug, thiserror::Error)]
pub enum AppError {
    #[error("原文件已移动或删除，无法粘贴")] FileMissing,
    #[error("写入剪切板失败，请重试")]       ClipboardWrite,
    #[error("该快捷键已被其他应用占用，请换一个")] HotkeyTaken,
    #[error("{0}")]                           Invalid(String),   // 参数不合法：非 http 链接、记录不存在等，kind 为 "invalid"
    #[error(transparent)]                     Core(#[from] xpaste_core::CoreError),
    #[error(transparent)]                     Tauri(#[from] tauri::Error),
    #[error(transparent)]                     Opener(#[from] tauri_plugin_opener::Error),
}
// 设置校验失败为 Core(CoreError::InvalidSettings(_))，kind 序列化为 "invalidSettings"
// 其余 Core、Tauri、Opener 的 kind 都是 "internal"；Opener 的 message 透传插件的错误文本（可能含路径），前端不得写进日志
// Serialize 为 { "kind": "fileMissing", "message": "…" }，前端按 kind 分支，message 直接用作提示条文案
```

所有命令都返回 `Result<T, AppError>`。规格说明附录里的提示条文案就是 `#[error("…")]` 里的字符串，只写一处。

### 8.2 类型（`src/api/types.ts`，与 `model.rs` 对应）

```ts
type Kind = 'text' | 'link' | 'code' | 'image' | 'video' | 'file';

// thumb、app.icon、image.src 在核心层是绝对路径，应用层 assets::summary_dto / detail_dto 转为 asset URL 后再发给前端
interface RecordSummary {          // 列表、频谱、计数用，启动时一次性全部加载
  id: number; kind: Kind; title: string;
  app: { name: string; icon: string | null } | null; // icon 为 asset URL
  copiedAt: number; uses: number; pinned: boolean; size: number;
  lang: string | null; thumb: string | null;   // 图片缩略图 / 视频封面的 asset URL
  durationSec: number | null;      // 视频
}

// 可选字段一律为 `| null`（Rust 的 Option 序列化为 null，字段始终存在）
interface RecordDetail extends RecordSummary {  // 选中某条记录时获取
  text: string | null;             // 超过 200 KB 时截断，并设置 truncated
  truncated: boolean;
  linkTitle: string | null;
  files: { path: string; name: string; ext: string; size: number; exists: boolean }[];
  image: { src: string; w: number; h: number } | null;
  video: { src: string | null; w: number; h: number; fps: number; codec: string } | null; // 只有视频有；src 为 null 表示源文件不存在；时长、封面、字节数在摘要（durationSec、thumb、size）
}
```

5000 条摘要大约 1.5 MB，常驻前端内存没有问题。

### 8.3 命令（`src-tauri/src/commands/`）

### 8.4 事件（Rust → 前端，`src/api/events.ts`）

| 事件 | 数据 | 前端处理 |
| --- | --- | --- |
| `record-added` | `RecordSummary` | 插入列表，播放“新记录进入”动效（面板可见时），频谱长出新光柱 |
| `record-updated` | `RecordSummary` | 替换数据：去重命中，或补全线程生成了缩略图 / 图标（图标写入后，对该应用的全部记录各发一次） |
| `records-removed` | `number[]` | 自动清理或清空历史后移除 |
| `panel-shown` | `{ t0?: number; trigger: 'hotkey' \| 'tray' \| 'relaunch' }` | 见 7.2 |
| `panel-hidden` | — | `panel::hide()` 隐藏成功后发出。Esc 或粘贴隐藏之后，失焦可能再触发一次隐藏，所以同一次隐藏可能收到两次；前端只写状态（`data-shown=false`、关闭菜单、失焦），重复处理没有副作用 |
| `panel-hide-requested` | — | 快捷键或托盘在面板可见时发出（`panel::toggle`）：前端走 `hide()`，播 160 ms 淡出后调 `hide_panel`（macOS 系统材质下立即调，由后端淡出窗口，7.2）。后端同时起 400 ms 兜底，届时仍有未处理的请求就直接隐藏（前端失效也能隐藏）；淡出途中再次按快捷键视为重新唤起 |
| `paused-changed` | `boolean` | 标题栏徽标 |
| `open-settings` / `confirm-clear` | — | 托盘菜单触发：先唤起面板，再打开对应对话框 |
| `hotkey-pressed` | — | 首次引导期间，或设置 / 确认框打开时发出（见 7.2）：面板可见时按快捷键；引导中面板隐藏时按快捷键，在 `panel-shown` 之后也发一次。前端：焦点在快捷键录制框时，把当前快捷键写入录制框（网页收不到被全局注册拦下的按键，被拦下的正是当前快捷键）；引导停在“试按快捷键”一步时判为成功；其他时候忽略（只有快捷键触发会发出；再次启动应用或托盘单击走 `toggle(Trigger::Relaunch / Tray)`，不发出） |

事件名在 Rust 端和 `events.ts` 各写一份常量，命名用 kebab-case。阶段 1 的临时事件 `clipboard-changed` 在阶段 3 删除，前端只靠 `record-*` 事件更新。`events::emit_summary` 只对未软删除的记录发事件（`Store::live_summary`），软删除期间补全完成不会让记录在前端复现。

**风险，需要技术验证**：窗口隐藏时，WKWebView 可能暂停执行脚本，导致事件在隐藏期间不被处理。如果出现这种情况，改为在 `panel-shown` 时调用 `bootstrap()` 重新拉取数据（5000 条的耗时也要测）。

### 8.5 复制与粘贴流程

```
copy(id, paste)
 ├─ 有文件引用且任一文件不存在 → Err(FileMissing)          前端提示，面板不隐藏
 ├─ platform::write(flavors)，记下返回的序号 → 失败时 Err(ClipboardWrite)   前端提示
 ├─ uses + 1；move_to_top 开启且记录未置顶时 copied_at = now；发出 record-updated
 ├─ !paste → Ok(Copied)
 ├─ platform::can_paste(target) 被阻止 → Ok(CopiedOnly)         面板不隐藏，提示“已复制，在目标应用中按 Mod + V 粘贴”
 └─ 隐藏面板 → platform::paste() → Ok(Pasted)
```

`platform::paste()` 在 macOS 上要在主线程执行，命令里用 `app.run_on_main_thread()` 调度。

使用次数首次达到常用阈值（`frequentMinUses`，默认 3）时的“已加入常用”提示（文案里的次数取当时的使用次数），由前端比较 `uses` 前后的值来判断并显示。面板隐藏后提示显示不出来，所以只在面板仍可见时提示（`Copied`、`CopiedOnly`）。

## 9. 前端

### 9.1 迁移方式

原型就是界面的实现，迁移时尽量少改，不重写：

1. 把原型的 `<style>` 整体移到 `src/styles.css`，`<body>` 中的面板部分移到 `index.html`，`<script>` 移到 `src/main.ts`，并补上类型。
2. 删除规格说明第 0 章列出的演示部分：极光与噪点背景、页头的演示按钮、示例数据、“在网页空白处粘贴加入历史”。主题切换控件移到设置对话框。
3. 字体改为本地加载：删除 Google Fonts 的 `<link>`，把 woff2 文件放进 `src/fonts/`，用 `@font-face` 引用（AC-M16-04）。只打包实际使用的字重：Geist 400/500/600、Unbounded 500/700、JetBrains Mono 400/500。实际做法：用 Google Fonts CSS2 API 取每族 latin 子集的可变字体，每族一个 woff2 文件，覆盖上述字重；由 `scripts/fetch-fonts.sh`（`make fonts`）下载，三个文件合计约 111 KB，OFL 许可证文本放在同一目录。中文回落系统字体，不打包 CJK 子集。
4. 原型直接修改 `S.items` 的地方，改为调用 `src/api/commands.ts` 中的函数，然后用返回值或事件更新本地状态。`main.ts` 不直接 `import '@tauri-apps/api'`。
5. 设置对话框的标记与样式随原型一起迁移，但阶段 5 之前 `#settingsBtn` 为 `disabled`（`title="设置将在后续版本提供"`），`Mod + ,` 不响应；外观只在启动时按 `settings.appearance` 应用。
6. 原型 `.window` 的 `backdrop-filter` 去掉，毛玻璃由系统材质负责；`opaque` 材质下 `.window` 背景用 `--ink`（14 px 圆角外露出的方角底色在阶段 6 处理）。`.glow` 随标记迁移，跟随指针的脚本未迁移，阶段 7 动效对照时补上或删除。

主题 token、类型颜色、动效曲线、`[data-theme-switching]`、`prefers-reduced-motion` 降级、键盘触发的操作不加动画等规则，都按原型原样保留。

### 9.2 状态

```ts
const S = {
  records: Map<number, RecordSummary>,  // 全部摘要
  filter: string, q: string,
  matchIds: Set<number> | null,         // q 为空时为 null，表示不过滤
  sel: number | null,
  detail: RecordDetail | null,          // 当前选中项的详情
  undo: { id: number, title: string, expiresAt: number } | null,  // 只保留最后一次删除
  settings, platform, paused,
  canPaste: boolean,                    // 能否自动粘贴：macOS 取 accessibility_granted()，Windows 恒真（9.6 动作文案）
};
```

`visible()` 沿用原型的写法：分类过滤 ∩ `matchIds` → 排序 → 分组。分类计数基于 `records` 计算，不受搜索影响（M06 规则 2）。

### 9.3 搜索

- 监听 `input` 事件，跳过 `isComposing` 为 true 的事件（M05 规则 7）；组字结束时由 `compositionend` 再触发一次搜索。
- 每次输入都调用 `search(q)`，不做防抖，因为本地 IPC 加 SQLite 查询远低于 50 ms 的要求。用一个递增的请求序号丢弃过期的返回结果，避免先发后到的结果覆盖新结果。
- 高亮仍沿用原型的 `hl()`，只高亮标题中的匹配部分。

### 9.4 虚拟列表（M07 规则 8）

行高固定为 56 px（原型 `.row-in`），分组标题固定为 34 px（按原型 `.ghead` 的内边距加行高取值，CSS 中写死 `height: 34px; box-sizing: border-box`）。先把 `visible()` 的结果展开为“标题 / 行”的扁平数组，并算出每一项的 `top`。滚动时只渲染可视区域上下各多 8 行的元素，每一项包在绝对定位的 `.vrow`（`position: absolute; left: 0; right: 0`）里，用 `transform: translateY(top)` 定位；外层容器的高度设为总高度。分组标题与行平铺在同一层，不再有原型的 `role=group` 分组容器。

原型的 `@media (max-width: 760px)` 按面板改写后保留（M04 规则 5）：列表与预览上下叠放，状态栏只保留第一项；原型里的 `.window { height: auto }` 等网页适配规则不带。

原型中依赖 DOM 的几处对应调整：

| 原型做法 | 虚拟列表中 |
| --- | --- |
| 选中光标用 `r.offsetTop` 取位置 | 从扁平数组取 `top`，行不在 DOM 中时也能定位 |
| `scrollIntoView` | 根据 `top` 直接设置 `scrollTop` |
| 新记录用 `grid-template-rows: 0fr → 1fr` 展开 | 只在新行位于可视区域时播放；可视区域下方的行整体下移 56 px，用 transform 过渡完成（阶段 3 未做：插入与删除时下方的行直接跳到新位置，归阶段 7 的 M20 对照） |
| 置顶时用 FLIP 平移 | 起点或终点不在可视区域时直接到位，不播放动画 |
| 列表逐行浮现（间隔 28 ms） | 只对首屏的行执行 |

`aria-activedescendant` 指向的选中行必须已经渲染。选中项总会被滚动到可视区域，所以这一点自然满足。

### 9.5 预览

沿用原型的 `bodyHTML()`，数据改为来自 `S.detail`。切换选中项时先用摘要渲染标题和信息栏，`get_record` 返回后再填充正文，保证按住方向键时预览不会被异步请求拖慢（AC-M20-02）。

| 类型 | 与原型的差异 |
| --- | --- |
| 文本 | 超过 200 KB 只显示前 200 KB，末尾提示“仅显示前 200 KB，复制时为完整内容” |
| 链接 | 点击 URL 调用 `open_url`；右键菜单“在浏览器中打开”同样调用它（9.6） |
| 代码 | 沿用原型的 `hlCode` 词法高亮 |
| 图片 | `src` 指向 `images/<id>.png`（位图）或原文件（文件引用），通过 asset 协议加载 |
| 视频 | 封面卡片 `figure.p-video`。有 `thumb` 时显示封面图；没有时显示深色占位，比例取 `w/h`，未知时为 16:9。右下角为时长；下方为 figcaption（文件名）和芯片（编码、`W × H`、帧率，未知项省略）。可播放的定义：源文件存在，且扩展名在 `canInlinePlay` 白名单（`mp4`、`mov`、`m4v`、`webm`，即 WKWebView 能播的容器）。可播放时封面是 `button.poster`（`aria-label="播放“{标题}”"`），点击、Enter 或 Space 时才创建 `<video src controls playsinline>` 原地替换它，并调用 `play()`，焦点移到 `<video>`。按住方向键掠过时不加载任何视频数据（AC-M20-02），也保住原型的封面卡片和“悬停时播放钮放大”。不可播放时封面是 `div.poster`，没有播放钮：源文件缺失时提示“原文件已移动或删除”，格式不在白名单时提示“无法在预览中播放这个格式”。编码不受支持（如旧系统上的 AV1）由 `<video>` 的 `error` 事件兜底，整张卡片按不可播放重绘。面板隐藏时，先暂停全部 `<video>`，再清空正文。源文件经 `get_record` 单独授权（8.3）。`get_record` 发现视频没有时长（摘要 `durationSec` 为 null，即阶段 7 之前采集、或去重命中走 `Merged` 而从未补全）且源文件存在时，向补全线程补发一次 `Job::Video`。进程内的 `BACKFILLED` 集合保证每个 id 每次运行只补一次，读不出元数据的 `mkv` 不会每次选中都重新排队 |
| 文件 | 文件图标沿用原型的类型图标，不读取系统图标。“在访达 / 资源管理器中显示”调用 `reveal_file`（文案由 `labels.ts` 的 `openLabel` 给出，与右键菜单同一处） |

### 9.6 其他

- **平台判断**：使用 `bootstrap()` 返回的 `platform.os`，替换原型中的 `navigator.platform`。
- **外观**：默认暗色，`index.html` 的根元素先带 `data-theme="dark"`，bootstrap 前的首帧即为暗色；bootstrap 按 `settings.appearance` 改写，跟随系统时删去 `data-theme`，由 `prefers-color-scheme` 决定（AC-M16-01）。设置变化时，Rust 端同时调用 `window.set_theme()`，使系统材质的深浅与主题一致（启动时 setup 也调用一次）。阶段 9 起设置对话框里的外观**点选即生效并保存**（规格说明 M15），不受“保存设置 / 取消”约束，没有预览、关闭还原和圆形扩散：`applyAppearance(mode)` 先把 `S.settings.appearance` 改成新值（保存途中 `persistUi` 落盘或点“保存设置”带上的都是新外观），再 `setTheme(mode)`（设 `data-theme-switching` → 设 / 删 `data-theme` → 两帧后去掉 `data-theme-switching`，切换期间不按各元素的过渡渐变），然后经 `themeSave` 串行链调用 `save_settings`：上一次保存结束后才发下一次，发的是那一刻最新的 `S.settings`，异步命令不会乱序落盘。`savedAppearance` 记最近一次确认落盘的外观（bootstrap 时取设置）；保存失败且期间没再点别的模式时回到它，并提示“外观未能保存”。←/→ 切换同样即时保存，按住时的重复按键（`e.repeat`）不切换、不保存。不经 `persistUi`：外观是显式动作，用户期望立刻落地。窗口主题（与系统材质的明暗）在 `save_settings` 落库后才切换，比页面晚一次 IPC 往返；切到“跟随系统”而系统配色与之前的显式主题不同时，页面先按旧的 `prefers-color-scheme` 显示，窗口主题切过去后再由 matchMedia 监听整体翻转一次。
- **界面记忆**（`persistUi(patch)`，阶段 9 由 `persistFilter` 抽出）：patch 合并进待写对象，300 ms 防抖；到点时每个键都等于 `S.settings` 的当前值就不写，否则 `save_settings({ ...S.settings, ...patch })`，成功后只把 patch 合并进 `S.settings`（不回滚同时进行的设置保存），失败只记 `保存界面状态失败 kind=…`。分类（`lastFilter`：分类标签、`Mod + ←/→`、空状态的“清除搜索与筛选”、点光柱时被筛掉而切到“全部”）与频谱收起（`spectrumCollapsed`，9.7）走它。
- **相对时间**：每分钟刷新一次（重建分组，跨午夜时分组标题随之更新），只在面板可见时运行。`rel()` 的口径与分组一致：45 秒内“刚刚”；60 分钟内按分钟；与当前同一本地日历日时按小时（截断，最小 1）；否则按两者本地零点之差的天数。格式化用 `Intl.RelativeTimeFormat('zh-CN', { numeric: 'auto' })`，输出“2分钟前”“3小时前”“昨天”“前天”“5天前”（中文没有空格）。
- **删除与撤销**：5 秒后 `Mod + Z` 不处理，也不提示；“已无法恢复”只在后端 `undo_delete` 返回 false 时显示（前后端计时在 5 秒边界上有出入）。阶段 9 起非撤销提示不再清 `S.undo`：`S.undo` 只在撤销、新的删除替换它、或别处删掉了待撤销记录时改变；所有读取方（`undo()`、`Mod + Z` 的 keymap 上下文、状态栏 `#undoHint`）都按 `canUndo(S.undo, now)`（`view.ts`，比较 `expiresAt`）判断是否还在 5 秒内。提示条被其他提示顶掉后，撤销按钮不再回来，靠状态栏 `Mod + Z 撤销` 保持可发现。别处删掉了待撤销记录时（`records-removed`），只有提示条仍显示撤销按钮才收起提示条。
- **提示条操作按钮**：提示条可带一个操作按钮（如“前往授权”），样式同撤销按钮，展示 5 秒；与撤销按钮不同时出现。
- **动作文案按能力显示**（阶段 9，`labels.ts`）：`paintVerb()` 设 `S.canPaste`（macOS 取 `accessibility_granted()`，出错按 false；Windows 恒真），把 `copyVerb(canPaste)`（粘贴 / 复制）写进所有 `[data-verb]`（预览 `#copyBtn`、菜单项、状态栏“快速粘贴 / 快速复制”用 `data-verb="快速"` 前缀）与已渲染行快捷按钮的 `title`。bootstrap 设好修饰键之后调用一次，之后每次 `shown()` 开头刷新，引导检测到授权时也刷新。状态栏 `#escHint` 在 `runSearch` 里与清除按钮一起按 `escHint(hasQuery)` 更新（清空搜索 / 隐藏）；`#undoHint` 由 `paintUndoHint()` 按 `canUndo` 显示，删除时另起一个 `UNDO_MS` 定时器到期再刷新。
- **右键菜单按类型的动作**（阶段 9）：`#menu` 在“置顶”之后有一个默认隐藏的 `data-m="open"` 项。`openMenu` 按 `openLabel(kind, hasFile, os)` 设置文字与 `hidden`（链接为“在浏览器中打开”；文件、视频、来自文件的图片为“在访达中显示 / 在资源管理器中显示”；其余为 null 即隐藏），再给可见项重排 `--i`，之后才量尺寸定位，所以 stagger 不空拍、展开原点按最终高度计算。摘要没有文件信息，只有图片要知道是否来自文件：详情缓存命中就同步打开，否则先 `get_record`，返回时面板已隐藏、选中已换、菜单已开或记录已不在就不开。点击时先关菜单，再取详情：链接 → `open_url(text)`，否则 → `reveal_file(files[0].path)`；`fileMissing` 提示“原文件已移动或删除”。方向键只在可见项之间移动。复用已有命令，没有新命令和快捷键。
- **设置里的清空历史**（阶段 9）：`#clearBtn` 调用与托盘相同的 `confirmClear()`，确认框叠在设置上方，设置不关闭；`confirmClear()` 返回结果文案（取消为 null），写进该行的 `#clearNote`（`aria-live=polite`），因为提示条在模态对话框下面看不到；每次打开设置复位为“置顶记录会保留”。
- **面板打开时的外部新记录**：按第 2 节回写项 2，只插入列表并播放进入动效，不改搜索、分类、选中项，不弹提示条；搜索框有内容时重新取匹配集合。
- **减少动态效果**：WKWebView 读取 macOS 的“减弱动态效果”，WebView2 读取 Windows 的“显示动画效果”，两者都会反映到 `prefers-reduced-motion`，前端不需要额外处理。阶段 1 在两端各验证一次。
- **首次打开面板动效**（720 ms 编排动画）：只在应用启动后第一次显示面板时播放，之后唤起使用 90 ms 的快速出现。动画期间输入框已经可用。
- **对话框**：设置、确认、引导三个 `<dialog>` 共用一套弹入（`showModal` → 强制重排 → `is-shown`）、150 ms 收起（减少动态效果时为 0）、遮罩与逐行 `rowIn` 规则。对话框打开时面板快捷键全部不响应（`KeyCtx.dialogOpen`），Esc 只关最上层对话框；面板隐藏时直接关闭全部对话框。设置与确认框的开关经 `set_dialog_open` 同步给后端，打开期间失焦与唤起快捷键不隐藏面板（7.2）；设置里“前往授权”成功后前端主动 `hide()`。设置对话框头尾固定、中间滚动（面板高 640、最矮 520，放不下全部设置项；原型在整页里没有这个问题），点遮罩关闭要求按下和松开都在遮罩上。确认对话框（`confirm()`）打开时焦点在取消上；同时只允许一个，已有一个在等结果时新的调用直接得到 false。
- **首次引导**（M18）：面板内的模态对话框 `#onboard`：试按快捷键 → 辅助功能授权（仅 macOS，可跳过）→ 开机启动勾选 → 完成（macOS 3 步，Windows 2 步）。引导期间按快捷键不隐藏面板，而是让“试按一次”这一步显示成功状态（`hotkey-pressed`，见 7.2）。授权步骤每秒查一次 `accessibility_granted()`。右上角 × 与 Esc 等同完成；点遮罩不响应。引导期间面板失焦隐藏会关闭对话框，但不算结束：下次 `panel-shown` 时从同一步重新打开。完成时先 `save_settings`（开机启动开关）再 `finish_onboarding`，两者失败只记日志，对话框照常关闭。
- **开发者工具**：`tauri.conf.json` 不开 `devtools`；开发构建里 Tauri 默认允许右键打开，发布构建自动关闭。

### 9.7 复制频谱（M14）

纯函数在 `src/spectrum.ts`（配 `spectrum.test.ts`），`main.ts` 只负责 DOM。

- **位置与高度**：`xPct(age)` 超过 7 天时返回 null，不画光柱；1–7 天压在左侧“更早”区的 1–5%；24 h 内映射到 6–99.4%。`hPct(size)` 按字节数取对数，范围 16%–100%。
- **按 2 px 列合并**：轨道按 `COL_PX = 2` 分列，列数为 `max(1, floor(轨道宽 / 2))`，每列一根光柱（5000 条、900 px 时最多 450 根）。3 px 宽的光柱在 2 px 内本来就互相重叠，合并后看起来没有区别（规格说明 M14 规则 3 的补充句）。删除动画进行中的记录（`S.removing`）不参与布局，否则重绘会把正在收起的光柱拉回来。
- **代表记录**：每列取一条，决定光柱的颜色、高度、悬停提示与点击目标。优先级依次为：匹配当前筛选 > 新记录（`freshId`）> 高度更高 > 复制时间更新 > id 更大。匹配优先，是为了避免“代码”分类下出现一根亮着却是文本色的光柱。
- **变暗按列**：列内没有一条匹配当前分类或搜索时，整列加 `.dim`；列内含新记录时加 `.fresh`。
- **选中**：`colOf` 记录 id 到列下标的映射。`paintSpectrumSel` 只摘掉上一根的 `.on`、给选中记录所在的列加 `.on`，不遍历光柱。游标按选中记录自己的复制时间定位，不用所在列代表记录的；选中记录没有光柱（超过 7 天）时隐藏游标。
- **升起错位**：首次打开时 `barIn` 的间隔仍为 18 ms，但用 `--i = staggerIndex(i, n)` 控制步数：不超过 21 根时逐根错开，超过时压到 0–20 步，总时长不超过 220 + 20 × 18 + 620 ms。原型只有约 20 根光柱，照搬到 450 根会让升起拖到 8 秒，违背 M20 第 1 行的 720 ms。
- **统计**：`spectrumStat` 统计 24 h 内的条数，并分 24 个本地小时桶；最大值大于 1 时才给出“最忙 H 点”，并列时取数值较小的小时。
- **重绘时机**：以下情况调用 `renderSpectrum()`：
  - 启动时。
  - 切分类（`setFilter`）：在 `renderList` 之前重绘，选中项的游标滑动不会被打断。
  - 搜索结果返回：在 `runSearch` 回调写入匹配集合之后。
  - 新记录（`record-added`）：带 `freshId`，播放升起与 ping。
  - 去重命中（`record-updated`）：复制时间变了才带 `freshId`。
  - 记录移除：`records-removed` 时，以及删除动画结束（360 ms）后。
  - 窗口尺寸变化：用 rAF 合并。
  - 面板可见时每分钟一次（有删除进行中时跳过）。
  - `shown()`：经 `runSearch('')` 同步重绘一次，再用 `paintSpectrumSel(false)` 让游标直接落位。
- **原地更新**：新旧布局列数相同、且每列的 ids 相同（`sameColumns`）时，只改已有 `<span>` 的类名、类型、位置与高度，`.dim` / `.on` 的 200 ms 过渡照常播放。否则整段用 `innerHTML` 重建，并隐藏悬停提示。
- **收起 / 展开**（阶段 9，规格说明 M14 规则 9）：`#spectrum[data-collapsed]` 是唯一真值，bootstrap 时由 `settings.spectrumCollapsed` 初始化。不读 `S.settings`：`persistUi` 要等 300 ms 防抖且保存成功后才写回 `S.settings`，读它渲染会滞后；点击时先改 `S.settings` 又会让 `persistUi` 的“值没变就不写”跳过保存。点标题行 `.sp-head` 或其中的 `#spToggle`（同一个监听，按钮的点击冒泡上来；挂在 bootstrap 之后，免得用空设置去合并保存）：写 `data-collapsed`、`aria-expanded` 与 `aria-label`（收起复制频谱 / 展开复制频谱），`persistUi({ spectrumCollapsed })`。收起时 `.sp-track`、`.sp-axis` 为 `display: none`，`renderSpectrum` 先更新 `#spStat` 再提前返回（统计照常更新，新记录不播光柱动画），`paintSpectrumSel` 直接返回。展开时先 `replaceChildren()` 清空光柱再同步 `renderSpectrum()`：子节点数与新布局不同，于是整组重建，新光柱直接带最终的 `.dim` / `.on`，不会在显示时播 200 ms 过渡；不用 rAF，去掉 `display: none` 后读 `clientWidth` 已是真实宽度。高度即时切换（M20 原则 4），只有箭头 `transform 140ms enter` 旋转 180°。

## 11. 隐私与安全

- **CSP**：在现有基础上增加 asset 协议：
  `img-src 'self' data: blob: asset: http://asset.localhost; media-src asset: http://asset.localhost`。不允许任何外部来源。
- **asset 协议范围**：静态范围只包含 `$DATA/xPaste/images/**`、`$DATA/xPaste/thumbs/**`、`$DATA/xPaste/icons/**`（数据库、`blobs/` 和日志不开放）。视频源文件和图片源文件在预览时按单个文件动态授权（9.5），不把整个磁盘开放给 WebView。
- **不联网**：前后端都没有网络请求，链接标题只从剪切板读取。验收时断网运行全部用例，并用抓包工具确认（AC-M08-06、AC-M16-04）。
- **capabilities**：
  - `default.json`：窗口 `panel`；权限 `core:default`、`core:window:allow-start-dragging`（标题栏拖动）、`opener:allow-open-url`、`opener:allow-reveal-item-in-dir`、`log:default`。
  - `macos.json`：`"platforms": ["macOS"]`，目前为空壳，macOS 专有权限出现时放这里。
  - 应用自己的命令通过 `invoke_handler` 注册，Tauri 2 默认允许应用命令，不需要额外权限声明。前端用不到的插件权限不开。

## 15. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| `tauri-nspanel` 跟不上 Tauri 升级 | macOS 面板无法使用 | 锁定 commit；它的核心是把窗口类替换为 NSPanel 子类并设置样式，必要时在 `xpaste-platform` 里用 objc2 自行实现（约 100 行） |
| 隐藏状态下 WKWebView 暂停脚本 | 唤起后列表不是最新数据 | 见 8.4，改为唤起时重新拉取数据 |
| 读取全部格式会触发源应用的延迟渲染（Windows 上 Excel 等应用会当场生成大量格式） | 复制大表格时卡顿，记录体积大 | 单个格式 50 MB 上限（第 6 节）；如果仍有明显卡顿，改为只读取白名单格式（文本、HTML、RTF、PNG、DIB、文件引用和敏感标记） |
| macOS 新版本的剪切板隐私提示（Q8） | 后台监听可能弹窗，或读取不到内容 | 阶段 1 验证；最坏情况下在引导中说明并引导用户授权 |
| 非 QWERTY 键盘布局下模拟粘贴的按键不对 | 粘贴失败 | 见第 6 节的 ponytail 注释 |
| Windows 前台窗口锁定（`SetForegroundWindow` 被系统拒绝） | 焦点没有回到原应用，粘贴到了错误的位置 | 等待前台窗口确认后才发送按键（第 6 节）；超时则返回 `CopiedOnly` 并提示手动粘贴 |
| 手写的 TS 类型与 Rust 结构体不同步 | 运行时字段缺失 | 类型集中在一个文件；`cargo test` 里加一个用例，把每个结构体的示例值序列化成 JSON 写到 `src/api/fixtures/`，前端测试读取它们做类型检查 |

## 附录：v0.2 审查记录

按 Tauri 2 的项目组织方式重新审查 v0.1，改动如下。每条写明依据，方便以后再审。

| # | v0.1 的做法 | v0.2 的做法 | 依据 |
| --- | --- | --- | --- |
| 1 | 核心层、平台层是 `src-tauri/src/` 下的模块 | 独立 crate `crates/xpaste-core`、`crates/xpaste-platform`，Cargo 工作区 | ADR-001 约定 3 要求核心不依赖 Tauri；模块级约定靠自觉，crate 级约定靠编译器。Tauri 官方项目结构只约束 `src-tauri/` 内部，工作区不受影响 |
| 2 | 命令没有说明同步还是异步 | 全部 `#[tauri::command(async)]` | Tauri 把不带 `async` 的命令放在主线程执行，SQLite 查询会阻塞界面 |
| 3 | `Mutex<Connection>` 位置不明 | 托管状态 `AppState`，`State<'_, AppState>` 注入 | Tauri 的状态管理方式，避免全局变量，方便 `mock_builder` 测试 |
| 4 | 命令错误类型未定义 | `AppError`（thiserror + Serialize），统一 `{kind, message}` | Tauri 文档的错误处理方式；提示条文案只写一处 |
| 5 | `macOSPrivateApi`、bundle targets、nsis installMode 混在 `tauri.conf.json` | 拆到 `tauri.macos.conf.json`、`tauri.windows.conf.json` | Tauri 支持按平台的配置文件自动合并，共用配置不再带平台分支 |
| 6 | 一个 `capabilities/default.json` | `default.json` + `macos.json`（`platforms` 字段） | 平台专有权限不泄漏到另一端 |
| 7 | 不引入日志库，用 `eprintln!` | `tauri-plugin-log` + `log` | 官方插件，发布构建有可查的文件日志；内容不入日志的规则不变 |
| 8 | 快捷键被占用时用托盘菜单项变通，偏离规格说明 | `tauri-plugin-notification` 发系统通知 | 用官方插件就能满足规格说明 5.3.2，不必偏离 |
| 9 | `commands.rs` 单文件 | `commands/` 按领域分文件，`generate_handler!` 只出现一次 | 命令会增加到二十个以上，单文件难维护 |
| 10 | 前端 `api.ts` 单文件 | `src/api/` 目录：commands、events、types | 事件名和类型分开维护；`@tauri-apps/*` 只在这个目录出现 |
| 11 | 没有 CI | GitHub Actions 两端矩阵 | 开发机只有 macOS，Windows 编译问题要尽早暴露 |
| 12 | 版本号散在三处 | `package.json` 为唯一来源，`tauri.conf.json` 引用它，CI 检查 Cargo 版本一致 | Tauri 配置支持 `version` 指向 package.json |
| 13 | 没有评估官方插件 | 新增 3.3 节说明为什么不用 clipboard-manager、sql、store、window-state、positioner | 以后有人问起时有答案，也避免重复评估 |
| 14 | 未提及 tauri-specta | 明确不引入（仍是 rc），类型手写集中在一处，并加 fixtures 测试防止漂移 | 见第 4 节 |
