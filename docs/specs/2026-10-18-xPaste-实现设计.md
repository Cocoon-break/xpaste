## 1. 范围

**本期实现**：规格说明中全部 P0 和 P1 功能，macOS 与 Windows 两端。

**本期不实现**：

- 全部 P2：面板边框光晕、验证码内容识别、`rgb()` / `hsl()` 颜色识别、拼音搜索、Windows ARM64。例外是主题切换的圆形扩散（P2）：原型里已经写好，迁移时直接保留，不额外投入。
- 数据库加密（Q7）：本期不做，留到下一个迭代，见第 2 节。
- 自动更新（Q6）：本期不做，托盘菜单不放“检查更新…”。应用因此不发起任何网络请求。
- 规格说明第 8 章“本期不做”的全部内容。

## 2. 待确认问题的实现取值

规格说明第 7 章的问题还没有定论。为了不阻塞开发，先按下表实现。每一项都改动很小，结论有变化时再调整。

| 问题 | 本期实现 | 改动成本 |
| --- | --- | --- |
| Q1 Enter 的行为 | 复制并自动粘贴到上一个应用；无法粘贴时降级为只复制并提示。不提供“只复制”开关 | 加开关只改设置和 `copy` 命令的一个参数 |
| Q2 默认快捷键 | 保持规格说明的默认值 `⌘ ⇧ V` / `Ctrl + Shift + V`，可在设置中修改 | 改一个常量 |
| Q3 外部重复复制是否计入使用次数 | 计入 | 去掉一行 `uses + 1` |
| Q4 一次复制多个文件 | 一条记录；预览列出全部文件 | — |
| Q5 唤起时保留什么 | 保留分类，清空搜索词，选中第一条 | — |
| Q6 自动更新 | 本期不做 | 后续接入官方 `tauri-plugin-updater` |
| Q7 数据库加密 | 本期不做 | 数据库访问集中在 `xpaste-core::store`，后续可换成 SQLCipher |
| Q8 macOS 剪切板隐私提示 | 阶段 1 技术验证时测量，结论写回 ADR-001 和规格说明 M18 | — |
| Q9 验证码识别 | 不做（P2） | — |

**发现的规格说明问题，需要回写**：

1. **使用次数从几开始算**：AC-M11-01（通过 xPaste 复制 3 次进入常用）和 AC-M11-02（外部复制同一内容 3 次进入常用）不能同时成立。本期取值：**首次复制生成记录时使用次数为 0，之后每次重复使用 +1**，与原型数据一致。按这个取值，AC-M11-02 应改为“复制 4 次”，或者改用“首次复制记为 1”的口径。
2. **新记录在面板打开时进入**：原型的“模拟一次复制”会清空搜索、切换到“全部”并选中新记录，这是演示用的行为。正式版里，面板打开时外部产生的新记录只按 M20 的“新记录进入”动效插入列表，**不改变搜索、分类和选中项，也不弹提示条**。
3. **macOS 开机启动**：规格说明 M15 写的是 SMAppService。本期使用官方 autostart 插件的 LaunchAgent 方式，两端只维护一套代码。用户看到的效果相同，系统设置的“登录项”里都会显示 xPaste。如果验收时发现显示名称或系统提示不符合要求，再改用 SMAppService（约 20 行代码）。
4. **macOS 卸载时询问是否删除数据（5.2.4）**：`.dmg` 拖入废纸篓的卸载方式无法弹出询问，macOS 上做不到。Windows 使用 Tauri NSIS 卸载程序自带的“删除应用数据”勾选框。
5. **大文本预览**：超过 200 KB 只显示前 200 KB，新增一句提示文案“仅显示前 200 KB，复制时为完整内容”，需要补进规格说明附录。

## 3. 总体架构

### 3.1 分层

```
┌─ 前端（WebView，常驻、隐藏时不销毁）────────────────────────────────────────────┐
│  src/main.ts 等        键盘、状态、渲染（由原型迁移）                             │
│  src/api/              唯一引用 @tauri-apps/* 的目录：命令封装、事件封装、类型     │
└──────────────────────────────▲──────────────────────┬───────────────────────────┘
                               │ 事件                  │ 命令
┌─ 应用层 src-tauri/（依赖 tauri，是唯一依赖 tauri 的 crate）────▼───────────────────┐
│  lib.rs 组装 Builder   commands/ 命令   panel.rs 面板窗口   tray.rs 托盘            │
│  clipboard.rs 监听接线   enrich.rs 补全线程   housekeeping.rs 定时清理               │
│  error.rs 错误类型   state.rs 托管状态                                               │
├─ 核心层 crates/xpaste-core/（不依赖 tauri，不依赖系统接口，任何平台都能 cargo test）──┤
│  model.rs 类型   detect.rs 类型识别   capture.rs 快照 → 记录   store.rs SQLite      │
├─ 平台层 crates/xpaste-platform/（不依赖 tauri；按 #[cfg(target_os)] 编译不同实现）───┤
│  macos.rs   objc2 系列                  windows.rs   windows 库                     │
└──────────────────────────────────────────────────────────────────────────────────┘
```

把核心层和平台层拆成独立的 crate，而不是 `src-tauri/src/` 下的模块，目的是让编译器替我们执行 ADR-001 第 3 条约定（“核心逻辑不依赖 Tauri”）：这两个 crate 的 `Cargo.toml` 里没有 `tauri`，谁想在里面调 Tauri 都编译不过。Tauri 官方的项目结构只规定了 `src-tauri/` 内部的布局，对外层用 Cargo 工作区没有限制；Tauri CLI 通过 `tauri.conf.json` 定位应用 crate，工作区放在仓库根目录即可。

### 3.2 线程

| 线程 | 职责 | 所在层 |
| --- | --- | --- |
| 主线程 | Tauri 事件循环、窗口、托盘、全局快捷键。macOS 上所有 AppKit 调用（NSPanel、模拟粘贴前的窗口操作）必须在这里执行 | 应用层 |
| 监听线程 | macOS：每 300 ms 读一次 `changeCount`；Windows：一个隐藏的消息窗口接收 `WM_CLIPBOARDUPDATE`。检测到变化后读取快照，调用 `xpaste_core::capture::process` 写库，再通过 `AppHandle::emit` 通知前端 | 平台层提供监听，应用层 `clipboard.rs` 接线 |
| 补全线程 | 生成图片缩略图、视频封面和元数据、来源应用图标。完成后更新记录，发出 `record-updated`。一个线程加 `std::sync::mpsc` 队列 | 应用层 `enrich.rs`（`clipboard.rs` 投递任务） |
| 命令 | 所有访问数据库或剪切板的命令都声明为 `#[tauri::command(async)]`（或 `async fn`），由 Tauri 的异步运行时在工作线程上执行。**不加 `async` 的命令在主线程上执行**，一次几十毫秒的 SQLite 查询就会让界面掉帧 | 应用层 |
| 定时任务 | 每小时清理一次过期记录；软删除 5 秒后彻底删除。`housekeeping.rs` 用 `std::thread` 加 `thread::sleep`：一个常驻线程负责每小时清理，每次软删除起一个短命线程 | 应用层 |

数据库连接只有一个，封装在 `Store` 里，放在托管状态 `AppState` 的 `Mutex<Store>` 里（`std::sync::Mutex`，锁内没有 `await`），通过 `tauri::State<'_, AppState>` 注入到命令，不用全局变量。
`// ponytail: 单连接全局锁；如果补全线程写库与面板读取出现可感知的等待，再拆成读写两个连接（WAL 模式支持）`

### 3.3 为什么不用这些官方插件

| 插件 | 原因 |
| --- | --- |
| `tauri-plugin-clipboard-manager` | 只能读写文本、HTML 和图片，没有变化监听、读不到全部原始格式和敏感标记，满足不了 M01 |
| `tauri-plugin-sql` | 面向前端直接写 SQL 的场景；我们的数据逻辑都在 Rust 里，用 rusqlite 直接访问更简单，也方便测试 |
| `tauri-plugin-store` | 设置和历史放在同一个 SQLite 里，一处备份、一个事务；不值得再引入一个 JSON 文件 |
| `tauri-plugin-window-state` | 它会连同位置一起恢复，与“面板出现在鼠标所在显示器”冲突；尺寸记忆自己写只有十几行 |
| `tauri-plugin-positioner` | 面向托盘旁定位，我们按鼠标所在显示器定位 |

## 5. 核心层（`crates/xpaste-core`）

### 5.1 数据模型

```sql
PRAGMA journal_mode = WAL;      -- 进程被强制结束时已提交的事务不丢（AC-M03-04）
PRAGMA synchronous = NORMAL;
PRAGMA foreign_keys = ON;
-- 表结构版本记在 PRAGMA user_version，启动时按版本号依次执行迁移

CREATE TABLE records (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,  -- id 不复用：已删除记录的 id 不会分给新记录
  hash        BLOB    NOT NULL UNIQUE,   -- 去重哈希，见 5.4
  kind        TEXT    NOT NULL,          -- text | link | code | color | image | video | file
  title       TEXT    NOT NULL,          -- 列表标题，按 M07 规则 3 在采集时算好
  text        TEXT,                      -- 纯文本内容（文本、链接、代码、颜色）
  paths       TEXT,                      -- JSON 数组：文件引用的路径（图片文件、视频、文件）
  link_title  TEXT,                      -- 链接的页面标题，只来自剪切板数据
  lang        TEXT,                      -- 代码语言：JavaScript | Shell | SQL | …，识别不出为 NULL
  size        INTEGER NOT NULL,          -- 字节数，见 5.3
  meta        TEXT,                      -- JSON：图片宽高；视频时长、宽高、帧率、编码
  search_text TEXT    NOT NULL,          -- 小写后的“内容 + 链接标题 + 文件名与路径 + 来源应用名”
  app_id      TEXT REFERENCES apps(id),  -- 来源应用；NULL 表示“未知来源”
  copied_at   INTEGER NOT NULL,          -- 毫秒时间戳，决定排序和分组
  uses        INTEGER NOT NULL DEFAULT 0,
  pinned      INTEGER NOT NULL DEFAULT 0,
  deleted_at  INTEGER                    -- 软删除时间，非 NULL 的记录不对前端返回
);
CREATE INDEX records_copied_at ON records(copied_at);

-- 剪切板原始格式，粘贴时原样写回（M01 规则 2、10）
CREATE TABLE flavors (
  record_id INTEGER NOT NULL REFERENCES records(id) ON DELETE CASCADE,
  item      INTEGER NOT NULL CHECK (item < 65536),   -- macOS 的 NSPasteboardItem 序号；Windows 固定为 0
  format    TEXT    NOT NULL,   -- macOS 为 UTI；Windows 为格式名（标准格式用 "CF_UNICODETEXT" 这类名字）
  data      BLOB,               -- ≤ 1 MB 时直接存库
  file      TEXT,               -- > 1 MB 时存为 blobs/<record_id>/<序号>，这里记相对路径
  PRIMARY KEY (record_id, item, format)
);

CREATE TABLE apps (
  id   TEXT PRIMARY KEY,        -- macOS bundle ID；Windows 可执行文件完整路径
  name TEXT NOT NULL,
  icon_path TEXT                -- 图标 PNG 的绝对路径（icons/<哈希>.png），由补全线程填入。存为文件而不是 BLOB，供 asset 协议读取
);

CREATE TABLE kv (key TEXT PRIMARY KEY, value TEXT NOT NULL);  -- 设置（JSON）、是否完成首次引导等
```

`store.rs` 只接收一个数据目录路径，不知道这个路径怎么来的。应用层用 Tauri 的 `path().data_dir()`（macOS 为 `~/Library/Application Support`，Windows 为 `%APPDATA%`）拼上 `xPaste/` 后传进来。不要用 `app_data_dir()`，它会按应用标识生成 `com.xpaste.app` 目录名，与规格说明 M03 不符。

```
xPaste/
  xpaste.db (+ -wal, -shm)
  blobs/<record_id>/…        大于 1 MB 的原始格式数据
  images/<record_id>.png     位图记录的 PNG（预览用）
  thumbs/<record_id>.png     图片缩略图和视频封面，长边 320 px
  icons/<哈希>.png           来源应用图标，文件名为应用 id 的 SHA-256 前 16 字节（32 位小写 hex）
  logs/                      tauri-plugin-log 的日志文件
```

删除记录时，同时删除它在 `blobs/`、`images/`、`thumbs/` 下的文件。

### 5.2 采集流程（`capture.rs`）

平台层把剪切板读成一个与平台无关的快照（类型定义在 `model.rs`）：

```rust
pub struct Snapshot {
    pub flavors: Vec<Flavor>,         // (item, format, data)
    pub text: Option<String>,         // 纯文本，换行统一为 \n
    pub html: Option<String>,
    pub file_paths: Vec<PathBuf>,
    pub bitmap: Option<Vec<u8>>,      // PNG 字节；macOS 的 TIFF、Windows 的 DIB 在平台层转换
    pub url_title: Option<String>,    // 见 5.3
    pub sensitive: bool,              // 平台层已检测到敏感标记（开关关闭时内容照常读出，仍为 true）
    pub source: Option<AppInfo>,      // id、name
}
```

`capture::process(snapshot, &settings, paused, &mut store, now_ms) -> Result<Outcome, CoreError>`，`Outcome` 为 `Skipped(原因)`、`Added(id, removed)` 或 `Merged(id, removed)`（`removed` 为容量清理删除的 id）。依次执行，任何一步返回“跳过”就结束：

1. 已暂停 → 跳过（M01 规则 8）。
2. `sensitive && settings.skip_sensitive` → 跳过（规则 6）。平台层 `read_snapshot(skip_sensitive)` 在开关开启时遇到敏感标记只返回标记、不读内容；开关关闭时照常读出内容并保留 `sensitive = true`，这一步放行，按普通内容入库（AC-M01-08）。
3. 来源应用在忽略列表中 → 跳过（规则 7）。忽略列表按应用名称匹配（`capture::is_ignored_app`：去首尾空白、不区分大小写）。P0 阶段设置里是逗号分隔的文本，这样匹配最直接。

第 1、3 步在监听回调里先做一次：已暂停，或 `frontmost_app()` 的名称命中忽略列表时，**不读取剪切板**直接跳过；`process` 里保留同样的检查兜底。
4. 超过大小上限 → 跳过（规则 9）：纯文本超过 5 MB，或位图超过 50 MB。
5. 快照里既没有文本，也没有文件和位图 → 跳过。例如只包含私有格式的复制，没有可以展示的内容。
6. 用 `detect::kind()` 判定类型，计算哈希。哈希已存在时更新原记录（5.4）并返回 `Merged`，否则新建记录返回 `Added`。
7. 一个事务内写入 `records`、`flavors` 和 `apps` 的名称；超出“最多保存条数”的部分在同一事务里删除（5.5），被删除的 id 一并返回。

补全任务（位图生成 PNG 和缩略图、视频封面与元数据、来源应用图标）由应用层根据 `Outcome` 放进队列，核心层不管线程。

**自身写入不记录**（规则 5）：平台层写剪切板后返回写入后的序号（macOS 为 `changeCount`，Windows 为 `GetClipboardSequenceNumber()`），应用层记在 `AppState`。监听线程遇到这个序号时直接跳过，不读取剪切板。

### 5.3 字段计算

| 字段 | 规则 |
| --- | --- |
| `title` | 文本：第一个非空行，截断到 200 字符；链接：`link_title`，没有时用 URL；颜色：大写 HEX；图片、视频、文件：第一个文件名，多个文件时为“文件名 等 N 个”；位图：`截图 YYYY-MM-DD HH.mm.png`，按复制时间生成。时间戳目前为 UTC（核心层不引入时区库），前端按 `copiedAt` 本地化显示 |
| `size` | 文本类：纯文本的 UTF-8 字节数；位图：PNG 字节数；文件引用：各文件大小之和（文件夹不递归统计，大小记 0，界面显示“—”） |
| `link_title` | 按顺序取第一个能取到的：macOS 的 `public.url-name`；HTML 内容恰好是一个 `<a href="同一 URL">标题</a>` 时取其中的文字；Windows 的 `UniformResourceLocatorW` 搭配 `FileGroupDescriptorW` 中的文件名（去掉 `.url` 后缀）。都取不到时为 NULL。**不联网**（M08 补充规则 1） |
| `lang` | P1。按顺序判断：以 `$ `、`git `、`npm `、`pnpm ` 开头为 Shell；以 `SELECT`、`INSERT`、`UPDATE`、`WITH` 开头（不区分大小写）为 SQL；包含 `const `、`let `、`function `、`=>`、`import ` 为 JavaScript；其余为 NULL |
| `search_text` | 文本内容、`link_title`、所有文件名和完整路径、来源应用名，用换行连接后整体转小写（Rust `to_lowercase()`） |

### 5.4 类型识别与去重

`detect::kind(&Snapshot) -> Kind` 严格按规格说明 M02 表格的顺序判断。规则 4 只在没有非空白文本时把位图判为图片；Numbers、Pages 等复制单元格或段落时会同时放入文本和渲染图，这时继续按文本规则（颜色、链接、代码、文本）判定，位图仍写入 `images/` 供预览，哈希按文本计算。扩展名列表、代码编辑器名单和正则都写成常量，放在这个文件里。代码前缀（`$ `、`git `、`SELECT` 等）按规格说明原文的大小写精确匹配：不区分大小写会把 “Let me…” 这类普通句子误判为代码。代码编辑器名单按 bundle ID（macOS）和可执行文件名（Windows）匹配：

```
com.microsoft.VSCode  com.todesktop.230313mzl4w4u92(Cursor)  com.jetbrains.*  com.apple.dt.Xcode
com.sublimetext.*  com.apple.Terminal  com.googlecode.iterm2
Code.exe  Cursor.exe  idea64.exe 等 JetBrains *64.exe  sublime_text.exe  WindowsTerminal.exe  powershell.exe  pwsh.exe
```

一次复制多个文件时：全部是视频则为视频，全部是图片则为图片，否则为文件。

**哈希**：对“规范化内容”计算 SHA-256（使用 `sha2` 库，0.11）。不使用标准库的 `DefaultHasher`，因为它的结果在不同 Rust 版本之间不保证一致，而哈希要写入数据库长期使用。

| 类型 | 规范化内容 |
| --- | --- |
| 文件引用（图片文件、视频、文件） | `"files\n"` + 排序后的路径，用 `\n` 连接 |
| 位图（类型为图片，即没有非空白文本） | `"bitmap\n"` + 平台层转换出的 PNG 字节 |
| 其他 | `"text\n"` + 纯文本（换行已统一为 `\n`，不去首尾空白） |

**命中已有记录时**（M01 规则 4）：`uses + 1`；非置顶记录同时把 `copied_at` 更新为当前时间；如果记录处于软删除状态，先恢复。原始格式保留首次的数据，不覆盖。

### 5.5 清理

| 时机 | 动作 |
| --- | --- |
| 启动时 | 彻底删除所有 `deleted_at` 非 NULL 的记录（上次退出前没来得及删除的软删除）；执行一次保留时长清理 |
| 每小时 | 保留时长清理：删除 `copied_at` 早于“现在 − 保留时长”的非置顶记录。保留时长为“永久”时跳过 |
| 每次新建记录 | 非置顶记录数超过“最多保存条数”时，按 `copied_at` 从旧到新删除多出的部分。“最多保存条数”只计非置顶记录，置顶记录不占名额 |
| 保存设置前 | 前端调用 `prune_preview(retention, max)` 获取将被删除的条数（保留时长与最多条数两条规则命中记录的并集，同一条不重复计数）；大于 0 时先弹确认“将删除 N 条记录”，用户确认后才保存（M03 规则 5） |

清理导致记录被删除时，向前端发出 `records-removed` 事件。

### 5.6 删除与撤销

- `delete(id)`：设置 `deleted_at = now`，应用层同时启动一个 5 秒定时器；5 秒后如果 `deleted_at` 仍是这个值，就彻底删除。
- `undo_delete(id)`：把 `deleted_at` 设为 NULL。置顶状态和使用次数都在记录里，恢复后自然保持不变。
- 前端只保留最近一次删除的撤销入口。连续删除多条时，前面几条在各自的 5 秒后彻底删除（AC-M20-03）。

### 5.7 设置

设置以一个 JSON 对象存在 `kv` 表的 `settings` 键下，用 serde 读写，`#[serde(default)]` 让缺少的字段取默认值：

```rust
#[derive(Serialize, Deserialize)]
#[serde(rename_all = "camelCase", default)]
pub struct Settings {
    pub hotkey: String,              // Tauri 快捷键格式，默认 "CommandOrControl+Shift+V"
    pub retention_days: Option<u32>, // 7 | 30 | 90，None 表示永久；默认 Some(30)
    pub max_records: u32,            // 50..=5000，步长 50，默认 500
    pub ignored_apps: Vec<String>,   // 默认值按平台不同，见 M15
    pub skip_sensitive: bool,        // 默认 true
    pub move_to_top: bool,           // 默认 true
    pub launch_at_login: bool,       // 默认 true
    pub appearance: Appearance,      // System | Light | Dark，默认 System
    pub panel_size: (f64, f64),      // 逻辑像素，默认 (960, 640)
    pub last_filter: String,         // 默认 "all"（Q5：保留分类）
}
```

`Settings::validate()` 在核心层实现，`save_settings` 命令调用它。前端用同样的规则先校验一遍，方便即时提示。

## 6. 平台层（`crates/xpaste-platform`）

两个平台的文件对外提供同名、同签名的函数，`lib.rs` 按 `#[cfg(target_os)]` re-export，不定义 trait。

| 函数 | macOS | Windows |
| --- | --- | --- |
| `watch(on_change)` | 监听线程每 300 ms 读一次 `NSPasteboard.generalPasteboard.changeCount`，变化时回调 | 在监听线程创建 message-only 窗口，调用 `AddClipboardFormatListener`，收到 `WM_CLIPBOARDUPDATE` 时回调 |
| `read_snapshot(skip_sensitive) -> Result<Option<Snapshot>>` | 遍历 `pasteboardItems`，读取每个 item 的全部 `types`，但跳过 `com.apple.icns`，且同一 item 已有 `public.png` 时跳过 `public.tiff`（实测访达复制文件 1.3 MB → 57 B，带 PNG + TIFF 的图片 74.9 MB → 924 KB）。出现 `org.nspasteboard.ConcealedType`、`TransientType`、`AutoGeneratedType` 时设置 `sensitive`；`skip_sensitive` 为真时不再读取内容，为假时照常读取。`url_title` 来自 `public.url-name`；文件 URL 经 `filePathURL` 解析（访达给的是 `file:///.file/id=…` 引用 URL）。位图优先取已读的 `public.png`，只有 TIFF 时用 `NSBitmapImageRep` 的 `representationUsingType:.png` 转换 | `OpenClipboard` 失败时每 20 ms 重试，最多 5 次，仍失败就跳过这次变化（规格说明 5.3.1）。用 `EnumClipboardFormats` 枚举全部格式。出现 `ExcludeClipboardContentFromMonitorProcessing`，或 `CanIncludeInClipboardHistory` 的值为 DWORD 0 时，设置 `sensitive`；`skip_sensitive` 为真时不再读取内容，为假时照常读取。`CF_DIB` / `CF_DIBV5` 用 `image` 库转为 PNG |
| `write(&[Flavor]) -> Result<u64>` | `clearContents` 后，按 item 分组写入 `NSPasteboardItem`；返回新的 `changeCount` | `EmptyClipboard` 后，逐个格式调用 `SetClipboardData`；返回 `GetClipboardSequenceNumber()` |
| `write_text(s) -> Result<seq>` | 只写纯文本，用于复制颜色格式 | 同左 |
| `frontmost_app() -> Option<AppInfo>` | `NSWorkspace.frontmostApplication` 的 bundle ID 和本地化名称 | 先取 `GetClipboardOwner` 所属进程，取不到再取 `GetForegroundWindow` 所属进程。用 `QueryFullProcessImageNameW` 得到路径，名称取文件版本信息中的 `FileDescription`，没有时用不带扩展名的文件名 |
| `app_icon(id) -> Option<Vec<u8>>` | `NSWorkspace.iconForFile:`，`CGImageForProposedRect` 取 64×64 pt 档转 PNG（Retina 屏为 128×128 px） | `SHGetFileInfoW` 取图标后转为 PNG |
| `can_paste(target: Option<isize>) -> PasteBlock` | `AXIsProcessTrusted()` 为 false 时返回 `NeedAccessibility` | `target` 为唤起前记录的前台窗口；它所属进程为管理员权限而 xPaste 不是时，返回 `Elevated`。判断方法：`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` 后读 `TokenElevation`；拿不到令牌也按管理员权限处理 |
| `paste()` | 用 `CGEventCreateKeyboardEvent` 发送 ⌘ + V（虚拟键码 `kVK_ANSI_V` = 9） | 先 `SetForegroundWindow(上一个窗口)`，等待 `GetForegroundWindow()` 等于它（最多 100 ms），再用 `SendInput` 发送 Ctrl + V |
| `open_accessibility_settings()` | 打开 `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` | 不需要 |
| `video_meta(path)`（补全线程） | `AVURLAsset` 读取时长、视频轨道的尺寸、帧率和编码；`AVAssetImageGenerator` 取第一帧作为封面 | `IShellItemImageFactory::GetImage` 取封面；`IPropertyStore` 读取 `System.Media.Duration`、`System.Video.FrameWidth` / `FrameHeight` / `FrameRate` / `Compression` |

`kVK_ANSI_V` 是物理按键位置。使用 Dvorak 等非 QWERTY 键盘布局时，这个键位可能不是 V。`// ponytail: 固定键码；有用户反馈时再用 UCKeyTranslate 按当前布局查出 V 的键码`

**Windows 不保存的格式**：基于 GDI 句柄的格式不能按内存块读写，跳过 `CF_BITMAP`、`CF_METAFILEPICT`、`CF_ENHMETAFILE`、`CF_PALETTE`、`CF_DSPBITMAP`、`CF_DSPMETAFILEPICT`、`CF_DSPENHMETAFILE`、`CF_OWNERDISPLAY`。由系统自动合成的 `CF_TEXT`、`CF_OEMTEXT` 也不保存，写回 `CF_UNICODETEXT` 后系统会重新合成。

**单个格式超过 50 MB 时跳过该格式**，不放弃整条记录。它通常是 Office 等应用写入的私有格式，跳过后仍可以按文本或图片粘贴。

## 7. 面板窗口（`src-tauri/src/panel.rs`）

### 7.1 窗口配置

`tauri.conf.json` 中删除模板生成的 `main` 窗口，改为一个 `panel` 窗口，并在启动时预先创建好：

```json
{
  "label": "panel", "url": "index.html",
  "width": 960, "height": 640, "minWidth": 720, "minHeight": 520,
  "visible": false, "decorations": false, "transparent": true,
  "alwaysOnTop": true, "skipTaskbar": true, "resizable": true, "shadow": true
}
```

平台特有项放在平台配置文件里，不和共用配置混在一起：

| 文件 | 内容 |
| --- | --- |
| `tauri.macos.conf.json` | `bundle.targets: ["dmg"]`；`bundle.macOS.minimumSystemVersion: "13.0"` |
| `tauri.windows.conf.json` | `bundle.targets: ["nsis"]`；`bundle.windows.nsis.installMode: "currentUser"`（规格说明 5.5.2，不需要管理员权限） |

`app.macOSPrivateApi: true` 写在共用的 `tauri.conf.json` 里，不放平台文件：tauri-build 会用目标平台合并后的配置校验 Cargo features，放在 macOS 文件里会让 Windows 构建因 `macos-private-api` feature 不匹配而失败。

| 平台 | 启动时的额外处理 |
| --- | --- |
| macOS | 设置 `ActivationPolicy::Accessory`，不显示 Dock 图标（M04 规则 4）。用 `tauri-nspanel` 把窗口转换为 `NSPanel`：样式加 `nonactivatingPanel`，层级设为浮动层级，`collectionBehavior` 设为 `canJoinAllSpaces \| fullScreenAuxiliary`。这样面板能浮在全屏应用之上（AC-M04-02），能接收键盘输入，同时前台应用保持不变，粘贴时不需要切回焦点。`tauri-nspanel` 不在 crates.io 上，用 git 依赖并锁定到具体 commit |
| Windows | `skipTaskbar` 隐藏任务栏按钮。显示前用 `GetForegroundWindow()` 记下上一个窗口，供粘贴使用 |

**毛玻璃材质**（M16 规则 2）使用 `window-vibrancy` 库：

| 平台 | 调用 | 前端 `data-material` |
| --- | --- | --- |
| macOS | `apply_vibrancy(HudWindow, Active, 圆角 16)` | `glass` |
| Windows 11 | `apply_mica`；失败时 `apply_acrylic` | `glass` |
| Windows 10 / 以上都失败 | 不调用 | `opaque` |

前端根据 `data-material` 设置面板背景：为 `glass` 时使用半透明的颜色 token，模糊交给系统材质完成，CSS 里去掉 `backdrop-filter`；为 `opaque` 时使用不透明背景，配色不变（AC-M16-03）。

### 7.2 显示与隐藏

`toggle()` 由全局快捷键、托盘、第二次启动应用（single-instance）调用。

**显示**：

1. 取鼠标位置 `cursor_position()`，在 `available_monitors()` 中找到鼠标所在的显示器。
2. 用设置里的 `panel_size` 设置窗口尺寸；位置水平居中，窗口顶边位于工作区高度的 1/6（窗口中心大约在上三分之一处）。全程用逻辑像素计算，最后按该显示器的缩放比例换算为物理像素。
3. macOS：`panel.show()` 并设为 key window。Windows：`show()` 后 `set_focus()`。
4. 发出 `panel-shown` 事件，前端收到后清空搜索、选中第一条、聚焦搜索框。

**隐藏的触发条件**（M04 规则 3）：快捷键；前端发起的 `hide_panel`（按 Esc、点击最小化或关闭按钮、粘贴完成）；窗口失去焦点（`WindowEvent::Focused(false)`，即点击了面板外部）。

**尺寸记忆**：监听 `WindowEvent::Resized`，用 300 ms 防抖后写入设置。

**唤起耗时测量**（AC-M04-07）：开发构建（`#[cfg(debug_assertions)]`）中，Rust 端在收到快捷键时记录时间戳并放进 `panel-shown` 事件；前端在搜索框获得焦点后的下一帧（`requestAnimationFrame`）计算差值并打印到控制台。这只能测到软件内部耗时，最终验收仍要用高速摄像。

## 8. 前后端接口

### 8.1 错误类型

```rust
// src-tauri/src/error.rs
#[derive(Debug, thiserror::Error)]
pub enum AppError {
    #[error("原文件已移动或删除，无法粘贴")] FileMissing,
    #[error("写入剪切板失败，请重试")]       ClipboardWrite,
    #[error("该快捷键已被其他应用占用，请换一个")] HotkeyTaken,
    #[error(transparent)]                     Core(#[from] xpaste_core::CoreError),
    #[error(transparent)]                     Tauri(#[from] tauri::Error),
}
// 设置校验失败为 Core(CoreError::InvalidSettings(_))，kind 序列化为 "invalidSettings"
// Serialize 为 { "kind": "fileMissing", "message": "…" }，前端按 kind 分支，message 直接用作提示条文案
```

所有命令都返回 `Result<T, AppError>`。规格说明附录里的提示条文案就是 `#[error("…")]` 里的字符串，只写一处。

### 8.2 类型（`src/api/types.ts`，与 `model.rs` 对应）

```ts
type Kind = 'text' | 'link' | 'code' | 'color' | 'image' | 'video' | 'file';

// thumb、app.icon、image.src 在核心层是绝对路径，应用层 assets::summary_dto / detail_dto 转为 asset URL 后再发给前端
interface RecordSummary {          // 列表、频谱、计数用，启动时一次性全部加载
  id: number; kind: Kind; title: string;
  app: { name: string; icon: string | null } | null; // icon 为 asset URL
  copiedAt: number; uses: number; pinned: boolean; size: number;
  lang: string | null; thumb: string | null;   // 图片缩略图 / 视频封面的 asset URL
  durationSec: number | null;      // 视频
}

// 可选字段一律为 `| null`（Rust 的 Option 序列化为 null，字段始终存在）
interface RecordDetail extends RecordSummary {  // 选中某条记录时获取
  text: string | null;             // 超过 200 KB 时截断，并设置 truncated
  truncated: boolean;
  linkTitle: string | null;
  files: { path: string; name: string; ext: string; size: number; exists: boolean }[];
  image: { src: string; w: number; h: number } | null;
  video: { src: string; w: number; h: number; fps: number; codec: string; durationSec: number } | null; // 阶段 2 暂为 unknown
}
```

5000 条摘要大约 1.5 MB，常驻前端内存没有问题。

### 8.4 事件（Rust → 前端，`src/api/events.ts`）

| 事件 | 数据 | 前端处理 |
| --- | --- | --- |
| `record-added` | `RecordSummary` | 插入列表，播放“新记录进入”动效（面板可见时），频谱长出新光柱 |
| `record-updated` | `RecordSummary` | 替换数据：去重命中，或补全线程生成了缩略图 / 图标（图标写入后，对该应用的全部记录各发一次） |

| `paused-changed` | `boolean` | 标题栏徽标 |
| `open-settings` / `confirm-clear` | — | 托盘菜单触发：先唤起面板，再打开对应对话框 |

事件名在 Rust 端和 `events.ts` 各写一份常量，命名用 kebab-case。`events::emit_summary` 只对未软删除的记录发事件（`Store::live_summary`），软删除期间补全完成不会让记录在前端复现。

**风险，需要技术验证**：窗口隐藏时，WKWebView 可能暂停执行脚本，导致事件在隐藏期间不被处理。如果出现这种情况，改为在 `panel-shown` 时调用 `bootstrap()` 重新拉取数据（5000 条的耗时也要测）。

### 8.5 复制与粘贴流程

```
copy(id, paste)
 ├─ 有文件引用且任一文件不存在 → Err(FileMissing)          前端提示，面板不隐藏
 ├─ platform::write(flavors)，记下返回的序号 → 失败时 Err(ClipboardWrite)   前端提示
 ├─ uses + 1；move_to_top 开启且记录未置顶时 copied_at = now；发出 record-updated
 ├─ !paste → Ok(Copied)
 ├─ platform::can_paste(target) 被阻止 → Ok(CopiedOnly)         面板不隐藏，提示“已复制，在目标应用中按 Mod + V 粘贴”
 └─ 隐藏面板 → platform::paste() → Ok(Pasted)
```

`platform::paste()` 在 macOS 上要在主线程执行，命令里用 `app.run_on_main_thread()` 调度。

使用次数首次达到 3 时的“已加入常用”提示，由前端比较 `uses` 前后的值来判断并显示。面板隐藏后提示显示不出来，所以只在面板仍可见时提示（`Copied`、`CopiedOnly`）。

## 9. 前端

### 9.1 迁移方式

原型就是界面的实现，迁移时尽量少改，不重写：

1. 把原型的 `<style>` 整体移到 `src/styles.css`，`<body>` 中的面板部分移到 `index.html`，`<script>` 移到 `src/main.ts`，并补上类型。
2. 删除规格说明第 0 章列出的演示部分：极光与噪点背景、页头的演示按钮、示例数据、“在网页空白处粘贴加入历史”。主题切换控件移到设置对话框。
3. 字体改为本地加载：删除 Google Fonts 的 `<link>`，把 woff2 文件放进 `src/fonts/`，用 `@font-face` 引用（AC-M16-04）。只打包实际使用的字重：Geist 400/500/600、Unbounded 500/700、JetBrains Mono 400/500。
4. 原型直接修改 `S.items` 的地方，改为调用 `src/api/commands.ts` 中的函数，然后用返回值或事件更新本地状态。`main.ts` 不直接 `import '@tauri-apps/api'`。

主题 token、类型颜色、动效曲线、`[data-theme-switching]`、`prefers-reduced-motion` 降级、键盘触发的操作不加动画等规则，都按原型原样保留。

### 9.2 状态

```ts
const S = {
  records: Map<number, RecordSummary>,  // 全部摘要
  filter: string, q: string,
  matchIds: Set<number> | null,         // q 为空时为 null，表示不过滤
  sel: number | null,
  detail: RecordDetail | null,          // 当前选中项的详情
  undo: { id: number, timer: number } | null,
  settings, platform, paused,
};
```

`visible()` 沿用原型的写法：分类过滤 ∩ `matchIds` → 排序 → 分组。分类计数基于 `records` 计算，不受搜索影响（M06 规则 2）。

### 9.3 搜索

- 监听 `input` 事件，跳过 `isComposing` 为 true 的事件（M05 规则 7）；组字结束时由 `compositionend` 再触发一次搜索。
- 每次输入都调用 `search(q)`，不做防抖，因为本地 IPC 加 SQLite 查询远低于 50 ms 的要求。用一个递增的请求序号丢弃过期的返回结果，避免先发后到的结果覆盖新结果。
- 高亮仍沿用原型的 `hl()`，只高亮标题中的匹配部分。

### 9.4 虚拟列表（M07 规则 8）

行高固定为 56 px（原型 `.row-in`），分组标题的高度也固定。先把 `visible()` 的结果展开为“标题 / 行”的扁平数组，并算出每一项的 `top`。滚动时只渲染可视区域上下各多 8 行的元素，用 `transform: translateY(top)` 定位；外层容器的高度设为总高度。

原型中依赖 DOM 的几处对应调整：

| 原型做法 | 虚拟列表中 |
| --- | --- |
| 选中光标用 `r.offsetTop` 取位置 | 从扁平数组取 `top`，行不在 DOM 中时也能定位 |
| `scrollIntoView` | 根据 `top` 直接设置 `scrollTop` |
| 新记录用 `grid-template-rows: 0fr → 1fr` 展开 | 只在新行位于可视区域时播放；可视区域下方的行整体下移 56 px，用 transform 过渡完成 |
| 置顶时用 FLIP 平移 | 起点或终点不在可视区域时直接到位，不播放动画 |
| 列表逐行浮现（间隔 28 ms） | 只对首屏的行执行 |

`aria-activedescendant` 指向的选中行必须已经渲染。选中项总会被滚动到可视区域，所以这一点自然满足。

### 9.5 预览

沿用原型的 `bodyHTML()`，数据改为来自 `S.detail`。切换选中项时先用摘要渲染标题和信息栏，`get_record` 返回后再填充正文，保证按住方向键时预览不会被异步请求拖慢（AC-M20-02）。

| 类型 | 与原型的差异 |
| --- | --- |
| 文本 | 超过 200 KB 只显示前 200 KB，末尾提示“仅显示前 200 KB，复制时为完整内容” |
| 链接 | 点击 URL 调用 `open_url` |
| 代码 | 沿用原型的 `hlCode` 词法高亮 |
| 颜色 | 沿用 `hexInfo` 和对比度计算；格式“复制”按钮调用 `copy_text` |
| 图片 | `src` 指向 `images/<id>.png`（位图）或原文件（文件引用），通过 asset 协议加载 |
| 视频 | P1 内联播放：用 `<video>` 加载原文件。播放前调用 `asset_protocol_scope().allow_file(path)`，只授权这一个文件 |
| 文件 | 文件图标沿用原型的类型图标，不读取系统图标。“在访达 / 资源管理器中显示”调用 `reveal_file` |

### 9.6 其他

- **平台判断**：使用 `bootstrap()` 返回的 `platform.os`，替换原型中的 `navigator.platform`。
- **外观**：设置为跟随系统时，不设置 `data-theme`，由 `prefers-color-scheme` 决定（AC-M16-01）。设置变化时，Rust 端同时调用 `window.set_theme()`，使系统材质的深浅与主题一致。
- **相对时间**：每分钟刷新一次，只在面板可见时运行。
- **减少动态效果**：WKWebView 读取 macOS 的“减弱动态效果”，WebView2 读取 Windows 的“显示动画效果”，两者都会反映到 `prefers-reduced-motion`，前端不需要额外处理。阶段 1 在两端各验证一次。
- **首次打开面板动效**（720 ms 编排动画）：只在应用启动后第一次显示面板时播放，之后唤起使用 90 ms 的快速出现。动画期间输入框已经可用。
- **首次引导**（M18）：面板内的一个分步覆盖层：试按快捷键 → 辅助功能授权（仅 macOS，可跳过）→ 开机启动勾选 → 完成。引导期间按快捷键不隐藏面板，而是让“试按一次”这一步显示成功状态。
- **开发者工具**：`tauri.conf.json` 不开 `devtools`；开发构建里 Tauri 默认允许右键打开，发布构建自动关闭。

## 11. 隐私与安全

- **CSP**：在现有基础上增加 asset 协议：
  `img-src 'self' data: blob: asset: http://asset.localhost; media-src asset: http://asset.localhost`。不允许任何外部来源。
- **asset 协议范围**：静态范围只包含 `$DATA/xPaste/images/**`、`$DATA/xPaste/thumbs/**`、`$DATA/xPaste/icons/**`（数据库、`blobs/` 和日志不开放）。视频源文件和图片源文件在预览时按单个文件动态授权（9.5），不把整个磁盘开放给 WebView。
- **不联网**：前后端都没有网络请求，链接标题只从剪切板读取。验收时断网运行全部用例，并用抓包工具确认（AC-M08-06、AC-M16-04）。
- **capabilities**：
  - `default.json`：窗口 `panel`；权限 `core:default`、`core:window:allow-start-dragging`（标题栏拖动）、`opener:allow-open-url`、`opener:allow-reveal-item-in-dir`、`log:default`。
  - `macos.json`：`"platforms": ["macOS"]`，目前为空壳，macOS 专有权限出现时放这里。
  - 应用自己的命令通过 `invoke_handler` 注册，Tauri 2 默认允许应用命令，不需要额外权限声明。前端用不到的插件权限不开。

| --- | --- | --- |
| `tauri-nspanel` 跟不上 Tauri 升级 | macOS 面板无法使用 | 锁定 commit；它的核心是把窗口类替换为 NSPanel 子类并设置样式，必要时在 `xpaste-platform` 里用 objc2 自行实现（约 100 行） |
| 隐藏状态下 WKWebView 暂停脚本 | 唤起后列表不是最新数据 | 见 8.4，改为唤起时重新拉取数据 |
| 读取全部格式会触发源应用的延迟渲染（Windows 上 Excel 等应用会当场生成大量格式） | 复制大表格时卡顿，记录体积大 | 单个格式 50 MB 上限（第 6 节）；如果仍有明显卡顿，改为只读取白名单格式（文本、HTML、RTF、PNG、DIB、文件引用和敏感标记） |
| macOS 新版本的剪切板隐私提示（Q8） | 后台监听可能弹窗，或读取不到内容 | 阶段 1 验证；最坏情况下在引导中说明并引导用户授权 |
| 非 QWERTY 键盘布局下模拟粘贴的按键不对 | 粘贴失败 | 见第 6 节的 ponytail 注释 |
| Windows 前台窗口锁定（`SetForegroundWindow` 被系统拒绝） | 焦点没有回到原应用，粘贴到了错误的位置 | 等待前台窗口确认后才发送按键（第 6 节）；超时则返回 `CopiedOnly` 并提示手动粘贴 |
| 手写的 TS 类型与 Rust 结构体不同步 | 运行时字段缺失 | 类型集中在一个文件；`cargo test` 里加一个用例，把每个结构体的示例值序列化成 JSON 写到 `src/api/fixtures/`，前端测试读取它们做类型检查 |

## 16. 留给开发者决定的事项

以下细节不影响功能和验收，开发时自行决定，选定后在代码注释或本文中注明：

- 监听线程和补全线程的具体退出方式。
- `image` 库生成缩略图使用的缩放算法。
- 虚拟列表的预渲染行数（建议 8，可按实测调整）。
- 托盘图标的具体设计（需要与应用图标风格一致，并提供暂停样式）。
- Windows message-only 窗口和 COM 初始化放在哪个线程。
- `main.ts` 何时以及怎样拆分文件（见第 4 节）。

## 附录：v0.2 审查记录

按 Tauri 2 的项目组织方式重新审查 v0.1，改动如下。每条写明依据，方便以后再审。

| # | v0.1 的做法 | v0.2 的做法 | 依据 |
| --- | --- | --- | --- |
| 1 | 核心层、平台层是 `src-tauri/src/` 下的模块 | 独立 crate `crates/xpaste-core`、`crates/xpaste-platform`，Cargo 工作区 | ADR-001 约定 3 要求核心不依赖 Tauri；模块级约定靠自觉，crate 级约定靠编译器。Tauri 官方项目结构只约束 `src-tauri/` 内部，工作区不受影响 |
| 2 | 命令没有说明同步还是异步 | 全部 `#[tauri::command(async)]` | Tauri 把不带 `async` 的命令放在主线程执行，SQLite 查询会阻塞界面 |
| 3 | `Mutex<Connection>` 位置不明 | 托管状态 `AppState`，`State<'_, AppState>` 注入 | Tauri 的状态管理方式，避免全局变量，方便 `mock_builder` 测试 |
| 4 | 命令错误类型未定义 | `AppError`（thiserror + Serialize），统一 `{kind, message}` | Tauri 文档的错误处理方式；提示条文案只写一处 |
| 5 | `macOSPrivateApi`、bundle targets、nsis installMode 混在 `tauri.conf.json` | 拆到 `tauri.macos.conf.json`、`tauri.windows.conf.json` | Tauri 支持按平台的配置文件自动合并，共用配置不再带平台分支 |
| 6 | 一个 `capabilities/default.json` | `default.json` + `macos.json`（`platforms` 字段） | 平台专有权限不泄漏到另一端 |
| 7 | 不引入日志库，用 `eprintln!` | `tauri-plugin-log` + `log` | 官方插件，发布构建有可查的文件日志；内容不入日志的规则不变 |
| 8 | 快捷键被占用时用托盘菜单项变通，偏离规格说明 | `tauri-plugin-notification` 发系统通知 | 用官方插件就能满足规格说明 5.3.2，不必偏离 |
| 9 | `commands.rs` 单文件 | `commands/` 按领域分文件，`generate_handler!` 只出现一次 | 命令会增加到二十个以上，单文件难维护 |
| 10 | 前端 `api.ts` 单文件 | `src/api/` 目录：commands、events、types | 事件名和类型分开维护；`@tauri-apps/*` 只在这个目录出现 |
| 11 | 没有 CI | GitHub Actions 两端矩阵 | 开发机只有 macOS，Windows 编译问题要尽早暴露 |
| 12 | 版本号散在三处 | `package.json` 为唯一来源，`tauri.conf.json` 引用它，CI 检查 Cargo 版本一致 | Tauri 配置支持 `version` 指向 package.json |
| 13 | 没有评估官方插件 | 新增 3.3 节说明为什么不用 clipboard-manager、sql、store、window-state、positioner | 以后有人问起时有答案，也避免重复评估 |
| 14 | 未提及 tauri-specta | 明确不引入（仍是 rc），类型手写集中在一处，并加 fixtures 测试防止漂移 | 见第 4 节 |
