# xPaste 划词翻译与语言包下载 设计

**版本：** v0.2　**状态：** 已实现，回写为规格说明 v0.1.27 的 M26　**日期：** 2026-10-30
**依据：** 功能规格说明 v0.1.26（M15、M18、M19、M23、M26）；[翻译设计](2026-10-29-翻译-设计.md)
**目标阶段：** 阶段 15.1（M26 增补，规格说明 M26 规则 16–19、AC-M26-18…33）

**实现与设计的差异**（规格说明 M26 按实现写）：

1. 截图卡片：识别出文字后翻译失败（接口出错、超时、缺语言包、系统翻译用不了），改为出一张失败卡片（原因、翻译方式、“换用…”），不再回到选区（规格说明 M26 规则 5）。截图卡片上**没有**“下载语言包”和“去设置”：遮罩层级很高、Esc 会隐藏遮罩，确认框挂上去等不到结果；语言包到设置或面板里下载（3.4、3.1）。
2. 语言包下载的桥接为 `xp_tr_prepare(source, target, window, ctx, cb)`，另有 `xp_tr_prepare_cancel(window)`：面板、划词卡片的每条隐藏路径在隐藏前调用，把挂着的视图撤下并按取消回调，命令返回 `download`（4、6 第 1 条）。下载完成后用 `LanguageAvailability` 再查这一对语言，装好才算“已下载”。`prepareTranslation()` 在 1 秒内抛错视为确认框弹不出（7）。
3. 下载期间面板失焦不隐藏、划词卡片失焦不关闭（确认框会拿走焦点）；结束时面板没焦点、没开对话框的再隐藏。同一时刻只下载一个，再点静默忽略。缺语言包的报错同时带回源语言和**目标语言**：目标语言按原文算出（原文是中文时翻成英文），只带源语言会下错语言对（3.1）。
4. 下载语言包的语言名：报错与退回提示里，五种目标语言用其显示名（`English`、`简体中文` 等），其余用系统的本地化名，所以出现“系统翻译还没有English和简体中文的语言包”；设置那一行仍写“英语 ↔ …”（3.1）。
5. 设置页“面板、截图、划词翻译都默认用这一种…”只在“翻译方式”这一项出现时（macOS 26 及以上，两种都有）追加；只有一种时“可以临时换用另一种”不成立（3.4）。
6. 翻译快捷键：Windows 上不注册录屏快捷键，所以翻译快捷键不与录屏比较，按下时也不认作录屏（3.3）。设置或确认框开着、面板有焦点、焦点不在录制框里时，后端先交给面板，面板再调 `trcard_press` 弹卡片（3.2）。升级读出时撞上唤起、截图、录屏（macOS）任一个就读出为不启用（3.3）。
7. 模拟复制：修饰键 500 ms 内没松开就**不发**复制、直接翻译剪切板（设计原为“最多等 500 ms 后照发”），免得发出 `Ctrl+Alt+Shift+Insert`、或注入的 Ctrl 松开逻辑上松掉用户按着的 Ctrl。Windows 的 Insert 带扫描码与扩展键标志（3.2、4）。
8. 敏感内容：读剪切板的三条路径（新复制的、没变的、没权限时）都看敏感标记，剪切板里原有的密码同样不翻译（3.2 第 0 步）。“密码管理器”按“不记录这些应用”判断（默认列表里有），没有单独的名单。
9. 划词卡片：
   - 无文字、排除应用的提示不拿键盘（Windows 用 `SW_SHOWNOACTIVATE` 显示、`SW_HIDE` 收起），只有翻译卡片拿键盘（3.2）。
   - 窗口宽固定 360（设计 240–360），卡片铺满；改高度时向上翻转的卡片底边不动。
   - 再按快捷键时先撤下开着的卡片再模拟复制，否则 `⌘C` 会发到卡片自己身上；旧请求经序号中止。
   - 失败的卡片不放“复制译文”（设计只说“只能关闭”）；“去设置”也用于系统翻译用不了（`translateOs`），先关卡片再唤起面板、打开设置的“翻译”标签。
   - 下载语言包取消或失败后卡片重新拿键盘（新增 `trcard_focus`）；下载后重试显式用系统翻译。
   - 卡片关闭时把键盘还给按快捷键前的地方：面板（当时有焦点）或原来的应用（Windows 用 `activate_window`）。
10. 翻译方式标签存为 `system` / `openai:{模型 ID}`（`records.translation_engine`，库迁移 9）；“重新翻译”沿用存库的方式，模型 ID 取当前设置。迁移 9 之前存的译文没有方式：不标注、不给“换用…”（4）。`translate_engines` 另返回 `current`（按设置会用的方式），截图翻译在出第一段之前失败时据此标注。

## 1. 意图

阶段 15 交付后，用户真机验收时提了两个问题：

1. **语言包。** 用户在“语言与地区”页看到“首选语言”里有 English，以为已经配好了，翻译时却报“需要先下载English→简体中文的翻译语言包”。翻译语言包在同一页最下方的“翻译语言…”里，和首选语言是两回事。“打开系统设置”只能跳到这一页顶部，正好落在“首选语言”上，误导更深。
2. **终端里没法翻译。** `Mod + T` 只在 xPaste 面板里有效。在终端里 `⌘T` 是新建标签页，右键菜单也是终端自己的。现在要“复制 → 唤起面板 → 选中 → `⌘T`”四步，太绕。

3. **不知道用的是哪种翻译。** 系统翻译和 AI 翻译都配好时，用户看不出这次译文来自哪一种，也没法临时换一种。两种各有长短：系统翻译离线、快，但命令和代码也会被翻（“Run pnpm install” → “运行pnpm安装”）；AI 翻译能保留命令原样，但要联网、更慢。

用户的决定（2026-10-30）：

- 问题 1：在 xPaste 里一键下载语言包，弹出 macOS 自己的下载确认，不再让用户去系统设置里找。原设计第 8 章“在 xPaste 里下载系统翻译语言包”这条非目标撤销。
- 问题 2：新增全局“翻译”快捷键，在任何应用里选中文字后按一下，译文卡片弹在**鼠标旁**，不打开面板。
- 问题 3：每一处译文都标出用的是哪种翻译；两种都能用时，可以只对这一次换用另一种，不改设置。“一定要按照产品的逻辑处理，不然用户都不知道生效的是哪一个。”

## 2. 目标、非目标、反目标

**目标**

1. 系统翻译缺语言包时，所有提示处（设置的“语言包”一行、面板提示条、划词翻译卡片）都给“下载语言包”按钮，点了弹出系统的下载确认；下载完成后不用重启，直接能翻译。
2. 全局翻译快捷键，默认 macOS `⌥ ⇧ T`、Windows `Alt + Shift + T`，可改、可不启用。按下后翻译当前选中的文字，没有选中时翻译剪切板里的文字；译文在鼠标旁的卡片里逐段出现，回车复制，Esc 关闭。
3. 终端、浏览器、编辑器等任何应用里都能用，macOS 与 Windows 都支持。
4. 用户在任何一处看到译文，都知道它来自哪种翻译；能只对这一次换用另一种翻译。

**非目标**

- 不读取其他应用的选区内容（辅助功能 API 读选区），只用模拟“复制”拿到选中的文字。
- macOS“服务”菜单入口（右键 › 服务 › 用 xPaste 翻译）。
- 选中文字后自动弹出翻译按钮（PopClip 式）。
- 卡片里改目标语言、换翻译方式、编辑原文。
- 把卡片钉住、拖动卡片。
- Windows 的语言包下载（Windows 没有系统翻译）。

**反目标**

- 按了快捷键，原来那个应用的状态被改坏：多出一次粘贴、选区丢失、终端收到 `⌃C` 中断信号、按键残留成修饰键卡住。
- 卡片弹出后抢走前台：关掉卡片接着打字，字没有回到原来的应用。
- 没按快捷键也发生模拟复制或翻译请求。
- 日志里出现选中的文字、译文。
- 用户看到一段译文却分不清是系统翻译还是 AI 翻译；或者系统翻译失败时悄悄改用 AI（等于没经同意把文字发到网上）。
- 下载语言包时 xPaste 弹出自己的窗口或把面板带到前台以外的地方。

## 3. 交互

### 3.1 下载语言包（macOS 26 及以上，系统翻译）

- 按钮文案“下载语言包”，替换原来的“打开系统设置”。出现在：
  - 设置“翻译”标签的“语言包”一行：“英语 ↔ 简体中文：未下载”＋［下载语言包］；
  - 面板提示条（面板翻译报缺语言包时）；
  - 划词翻译卡片（3.2）报缺语言包时。
- 点击后弹出 macOS 的“下载翻译语言”确认（系统界面，xPaste 不画）。用户点下载 → 系统在后台下载；点取消 → 什么都不变。
- 下载期间设置里那一行显示“下载中…”；完成后变为“已下载”。从面板或卡片点的，完成后自动重试刚才那次翻译。
- 系统确认框弹不出来（极少见，比如系统组件异常）时，退回到原来的做法：打开“语言与地区”页，并提示“在这一页最下方点“翻译语言…”，下载英语和<目标语言>”。
- 缺语言包的报错文案同时改清楚：“系统翻译还没有<源语言>和<目标语言>的语言包”，不再写成“A→B”的形式。

**已验证（2026-10-30，本机 macOS 27.2）：** 用系统 `TranslationSession.prepareTranslation()` 弹确认，会话要来自 SwiftUI 的 `.translationTask`，所以要挂一个 SwiftUI 视图。独立测试程序（`accessory` 激活策略，一个小窗口里的 `NSHostingView`）成功弹出系统确认，用户点下载，约 3 分钟完成；之后英语 → 简体中文状态为 `installed`，`TranslationSession(installedSource:target:)` 翻译第一句 836 ms（含模型加载），第二句 73 ms。

### 3.2 划词翻译（全局快捷键）

**触发**

- 快捷键全局生效，规则同截图、录屏快捷键（M15）：可改、可清空（不启用）、不能和唤起、截图、录屏快捷键重复、被占用时报错。
- 按下后：
  0. 前台应用在“不记录这些应用”里（M15），或是密码管理器：不复制、不翻译，卡片显示“这个应用里的内容不翻译”，2 秒后消失。复制出来的内容被标记为敏感（M01）时同样不翻译、不入历史。
  1. 模拟一次“复制”（macOS `⌘C`；Windows `Ctrl + Insert`，见下条），最多等 400 ms 看剪切板有没有变。
  2. 变了，而且是文字：翻译这段文字。这段文字照常作为一条记录进历史（就是一次普通复制）。
  3. 没变（当前没有选中文字），或复制出来的不是文字：翻译剪切板里现有的文字。
  4. 剪切板里也没有文字：卡片显示“没有可翻译的文字：先选中文字再按 <快捷键>”，2 秒后自动消失。
- 模拟复制要等按快捷键的修饰键全部松开再发（最多等 500 ms）。否则 `⌥⇧` 还按着，会变成 `⌥⇧⌘C`，或者在 Windows 上变成 `Ctrl+Alt+Shift+Insert`。
- Windows 用 `Ctrl + Insert` 而不是 `Ctrl + C`：在 PowerShell、cmd、Windows Terminal 里没有选中文字时 `Ctrl + C` 是中断（会结束正在跑的命令），`Ctrl + Insert` 在这些终端和一般应用里都是“复制”，没有选区时什么都不做。macOS 终端里 `⌘C` 没有选区时同样什么都不做（中断是 `⌃C`）。
- macOS 没有辅助功能权限时不能模拟复制：直接翻译剪切板里的文字，卡片底部加一行“没有辅助功能权限，翻译的是剪切板里的文字”＋［前往授权］。
- 面板开着时按快捷键：面板不隐藏，照常弹卡片。设置或确认对话框里录制快捷键时，按法同截图快捷键（M15 交互规则 3，写入录制框，不翻译）。
- 卡片已经开着时再按：用新的文字重新翻译，卡片移到新的鼠标位置。

**卡片**

- 出现在鼠标指针右下方，离指针 12 px；放不下时向左、向上翻转，不超出鼠标所在屏幕的可用区域（避开菜单栏、程序坞、任务栏）。
- 宽 240–360 逻辑像素。高度随译文增长，最高到屏幕可用高度的 60%，再长就在卡片内滚动并跟到最新一段。
- 外观同截图译文卡片（M23 规则 10、M26 规则 5）：跟随 xPaste 主题，出现动效遵守“减少动态效果”。
- 内容：
  - 顶部一行灰字：原文的前 40 个字，超出用“…”；
  - 正文：译文，逐段出现，可选中；系统翻译整段出现；
  - 底部按钮：“复制译文 ↵”“关闭 Esc”。
- 状态：
  - 翻译中：正文先显示“翻译中…”，有译文后替换。收完之前“复制译文”不可用。
  - 失败：显示原因（M26 规则 13），只能关闭；未配置时带［去设置］（唤起面板并打开设置的“翻译”标签），缺语言包时带［下载语言包］（3.1）。
- 键盘与焦点：卡片拿到键盘但**不激活 xPaste**（与截图遮罩同一种窗口，M23 规则 1），前台应用不变。
  - 回车：复制译文。按普通写入进剪切板，作为一条文本记录进历史，同截图卡片。提示“已复制译文”在卡片上显示 900 ms 后卡片关闭。
  - Esc：关闭。
  - 点卡片以外的地方：关闭（卡片失去键盘时关闭）。
- 关闭后键盘回到原来的应用，接着打字就进原来的应用。
- 卡片翻译的结果不存进任何记录的译文（同截图翻译）。

### 3.3 设置

- “翻译”标签新增“翻译快捷键”录制框，放在“翻译方式”上面（两种翻译方式都用）。说明“在任何应用里选中文字后按下，译文显示在鼠标旁”。
- 显示格式、修饰键要求、⌫ / Delete 清空、占位“未启用”、冲突与占用提示全部同截图快捷键（M15）。缺修饰键时报“翻译快捷键至少需要包含 Mod 或 Alt”；不能和唤起、截图、录屏快捷键相同。
- 升级时：唤起、截图、录屏快捷键里已经有这组按键时，翻译快捷键读出为不启用。
- 状态栏不加提示（全局快捷键不在面板里用）。

### 3.4 标出翻译方式，单次换用另一种

**原则：** 设置里的“翻译方式”决定默认用哪一种；每段译文都写明它实际来自哪一种；换用只对这一次有效，要用户自己点，不自动切换。

- **标注。** 所有显示译文的地方，在标题行写翻译方式：
  - 面板译文区块：`译文 · 简体中文 · 系统翻译` / `译文 · 简体中文 · AI（gpt-4o-mini）`。AI 后面括号里是模型 ID；模型 ID 太长时截断，悬停显示完整值；不显示接口地址。
  - 截图译文卡片、划词卡片：标题行同上（不写目标语言时只写 `系统翻译` / `AI（模型 ID）`）。
  - 翻译中：`翻译中… · 系统翻译` / `翻译中… · AI（gpt-4o-mini）`，一开始就让用户知道用的是哪种。
  - 失败、中断时同样带上翻译方式，例如 `翻译失败 · 系统翻译`。
- **换用按钮。** 面板译文区块、截图卡片、划词卡片在译文收完（或失败、中断）后多一个按钮：当前是系统翻译时为“换用 AI 翻译”，当前是 AI 翻译时为“换用系统翻译”。
  - 只在另一种**能用**时显示：“换用系统翻译”要求 macOS 26 及以上；“换用 AI 翻译”要求 AI 接口已配置（接口地址、模型 ID 都不为空）。另一种用不了时不显示，也不显示置灰的按钮。
  - 点了用另一种重新翻译同一段原文，标题行随之改为新的翻译方式；不改设置里的“翻译方式”。
  - 换用 AI 翻译就是一次联网请求，和按“翻译”一样是用户的主动操作（M26 规则 1 的“手动触发”包含这个按钮）。
  - 面板里换用后的译文照常存库（覆盖原来那份，连同翻译方式），下次选中这条记录显示的是换用后的译文与它的翻译方式。
- **重新翻译** 沿用当前这段译文的翻译方式（换用过 AI 的，重新翻译还是 AI）；没有译文时（第一次翻译）用设置里的方式。
- **失败不自动换。** 系统翻译缺语言包时只给“下载语言包”；AI 接口出错时只报原因。两种情况下，如果另一种能用，失败的区块或卡片上同样有“换用…”按钮，由用户决定。
- **设置页。** “翻译方式”下方说明之后加一句：“面板、截图、划词翻译都默认用这一种；译文旁会标出用的是哪种，也可以临时换用另一种。”

## 4. 实现要点（细节由实现定）

- **语言包下载（macOS）：** Swift 桥接新增 `xp_tr_prepare(source, target, window, ctx, cb)` 与 `xp_tr_prepare_cancel(window)`（面板、卡片隐藏前调用，撤下视图并按取消回调）。源语言：设置里的“语言包”一行固定查、下载英语 ↔ 目标语言（目标是 English 时为简体中文 ↔ English）；面板、卡片因缺语言包失败时，用那次翻译识别出的源语言（Swift 已在 `NotInstalled { source }` 里交回），重试也带着它。在主线程建一个 1×1 透明的 SwiftUI 视图（`NSHostingView`）挂 `.translationTask(config)`，作为子视图塞进**发起下载时正在显示的那个 xPaste 窗口**（面板或划词卡片）的 contentView，在任务里调 `prepareTranslation()`，完成或出错时回调（0 已下载 / 1 用户取消 / 2 失败）并移除该视图。Rust 侧把窗口的 `NSWindow` 指针交给 Swift。Rust 侧 `translate_prepare(target) -> Result<PackStatus, …>` 在后台线程等回调，命令为 async。
- **模拟复制：** 平台层新增 `copy_selection()`，写法照 `paste()`：macOS `CGEvent` `⌘C`（显式只带 Command 标志），Windows `SendInput`。先等修饰键松开：macOS 用 `CGEventSourceFlagsState`，Windows 用 `GetAsyncKeyState`。用剪切板序号（macOS `changeCount`，Windows `GetClipboardSequenceNumber`）判断有没有变化。
- **卡片窗口：** 新建一个常驻、预建、隐藏的 webview 窗口 `tr-card`。macOS 用与截图遮罩同样不激活应用的 NSPanel，层级同贴图；Windows 不抢前台的写法同遮罩。按快捷键时定位、显示、交给键盘；关闭时 `orderOut`，交还键盘。前端页面独立（如 `card.html` + `src/card/`），只通过 `src/api/` 调 Tauri。
- **翻译：** 复用 `translate::run`。增量用 `translate-delta`、`id: null`，只发给 `tr-card` 窗口。再按一次快捷键时，上一次的请求通过 `on_delta` 返回 false 中止（同截图）。
- **快捷键：** `hotkey.rs` 加第四个角色 `translate`，`Settings` 新增 `translate_hotkey`（默认按平台），校验同 `shot_hotkey`。
- **翻译方式标注与换用：** 存储迁移 v8 → v9，`records` 加 `translation_engine TEXT`（`system` / `openai`），`RecordDetail` 带出来；AI 时标注用的模型 ID 由存储时一并存下（如 `translation_engine = 'openai:gpt-4o-mini'`，或另加一列，由实现定）。`translate_record(id, again, engine)` 的 `engine` 为空时：有译文且 `again` 用译文的方式，否则用设置的方式；给了就用指定的。`translate-delta` 载荷加 `engine`，命令返回值加 `engine` 与 `model`。截图卡片：后端在本次截图会话里留着识别出的原文，新增“用指定方式再翻译一次”的命令；划词卡片同理留着原文。“另一种能不能用”由一个命令返回（`translate_engines() -> { system: bool, openai: bool, model: String }`），面板、卡片打开时取一次。
- **日志：** 只记 `trcard copied=<bool> chars=N ms=T`、`trcard 无文字`、翻译本身的日志沿用 M26 规则 15；不写文字。

## 6. 我替用户做的决定（请评审时确认）

1. 语言包下载已验证可行（3.1），三次测试：
   - 普通可见窗口里的 SwiftUI 视图：弹出确认，下载成功（英语、简体中文）。
   - 完全透明（alpha 0）、不接收鼠标的独立窗口：**不弹确认**，`prepareTranslation` 一直不返回。所以不能用隐藏窗口。
   - 模拟 xPaste 面板的不激活 NSPanel，里面塞一个 1×1 透明 SwiftUI 子视图：弹出确认，下载成功（日语）。
   
   所以视图塞进当前显示的面板或卡片里，不另开窗口（4）。下载等待时间由系统决定，xPaste 不设超时；面板或卡片在下载期间被关掉时，xPaste 撤下视图、结束等待（命令返回“取消”），已经开始的下载可能由系统在后台继续，下次查状态时为“已下载”。
2. 没有选中文字时翻译剪切板里的文字，不报错。“先 `⌘C` 再按快捷键”也能用。
3. 选中的文字被复制下来会进历史（这是一次真的复制）；前台应用在“不记录这些应用”里或内容被标记为敏感时，不复制、不翻译、不入历史（3.2 第 0 步），免得把密码发给翻译接口；卡片里复制的译文也进历史（同截图卡片）。卡片翻译的结果不存成记录的译文。
4. 卡片点别处就关闭，不能钉住、不能拖。
5. 翻译快捷键放在设置的“翻译”标签，而不是“截图”标签。
6. 默认 `⌥ ⇧ T` / `Alt + Shift + T`，和截图 `⌥ ⇧ A`、录屏 `⌥ ⇧ R` 一组。
7. 卡片顶部显示原文前 40 个字，方便确认翻的是哪段。
8. Windows 模拟复制用 `Ctrl + Insert`，避免终端里没有选区时 `Ctrl + C` 中断正在跑的命令（3.2）。要在 Windows 真机上确认常见应用（Windows Terminal、PowerShell、cmd、浏览器、VS Code、记事本）都把它当“复制”。
10. 翻译方式标注用“系统翻译” / “AI（模型 ID）”，不写“OpenAI 兼容接口”，因为用户心里叫它 AI 翻译，接的也不一定是 OpenAI；设置页里的选项名不变。
11. 换用的译文在面板里覆盖存库，不同时保留两份；重新翻译沿用当前译文的方式。
9. 下载语言包的源语言：设置里固定英语 ↔ 目标语言；从面板、卡片的报错点下载时，用那次识别出的源语言（4）。
