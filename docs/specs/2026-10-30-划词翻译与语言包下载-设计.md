# xPaste 划词翻译与语言包下载 设计

**版本：** v0.1　**状态：** 待评审　**日期：** 2026-10-30
**依据：** 功能规格说明 v0.1.26（M15、M18、M19、M23、M26）；[翻译设计](2026-10-29-翻译-设计.md)
**目标阶段：** 阶段 15.1（M26 增补）

## 1. 意图

阶段 15 交付后，用户真机验收时提了两个问题：

1. **语言包。** 用户在“语言与地区”页看到“首选语言”里有 English，以为已经配好了，翻译时却报“需要先下载English→简体中文的翻译语言包”。翻译语言包在同一页最下方的“翻译语言…”里，和首选语言是两回事。“打开系统设置”只能跳到这一页顶部，正好落在“首选语言”上，误导更深。
2. **终端里没法翻译。** `Mod + T` 只在 xPaste 面板里有效。在终端里 `⌘T` 是新建标签页，右键菜单也是终端自己的。现在要“复制 → 唤起面板 → 选中 → `⌘T`”四步，太绕。

用户的决定（2026-10-30）：

- 问题 1：在 xPaste 里一键下载语言包，弹出 macOS 自己的下载确认，不再让用户去系统设置里找。原设计第 8 章“在 xPaste 里下载系统翻译语言包”这条非目标撤销。
- 问题 2：新增全局“翻译”快捷键，在任何应用里选中文字后按一下，译文卡片弹在**鼠标旁**，不打开面板。

## 2. 目标、非目标、反目标

**目标**

1. 系统翻译缺语言包时，所有提示处（设置的“语言包”一行、面板提示条、划词翻译卡片）都给“下载语言包”按钮，点了弹出系统的下载确认；下载完成后不用重启，直接能翻译。
2. 全局翻译快捷键，默认 macOS `⌥ ⇧ T`、Windows `Alt + Shift + T`，可改、可不启用。按下后翻译当前选中的文字，没有选中时翻译剪切板里的文字；译文在鼠标旁的卡片里逐段出现，回车复制，Esc 关闭。
3. 终端、浏览器、编辑器等任何应用里都能用，macOS 与 Windows 都支持。

**非目标**

- 不读取其他应用的选区内容（辅助功能 API 读选区），只用模拟“复制”拿到选中的文字。
- macOS“服务”菜单入口（右键 › 服务 › 用 xPaste 翻译）。
- 选中文字后自动弹出翻译按钮（PopClip 式）。
- 卡片里改目标语言、换翻译方式、编辑原文。
- 把卡片钉住、拖动卡片。
- Windows 的语言包下载（Windows 没有系统翻译）。

**反目标**

- 按了快捷键，原来那个应用的状态被改坏：多出一次粘贴、选区丢失、终端收到 `⌃C` 中断信号、按键残留成修饰键卡住。
- 卡片弹出后抢走前台：关掉卡片接着打字，字没有回到原来的应用。
- 没按快捷键也发生模拟复制或翻译请求。
- 日志里出现选中的文字、译文。
- 下载语言包时 xPaste 弹出自己的窗口或把面板带到前台以外的地方。

## 3. 交互

### 3.1 下载语言包（macOS 26 及以上，系统翻译）

- 按钮文案“下载语言包”，替换原来的“打开系统设置”。出现在：
  - 设置“翻译”标签的“语言包”一行：“英语 ↔ 简体中文：未下载”＋［下载语言包］；
  - 面板提示条（面板翻译报缺语言包时）；
  - 划词翻译卡片（3.2）报缺语言包时。
- 点击后弹出 macOS 的“下载翻译语言”确认（系统界面，xPaste 不画）。用户点下载 → 系统在后台下载；点取消 → 什么都不变。
- 下载期间设置里那一行显示“下载中…”；完成后变为“已下载”。从面板或卡片点的，完成后自动重试刚才那次翻译。
- 系统确认框弹不出来（极少见，比如系统组件异常）时，退回到原来的做法：打开“语言与地区”页，并提示“在这一页最下方点“翻译语言…”，下载英语和<目标语言>”。
- 缺语言包的报错文案同时改清楚：“系统翻译还没有<源语言>和<目标语言>的语言包”，不再写成“A→B”的形式。

**已验证（2026-10-30，本机 macOS 27.2）：** 用系统 `TranslationSession.prepareTranslation()` 弹确认，会话要来自 SwiftUI 的 `.translationTask`，所以要挂一个 SwiftUI 视图。独立测试程序（`accessory` 激活策略，一个小窗口里的 `NSHostingView`）成功弹出系统确认，用户点下载，约 3 分钟完成；之后英语 → 简体中文状态为 `installed`，`TranslationSession(installedSource:target:)` 翻译第一句 836 ms（含模型加载），第二句 73 ms。

### 3.2 划词翻译（全局快捷键）

**触发**

- 快捷键全局生效，规则同截图、录屏快捷键（M15）：可改、可清空（不启用）、不能和唤起、截图、录屏快捷键重复、被占用时报错。
- 按下后：
  0. 前台应用在“不记录这些应用”里（M15），或是密码管理器：不复制、不翻译，卡片显示“这个应用里的内容不翻译”，2 秒后消失。复制出来的内容被标记为敏感（M01）时同样不翻译、不入历史。
  1. 模拟一次“复制”（macOS `⌘C`；Windows `Ctrl + Insert`，见下条），最多等 400 ms 看剪切板有没有变。
  2. 变了，而且是文字：翻译这段文字。这段文字照常作为一条记录进历史（就是一次普通复制）。
  3. 没变（当前没有选中文字），或复制出来的不是文字：翻译剪切板里现有的文字。
  4. 剪切板里也没有文字：卡片显示“没有可翻译的文字：先选中文字再按 <快捷键>”，2 秒后自动消失。
- 模拟复制要等按快捷键的修饰键全部松开再发（最多等 500 ms）。否则 `⌥⇧` 还按着，会变成 `⌥⇧⌘C`，或者在 Windows 上变成 `Ctrl+Alt+Shift+Insert`。
- Windows 用 `Ctrl + Insert` 而不是 `Ctrl + C`：在 PowerShell、cmd、Windows Terminal 里没有选中文字时 `Ctrl + C` 是中断（会结束正在跑的命令），`Ctrl + Insert` 在这些终端和一般应用里都是“复制”，没有选区时什么都不做。macOS 终端里 `⌘C` 没有选区时同样什么都不做（中断是 `⌃C`）。
- macOS 没有辅助功能权限时不能模拟复制：直接翻译剪切板里的文字，卡片底部加一行“没有辅助功能权限，翻译的是剪切板里的文字”＋［前往授权］。
- 面板开着时按快捷键：面板不隐藏，照常弹卡片。设置或确认对话框里录制快捷键时，按法同截图快捷键（M15 交互规则 3，写入录制框，不翻译）。
- 卡片已经开着时再按：用新的文字重新翻译，卡片移到新的鼠标位置。

**卡片**

- 出现在鼠标指针右下方，离指针 12 px；放不下时向左、向上翻转，不超出鼠标所在屏幕的可用区域（避开菜单栏、程序坞、任务栏）。
- 宽 240–360 逻辑像素。高度随译文增长，最高到屏幕可用高度的 60%，再长就在卡片内滚动并跟到最新一段。
- 外观同截图译文卡片（M23 规则 10、M26 规则 5）：跟随 xPaste 主题，出现动效遵守“减少动态效果”。
- 内容：
  - 顶部一行灰字：原文的前 40 个字，超出用“…”；
  - 正文：译文，逐段出现，可选中；系统翻译整段出现；
  - 底部按钮：“复制译文 ↵”“关闭 Esc”。
- 状态：
  - 翻译中：正文先显示“翻译中…”，有译文后替换。收完之前“复制译文”不可用。
  - 失败：显示原因（M26 规则 13），只能关闭；未配置时带［去设置］（唤起面板并打开设置的“翻译”标签），缺语言包时带［下载语言包］（3.1）。
- 键盘与焦点：卡片拿到键盘但**不激活 xPaste**（与截图遮罩同一种窗口，M23 规则 1），前台应用不变。
  - 回车：复制译文。按普通写入进剪切板，作为一条文本记录进历史，同截图卡片。提示“已复制译文”在卡片上显示 900 ms 后卡片关闭。
  - Esc：关闭。
  - 点卡片以外的地方：关闭（卡片失去键盘时关闭）。
- 关闭后键盘回到原来的应用，接着打字就进原来的应用。
- 卡片翻译的结果不存进任何记录的译文（同截图翻译）。

### 3.3 设置

- “翻译”标签新增“翻译快捷键”录制框，放在“翻译方式”上面（两种翻译方式都用）。说明“在任何应用里选中文字后按下，译文显示在鼠标旁”。
- 显示格式、修饰键要求、⌫ / Delete 清空、占位“未启用”、冲突与占用提示全部同截图快捷键（M15）。缺修饰键时报“翻译快捷键至少需要包含 Mod 或 Alt”；不能和唤起、截图、录屏快捷键相同。
- 升级时：唤起、截图、录屏快捷键里已经有这组按键时，翻译快捷键读出为不启用。
- 状态栏不加提示（全局快捷键不在面板里用）。

## 4. 实现要点（细节由实现定）

- **语言包下载（macOS）：** Swift 桥接新增 `xp_tr_prepare(source, target, ctx, cb)`。源语言：设置里的“语言包”一行固定查、下载英语 ↔ 目标语言（目标是 English 时为简体中文 ↔ English）；面板、卡片因缺语言包失败时，用那次翻译识别出的源语言（Swift 已在 `NotInstalled { source }` 里交回），重试也带着它。在主线程建一个 1×1 透明的 SwiftUI 视图（`NSHostingView`）挂 `.translationTask(config)`，作为子视图塞进**发起下载时正在显示的那个 xPaste 窗口**（面板或划词卡片）的 contentView，在任务里调 `prepareTranslation()`，完成或出错时回调（0 已下载 / 1 用户取消 / 2 失败）并移除该视图。Rust 侧把窗口的 `NSWindow` 指针交给 Swift。Rust 侧 `translate_prepare(target) -> Result<PackStatus, …>` 在后台线程等回调，命令为 async。
- **模拟复制：** 平台层新增 `copy_selection()`，写法照 `paste()`：macOS `CGEvent` `⌘C`（显式只带 Command 标志），Windows `SendInput`。先等修饰键松开：macOS 用 `CGEventSourceFlagsState`，Windows 用 `GetAsyncKeyState`。用剪切板序号（macOS `changeCount`，Windows `GetClipboardSequenceNumber`）判断有没有变化。
- **卡片窗口：** 新建一个常驻、预建、隐藏的 webview 窗口 `tr-card`。macOS 用与截图遮罩同样不激活应用的 NSPanel，层级同贴图；Windows 不抢前台的写法同遮罩。按快捷键时定位、显示、交给键盘；关闭时 `orderOut`，交还键盘。前端页面独立（如 `card.html` + `src/card/`），只通过 `src/api/` 调 Tauri。
- **翻译：** 复用 `translate::run`。增量用 `translate-delta`、`id: null`，只发给 `tr-card` 窗口。再按一次快捷键时，上一次的请求通过 `on_delta` 返回 false 中止（同截图）。
- **快捷键：** `hotkey.rs` 加第四个角色 `translate`，`Settings` 新增 `translate_hotkey`（默认按平台），校验同 `shot_hotkey`。
- **日志：** 只记 `trcard copied=<bool> chars=N ms=T`、`trcard 无文字`、翻译本身的日志沿用 M26 规则 15；不写文字。

## 6. 我替用户做的决定（请评审时确认）

1. 语言包下载已验证可行（3.1），三次测试：
   - 普通可见窗口里的 SwiftUI 视图：弹出确认，下载成功（英语、简体中文）。
   - 完全透明（alpha 0）、不接收鼠标的独立窗口：**不弹确认**，`prepareTranslation` 一直不返回。所以不能用隐藏窗口。
   - 模拟 xPaste 面板的不激活 NSPanel，里面塞一个 1×1 透明 SwiftUI 子视图：弹出确认，下载成功（日语）。
   
   所以视图塞进当前显示的面板或卡片里，不另开窗口（4）。下载等待时间由系统决定，xPaste 不设超时；面板或卡片在下载期间被关掉时，视图随窗口隐藏，下载由系统继续，下次查状态时为“已下载”。
2. 没有选中文字时翻译剪切板里的文字，不报错。“先 `⌘C` 再按快捷键”也能用。
3. 选中的文字被复制下来会进历史（这是一次真的复制）；前台应用在“不记录这些应用”里或内容被标记为敏感时，不复制、不翻译、不入历史（3.2 第 0 步），免得把密码发给翻译接口；卡片里复制的译文也进历史（同截图卡片）。卡片翻译的结果不存成记录的译文。
4. 卡片点别处就关闭，不能钉住、不能拖。
5. 翻译快捷键放在设置的“翻译”标签，而不是“截图”标签。
6. 默认 `⌥ ⇧ T` / `Alt + Shift + T`，和截图 `⌥ ⇧ A`、录屏 `⌥ ⇧ R` 一组。
7. 卡片顶部显示原文前 40 个字，方便确认翻的是哪段。
8. Windows 模拟复制用 `Ctrl + Insert`，避免终端里没有选区时 `Ctrl + C` 中断正在跑的命令（3.2）。要在 Windows 真机上确认常见应用（Windows Terminal、PowerShell、cmd、浏览器、VS Code、记事本）都把它当“复制”。
9. 下载语言包的源语言：设置里固定英语 ↔ 目标语言；从面板、卡片的报错点下载时，用那次识别出的源语言（4）。

## 8. 已知限制（写进 docs/已知限制.md）

- 系统翻译不能用提示词约束：命令、路径、代码里的单词也可能被翻译（实测 “Run pnpm install” → “运行pnpm安装”）。需要原样保留时改用 OpenAI 兼容接口。
