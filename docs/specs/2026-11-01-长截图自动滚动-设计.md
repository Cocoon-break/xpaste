# xPaste 长截图（自动滚动）设计

日期：2026-11-01。现状见 [截图与录屏设计](2026-10-28-截图与录屏-设计.md)“长截图与收尾去抖”一节与规格说明 M23 规则 13（v0.1.41）；真实问题与排查见[验收记录](../验收记录.md)“长截图一开始就接不上”“长截图在终端里接不上”。

## 1. 意图

现在的长截图要用户自己滚，程序每秒截 10–30 帧、比对拼接。真机上的问题都出在这条路上：用户控制不好速度（“滚得太快没接上”），接不上时要看着预览往回找，长页面要一直拖到底，悬浮按钮、侧栏会被拼进长图。

目标是**体验最好、两个平台一致**，不以实现难度取舍：选好区域按 L，程序自己平稳地滚、看着画面拼，到底自动结束；用户随时可以自己滚、暂停或提前完成；结果干净，能直接编辑。

## 2. 目标、非目标、反目标

**目标**

1. 自动滚动：按 L 后程序自己往下滚，速度随拼接把握自适应；到底（继续滚画面不再变化）自动完成。
2. 用户随时接手：自己动滚轮、触控板时自动滚动让出，停手后接着滚；空格暂停、继续；回车提前完成，Esc 取消。
3. 不再出现“滚得太快”：截屏改为系统推送的连续画面流（最多每秒 60 帧），自动滚动每步小于一屏。
4. 接不上时程序自己恢复（往回滚、放慢、重试），而不是让用户去找位置；恢复不了时暂停并说明原因，用户可以保留已拼好的部分。
5. 结果干净：吸顶吸底只留一份（已有）；悬浮按钮、浮动提示、不随内容滚动的侧栏不进入长图的内容区。
6. 选区更省事：单击选中整个窗口后按 L，自动收窄到单击位置所在的可滚动区域（网页正文、聊天记录、代码编辑区），不用手动框。
7. 截完能编辑：长图进入可滚动的编辑窗口，可裁掉头尾、加标注，然后复制、保存或贴图。
8. macOS 与 Windows 功能一致。

**非目标**

- 横向长截图。
- 按应用逐个适配（读浏览器整页、读某个应用的滚动位置作为唯一依据）。系统辅助功能接口能拿到滚动位置时只当作提示，见 4.3。
- Linux（产品不支持）。

**反目标**（即使功能“能用”，出现就算失败）

- 悄悄接错：任何拿不准的情况都报没接上，不拼进长图。现有的防接错规则（精确比对的明显胜出、近似比对只有一个像样的位置）一条都不能放松。
- 向别的应用发键盘或点击：只发滚动事件。Page Down、空格、方向键会打进输入框、触发快捷键，点击会改变应用状态，一律不发。
- 抢走用户的指针：自动滚动期间用户移动指针、点击、滚动都照常生效，程序不把指针拉回去。
- 截进 xPaste 自己的窗口（边框、提示、预览）。

## 3. 约束

- 分层不变：拼接、运动估计、合成都在 `xpaste_core::stitch`（纯函数、单元测试、用存下的真实帧做回归）；截屏流、滚动事件、命中测试在 `xpaste-platform`，按 `cfg` 同名导出；节奏控制在 `src-tauri/src/longshot.rs`。
- 隐私（M23 规则 11）：画面只在本机内存里处理，长截图结束即释放；日志只记尺寸、帧数、耗时、没接上的帧数、滚动步数，不记画面、窗口标题、应用里的文字。
- 权限：macOS 发滚动事件需要“辅助功能”（自动粘贴已在申请，M18）；截屏需要“屏幕录制”（已有）。Windows 不需要额外权限，但发不进管理员权限的窗口（同自动粘贴的限制）。
- 最低系统：macOS 13（ScreenCaptureKit 可用，录屏已在用）；Windows 10 1903 起有 Windows.Graphics.Capture，产品已要求 21H2（设备支持）。
- 性能：每帧处理（定位、拼接）在 2 倍屏整屏选区下不超过一帧的时间（约 16 ms）的平均值；偶发超时可以丢帧，不能积压。

## 4. 已决定的方案

### 4.1 用户看到的流程

1. 截图遮罩里选区，与现在一样（单击仍选中整个窗口，复制、保存、贴图不受影响）。
2. 按 L（或工具栏“长截图”）。选区是单击选中的整个窗口时，先收窄到单击位置所在的可滚动区域（4.5），选区框在遮罩撤下前动一下，让用户看到截的是哪块〔我的决定：普通截图的单击行为不变，只在长截图时收窄；手动拖出的选区不收窄〕。遮罩撤下，边框、提示与预览出现（现有）。
3. 有辅助功能权限时**立即开始自动滚动**〔我的决定：默认自动，用户想自己滚时直接滚即可，不需要先切换模式〕。提示文案改为“自动滚动中 · 空格暂停 · ↩ 完成 · Esc 取消”。没有权限时进入手动模式（现在的行为），提示里加“授权辅助功能后可自动滚动”与“前往授权”。
4. 用户自己滚动时，自动滚动暂停；停手约 1 秒后接着滚〔建议值，实现时按手感调〕。空格切换暂停、继续。
5. 到底：连续几步滚动后画面都不再变化，自动完成（同回车）。
6. 完成后长图进入编辑窗口（4.6）；编辑窗口里回车复制、⌘S 保存、P 贴图、Esc 直接复制并关闭〔我的决定：Esc 在编辑窗口里不丢弃结果，长截图已经花了用户时间；丢弃用窗口里的“放弃”按钮〕。

### 4.2 截屏：连续画面流

- macOS：ScreenCaptureKit 的 `SCStream`，内容过滤器为选区所在显示器、排除 xPaste 的全部窗口（录屏已有的写法，`macos_record.rs`），`sourceRect` 为选区，像素格式 BGRA，`minimumFrameInterval` 1/60 秒。画面不变时系统只推空闲帧，正好对应 `Step::Same`，不必处理。
- Windows 11：Windows.Graphics.Capture 截选区所在的显示器，按选区裁剪，关掉系统的黄色截屏边框（`IsBorderRequired = false`，build 20348 起）；xPaste 的窗口带 `WDA_EXCLUDEFROMCAPTURE`（现有）。HDR 显示器上按 SDR 色调映射后再交给拼接。
- Windows 10：系统强制显示黄色截屏边框，且贴边的选区会把黄边截进画面，所以不用画面流，继续用现在的逐帧截屏（`capture_rect`）〔我的决定：两个系统上的功能一样，只是 Windows 10 的帧率低一些〕。
- 普通截图的冻结（`freeze_displays`）这一期不改；HDR 下截图发灰仍按设备支持里的优化项单独做。
- 平台层对上只暴露一个接口：开始一个区域画面流，回调给出 RGBA（sRGB）帧；停止。帧到达快于处理时只保留最新一帧（不积压）。
- 第一帧仍按 `longshot::settled` 的规则等画面稳定（遮罩淡出）。
- 现有的逐帧截屏（`capture_rect`）保留给截图冻结与不支持画面流的情况，不再用于长截图。

### 4.3 滚动：自动滚动与节奏

- 只发滚动事件，事件位置在选区中心（滚动事件作用于该位置下的窗口）。macOS 用像素单位的滚轮事件（`CGEventCreateScrollWheelEvent2`，`kCGScrollEventUnitPixel`），Windows 用 `SendInput` 的 `MOUSEEVENTF_WHEEL`（支持小于 120 的增量；不响应时改发整格）。发事件不移动用户的指针（4.3 末条）。
- 节奏：每步滚动量是选区高度的一部分（起步约 1/3 屏），等画面停下（连续两帧相同或超时）再发下一步。拼接连续成功就逐步加大步长（不超过 2/3 屏），没接上就减半。
- 学习比例：滚动事件的量与实际位移的比例各应用不同（平滑滚动、加速、行距换算）。用每次成功拼接时的实际位移校正比例，作为下一步的**预期位移**交给定位（4.4），缩小查找范围。
- 到底：连续 3 步发了滚动、画面都没变 → 完成。
- 不响应：开始后最初几步发了滚动、画面一直没变（应用不响应模拟滚动、管理员权限窗口、选区不是可滚动的内容）→ 转手动模式并提示“这个窗口不响应自动滚动，请自己滚动”。
- 恢复：没接上时往回滚半步、步长减半重试；连续 3 次恢复不了 → 暂停，提示“这里一直接不上（画面在变？），↩ 保留已拼好的部分”（沿用现有文案）。
- 用户接手：检测到不是自己发的滚动、按键或点击（macOS 用事件源区分，Windows 用 `dwExtraInfo` 标记自己发的事件）→ 暂停自动滚动，按现在的手动方式拼接；停手后恢复。
- 指针：程序不移动指针。滚动事件带位置；如果某个平台的滚动只作用于指针下的窗口，而用户把指针移出了选区，就暂停并提示“把指针移回选区继续”，不强行移动指针。
- 可选的精确提示：系统辅助功能接口（macOS AX 的滚动区域与滚动条值、Windows UI 自动化的 ScrollPattern）能读到滚动位置时，用它算预期位移，仍以画面比对为准；读不到时不影响功能。

### 4.4 定位：在现有比对上加三件事

现有 `Stitch` 的两级比对保留：先找完全相同的行，再按文字边缘近似比对（只有一个像样的位置才接）。在此之上：

1. **预期位移**：自动滚动时有预期位移（4.3），先在预期位移附近找；预期附近找不到再按现有的全范围规则找。预期只缩小范围、提高把握，不放松任何防接错的条件。
2. **分块判断哪些区域在滚**：把帧切成若干块（如 8 × 8），逐块估计相对上一帧的位移；多数块一致的位移就是滚动，其余块（侧栏、悬浮按钮、视频、悬停高亮、正在打字的光标附近）记为“不跟着滚”，比对时排除。现在靠“整行对不上的不超过 1/4”容忍这些情况，改为按块排除后，大块的悬浮元素与侧栏也能接上。
3. **画面流的连续性**：相邻帧位移很小，用上一帧到这一帧的位移累加作为又一个预期，与长图上的定位相互印证；两者不一致时视为没接上。

### 4.5 合成与选区

- 不跟着滚的块（4.4 第 2 条）：在长图里用别的帧中同一处内容（没被遮住时看到的）替换，悬浮按钮、浮动提示不进入长图；整列都不跟着滚的块（侧栏）按“吸顶吸底”的思路只保留一份，放在长图对应列的顶部，其余部分用内容区背景色填充〔我的决定，待原型验证效果；不好时改为整列裁掉〕。
- 背景图不随文字滚动的窗口：文字与背景在像素上分不开，背景仍会一段段拼起来（已知限制，保留）。
- 可滚动区域选区：按 L 时，若选区来自单击选中窗口，按单击位置问系统辅助功能接口（macOS `AXUIElementCopyElementAtPosition` 向上找 `AXScrollArea`；Windows UI 自动化 `ElementFromPoint` 向上找支持 ScrollPattern 的元素）拿到滚动区域的边界；拿不到时保持整个窗口。

### 4.6 编辑窗口

- 长截图完成后打开一个可滚动的编辑窗口：长图按窗口宽度显示，滚轮滚动，右侧有缩略导航。
- 工具与截图遮罩一致（矩形、箭头、马赛克、文字、序号，撤销重做），复用 `src/shot/` 的标注代码；另有“裁剪”：拖动顶部、底部的裁剪线。
- 动作：回车复制（进历史，同 M23 规则 7）、⌘S 保存、P 贴图（贴图过长时按屏幕高度缩放）、“放弃”。
- 窗口行为〔我的决定〕：普通的、会激活 xPaste 的窗口（文字标注要接收输入），关闭后把键盘还给原来的应用；同时只开一个，编辑窗口开着时可以照常截图、长截图，新的长截图完成时先问是否替换当前未处理的长图。
- 界面先做原型（本地 HTML，同截图与录屏的原型做法），确认后再实现；“侧栏只留一份”的合成效果也在原型里用真实帧验证。
- 有了编辑窗口后，“有标注时不能开始长截图”的限制保留（长截图截的是实时画面），标注在长截图之后做。

## 5. 规格说明要改的地方

M23 规则 3（单击选中可滚动区域）、规则 13（自动滚动、接手、到底完成、恢复、编辑窗口，提示文案），新增验收标准；M18（辅助功能权限用途加“长截图自动滚动”）；附录文案；已知限制、设备支持同步。

## 6. 阶段划分

每个阶段都能单独发版，按顺序：

验收：每个阶段在 macOS 真机上验收；Windows 部分先做 Windows 交叉 clippy 与单元测试，再由用户在 Windows 实机上验证（Windows 11、125% / 150% 缩放，有 HDR 显示器时加 HDR），结果记在验收记录。Windows 实机验证没做完的阶段，发版说明里写明“Windows 待实机验收”。

1. **画面流**：两个平台的区域画面流，长截图改用它；手动模式不变。验收：同样的手动滚动，没接上的帧明显减少（用存帧重放与真机日志的“没接上 L 帧”对比）。
2. **自动滚动**：4.1、4.3（含学习比例、预期位移、到底、不响应、恢复、用户接手、权限）。
3. **分块与干净合成**：4.4 第 2、3 条与 4.5 前两条。
4. **可滚动区域选区与编辑窗口**：4.5 末条与 4.6。

开发用的排查工具先行（阶段 1 之前）：开发构建里的逐帧存图开关与离线重放工具进仓库。回归数据〔我的决定〕：仓库里只放裁剪、缩小过、不含个人内容的短序列（每组几 MB 以内，不用 Git LFS），按“长截图在终端里接不上”这类真实场景各存一组；完整的帧序列只留在本机。

## 7. 留给实现者决定

- 自动滚动的起步步长、加速与减速曲线、等画面停下的超时、“停手后恢复”的等待时间。
- 分块的块数与“多数一致”的阈值。
- 画面流的帧率上限（60 或按显示器刷新率）。
- 编辑窗口的布局细节（工具栏位置、缩略导航样式），以原型为准。
- 某个平台的滚动事件不能带位置、只作用于指针下窗口时的具体处理（按 4.3 末两条的原则：不移动指针）。

## 8. 实现与设计不同的地方

画面流部分（M23 规则 13，规格 v0.1.42）：

- 帧率：macOS 限 60 帧/秒（`minimumFrameInterval`）。Windows 11 的限帧（`SetMinUpdateInterval`）24H2 起才生效，更早的版本按屏幕刷新率送帧，不在回调里丢帧：画面流只在画面变化时送帧，滚动停下前的最后一帧丢了就不会再来。槽位只留最新一帧，不积压，多花的是 CPU。第 7 节允许“60 或屏幕刷新率”，两者都用了。
- 第一帧：画面流只在画面变化时出帧（macOS 只投递 `Complete` 的帧），画面静止时 `settled` 等不到第二帧。改为最多等 100 ms，等不到就沿用上一帧，视为“连续两帧相同”。
- 空闲不算没接上：循环里取不到新帧时状态不变；但已经是“没接上”且满 3 秒时升级为“这里一直接不上”，否则用户停手后提示永远停在“没接上”。
- 画面流中断（Windows 上显示器分辨率变化、采集项被关闭）：按回车处理，保留已拼好的部分，不当作失败。
- Windows 10（build < 20348）与画面流启动失败（跨屏选区、关不掉黄色边框）：退回每 40 ms 逐帧截屏，原来的行为。
- 颜色：macOS 画面流设为 sRGB，与 `capture_rect` 同区域输出逐通道最大差 3（0.18% 的通道差 3）。一次长截图的帧全部来自画面流，拼接内部一致。
- Windows 上区域取整与 `capture_rect` 一致（截断），小数缩放下与“宽 = round(w × scale)”可能差 1 px。
- 排除范围：只排除边框窗口，不是第 4.2 节写的所有 xPaste 窗口；淡出中的截图遮罩仍可能被截进去，所以第一帧要等画面稳定（连续两帧相同）才取。
- HDR：不做显式的 SDR 色调映射，帧用 BGRA8，依赖系统转换；HDR 屏上的效果未验证。
- 开发构建加了 `XPASTE_LONG_DUMP=<目录>` 逐帧存图和 `stitch_replay` 离线重放（设计之外的排查手段，见 CONTRIBUTING.md）；`tests/fixtures/stitch/chrome`（22 帧）是回归夹具。

自动滚动部分（阶段 2，M23 规则 13，规格 v0.1.43）：

- 不做设计 4.1 第 3 步的“前往授权”按钮：边框窗口不接收点击（点击要穿透给被截的应用）。macOS 没有辅助功能权限时只在提示里写“授权辅助功能后可自动滚动”，授权入口沿用设置与提示条里已有的“前往授权”。
- 不做 4.3 末条“可选的精确提示”（读辅助功能接口的滚动位置）：画面比对加预期位移已够用，读不到也不影响功能，确有需要时再做。
- 预期位移只在比例测出来之后才给；比例没测出来（初始猜测）时按原规则拼。完全周期的内容里预期偏一个周期无法识别，初始猜测又可能差很多。
- 第一次实测位移直接取代初始猜测，之后才按 0.5 权重平均；测到之后，落在预期 0.5–2 倍之外的位移（到底前最后一小步、一次跳动）不用来学。
- 预期只在最近一帧定位到、且是往下的一步时给，往回滚的恢复步不给。预期范围被长图末端截断时不用预期，按全范围找。分层顺序：预期附近精确 → 全范围精确 → 预期附近近似 → 全范围近似。
- 等画面停下有上限：发出后满 1 秒（`STEP_MAX`）不管画面是否还在变都算停下，否则视频、轮播会让自动滚动卡住。停下的判断：画面连续 120 ms 没变；发出后一直没变时等 300 ms（应用处理滚动要时间）。“位置变了”也算画面变了（往回滚的恢复步结果是已拼好的部分）。
- 一步中途短暂没接上、最后回到原位，按“定位到了”算（`Stitch::located`），不报没接上，否则到底时会一直来回滚。
- 用户接手的判断：macOS 查系统 HID 状态里距上次滚轮、按键、点击的时间，本进程的滚动用私有事件源发、不进 HID 状态（待真机确认）；Windows 用低层钩子，忽略注入的输入与带 `dwExtraInfo` 标记的自己的滚动（设计写的“事件源区分”两端实现不同）。Windows 的钩子线程提高优先级，否则回调慢了系统会悄悄摘掉钩子，之后接手再也检测不到。
- 自己的空格、回车、Esc 不算接手：系统先看到按键再分发给快捷键回调，所以输入时刻不晚于快捷键时刻 + 300 ms 的不算；开始时刻也当作一次快捷键（macOS 的 HID 状态保留开始之前按 L、点工具栏的输入）。
- 空格只在自动滚动时注册，转手动、到上限时注销，手动滚时空格留给应用翻页。到上限后不再自动滚动（继续滚只会三步后按“到底”完成）。
- 连续 3 次恢复不了后暂停（`stuck`），空格从当前位置重新开始；暂停、一直接不上、接手期间显示自动滚动的状态，接手期间若拼接本身没接上则显示拼接的提示。
