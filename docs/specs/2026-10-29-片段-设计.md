# xPaste 片段 设计

**版本：** v0.2　**状态：** 待评审（已过一轮实现视角审阅）　**日期：** 2026-10-29
**依据：** 功能规格说明 v0.1.23（M03、M05、M06、M07、M09、M12、M13、M15、M19）
**目标阶段：** 阶段 14
**交互原型：** [2026-10-29-片段-原型.html](2026-10-29-片段-原型.html)（本地打开；在交互原型 v0.3 上改的，只看片段相关的部分）

## 1. 意图

历史记录是“复制过什么就记什么”，会被保留天数、条数上限和“清空历史”清掉。用户还有一类内容需要长期留着、随手粘贴：常用的命令（`fmctl 批量执行`、`docker 内执行命令`）、地址、邮件签名、收款二维码。这类内容的原文往往很长，不好搜，但用户给它起的名字很好记。

片段就是“名字 + 内容”：用户自己存进来，按名字（也可以按内容）搜到，回车粘贴出来的是内容。参照的是 Alfred 的 snippets：在同一个搜索框里输入名字，选中就粘贴。

## 2. 目标、非目标、反目标

**目标**

1. 两种入口新建片段：
   - 设置里新建一条，自己填名字和内容（只支持文字）；
   - 面板里把历史中已有的一条记录存成片段，再起个名字。文本、链接、代码、图片、视频、文件都可以存。
2. 分类栏单独加一个“片段”分类，只显示片段。在“全部”下搜索时，命中的片段和历史记录混在一起，片段排在最前面，自成“片段”一组。
3. 名字和内容都参与搜索。名字和历史标题一样支持拼音、首字母搜索，命中的汉字会高亮（M05 规则 11）。
4. 粘贴片段和粘贴历史记录完全一样：回车、双击、⌘1–9、右键“粘贴”都能用，自动粘贴、只能复制时的降级处理照旧（M09）。
5. 片段在面板里管理：改名、改内容（仅限文字类）、单条删除、批量删除，删除后 5 秒内可撤销。
6. 片段是用户自己的数据，**任何自动清理都不能动它**：不受保留天数、最多条数的限制，“清空历史”（设置和托盘两个入口）也不删片段。片段只能由用户在面板里单条或批量删除。

**非目标（本期不做，写进规格说明第 8 章）**

- 片段里的占位符或动态内容（日期、光标位置、剪切板内容、填空）
- 片段分组、文件夹、标签、排序拖动
- 输入缩写自动展开（在任意应用里打关键字直接替换，Alfred 的 auto-expand）
- 导入、导出、同步
- 在设置里新建图片、文件片段（只能从历史存进来）
- 片段置顶

**反目标（即使功能上能用，出现以下情况也算失败）**

- 清理、清空或容量上限删掉了任何一条片段。
- 历史里对应的那条记录被删掉或被清理后，从它存出来的片段内容丢失或损坏，包括图片文件和缩略图。
- 复制一段和某个片段内容相同的文字时，这次复制被合并进片段（片段的使用次数变了、历史里没有新记录）。
- 日志里出现片段的名字或内容。
- 历史视图（“全部”不搜索时、各类型分类、“常用”、复制频谱）里混进了片段。

## 3. 交互（已和用户确认，原型可点）

### 3.1 分类与列表

- 分类栏顺序：全部 · 常用 · **片段** | 文本 · 链接 · 代码 · 图片 · 视频 · 文件。分隔线从“常用”后挪到“片段”后。片段用品红作类型色（`--c-snip`，沿用已删掉的颜色类型那一档；具体色值由实现定，亮暗两套都要过对比度检查），图标是书签。
- “全部”不搜索时**不显示片段**。“全部”的条数也只算历史记录。
- 按类型筛选（文本、代码……）和“常用”时，片段都不出现，搜索时也不出现。片段只出现在“片段”分类，以及“全部”下有搜索词的时候。
- “片段”分类里只有一个分组，叫“片段”，按上次使用时间倒序，从没用过的按创建时间。
- 列表行：
  - 标题是片段的**名字**；
  - 第二行是内容的摘要（文字类取内容首行，图片显示“图片 W × H”，文件显示文件名）和“用过 N 次”，不显示来源应用和时间；
  - 缩略图按内容类型照常显示（图片有缩略图，其余是类型图标），但用片段的类型色。
- 行尾快捷按钮：历史行是“置顶 / 复制”，片段行换成“编辑 / 复制”。
- “片段”分组标题**吸顶**，右侧固定一个“+ 新建片段 ⌘N”按钮，片段再多也不用滚到底找（用户在原型上提出）。没有片段时，空状态写“还没有片段。在历史记录上右键“存为片段…”，或在设置里新建”，下面也放这个按钮。
- 搜索框右侧的“匹配数 / 总数”：在“片段”分类里总数是片段数；“全部”有搜索词时总数是历史数加片段数；其余情况不变。

### 3.2 搜索

- 名字和内容都参与匹配，规则与历史记录相同（M05 规则 2、3、11、12）：
  - 名字相当于片段的标题：拼音首字母（2 个字母只比标题）、全拼都对名字生效；
  - 高亮落在名字里命中的字上；
  - 内容按字面、拼音照常匹配，图片片段的图中文字照常可搜（M22）。
- 结果排序：命中的片段在前，组内按片段的排序规则；后面是历史记录，仍按 M07 分组（置顶、今天、昨天、更早）。不做“命中率”排序。
- ⌘1–9 按屏幕上的顺序编号，片段也算在内。

### 3.3 预览区

- 头部的类型标签：`片段`（品红）在前，后面是内容类型标签（文本、代码……）。
- 正文最上方用大字显示名字（有高亮），下面是内容，内容的展示方式与同类型的历史记录相同（M08）。
- 底部信息栏：上次使用、大小、使用次数，再按类型补充（字符数、行数、尺寸、时长……）。没有“来源”和“复制于”。
- 头部按钮：
  - 历史记录：置顶、**存为片段**（书签图标）、删除、复制；
  - 片段：**编辑**（铅笔图标）、删除、复制。片段不显示置顶。

### 3.4 存为片段 / 编辑 / 新建：同一个对话框

一个对话框，标题按用途变：“存为片段”“编辑片段”“新建片段”。

- 名字：必填，去掉首尾空白后不能为空，否则提示“请填写名字”，焦点留在这里。打开时预填并全选：
  - 存为片段时预填记录标题（截断到 40 个字符）；
  - 编辑时预填当前名字；
  - 新建时为空。

  下方说明：“在面板里搜这个名字就能找到它，支持拼音与首字母”。允许重名（我的决定：重名只是搜索时都出来，不值得拦）。名字上限 100 个字符（我的决定），超出部分输入框不让再输。
- 内容：
  - 文字类（文本、链接、代码）是多行输入框，可编辑，必填（空白提示“请填写内容”）；
  - 图片、视频、文件显示缩略图加文件名，不能改，下方说明“图片和文件的内容不能改，只能改名字”。
- 按钮：取消、保存片段（编辑时为“保存修改”）。Esc、点遮罩都关闭且不保存。
- 保存后：
  - 存为片段：提示条“已存为片段“名字”，搜索这个名字就能找到”；
  - 编辑：提示条“片段已更新”；
  - 从设置新建：设置开着时提示条被遮住，结果写在设置那一行的说明里：“已新建片段“名字”，在面板的“片段”分类里”。
- 这个对话框算“设置或确认对话框”：打开时面板失焦不隐藏，按唤起快捷键不隐藏面板（M04 规则 3、M15 交互规则 4），截图快捷键的处理也一样（M15 交互规则 3、4）。

### 3.5 入口与快捷键

| 操作 | 入口 | 快捷键 |
| --- | --- | --- |
| 存为片段 | 历史记录右键“存为片段…”、预览头部书签按钮 | `Mod + S`（选中的是历史记录时） |
| 编辑片段 | 片段右键“编辑片段…”、预览头部铅笔、行尾快捷按钮 | `Mod + E`（选中的是片段时） |
| 新建片段 | 设置“记录”标签里的“新建片段…”、“片段”分组标题右侧按钮、空状态按钮 | `Mod + N`（面板任意分类下） |
| 多选 | “片段”分类里 `Mod` 点击切换、`Shift` 点击连选、`Shift + ↑ / ↓` 扩选 | `Mod + A` 全选（搜索框为空时） |
| 批量删除 | 多选后按删除键、右键“删除 N 个片段”、预览区“删除 N 个片段”按钮 | 同 M12 的删除键 |

- 右键菜单：
  - 历史记录：粘贴、置顶、按类型的动作、**存为片段…**、分隔线、删除；
  - 片段：粘贴、**编辑片段…**、按类型的动作、分隔线、删除。
  - 在多选中的某一条上右键时，只剩“删除 N 个片段”。
- 多选只在“片段”分类里有效。多选时列表行带勾，预览区换成“已选 N 个片段”：列出名字，下面是“删除 N 个片段”（警示色）和“取消选择”两个按钮。单击（不带修饰键）、Esc、切换分类都会退出多选。多选时复制、编辑不可用。
- 撤销：批量删除算一次删除，提示条“已删除 N 个片段”带 5 秒撤销，`Mod + Z` 一次恢复全部（M12）。单条删除照旧：“已删除片段“名字””。
- 状态栏在“片段”分类时多一条提示：`Mod 点击 多选`。

### 3.6 设置

- “记录”标签加一行“片段”：
  - 说明“搜索名字就能粘贴出对应的内容；改名、改内容与删除在面板的“片段”分类里”；
  - 按钮“新建片段…”打开 3.4 的对话框，对话框叠在设置上方，设置不关闭。
- “历史记录”一行的说明从“置顶记录会保留”改成“**置顶记录与片段会保留**”。清空确认框的条数不算片段。

### 3.7 片段不参与的东西

- 复制频谱（M14）不画片段。
- “常用”（M11）不收片段，片段也不显示“用过 N 次”的常用色。
- 片段不能置顶，`Mod + P` 对片段无效。
- 首次进入常用的提示（M11）对片段不出现。

## 4. 数据与实现

### 4.1 存储：片段是 `records` 表里的一种行

片段放在 `records` 表里，加一列区分，不另建表。

**为什么放在同一张表：** 粘贴（`flavors` 写回剪切板）、预览详情、缩略图、图中文字识别、全文索引、拼音索引、软删除与撤销，全都按 `records.id` 工作。片段放进同一张表，这些都能直接用；另建表就得把每一样都复制一遍。代价是所有“清理历史”的地方都要排除片段，靠下面的“片段按置顶存”一次解决。

- **迁移：** 往迁移数组末尾追加 `ALTER TABLE records ADD COLUMN snippet_body TEXT;`。照现有测试的写法，补一个从上一版本升级的测试。
  - 历史记录的 `snippet_body` 为 NULL；
  - 片段的 `snippet_body` 为内容摘要，也就是列表第二行的文字，由后端在入库或改内容时算好：文字类为内容首行，文件、视频为原记录的标题（文件名，多个时“名 等 N 个”）。图片存空串，由 `summary_row` 按 `meta` 里的尺寸现拼成“图片 W × H”，取不到尺寸时为“图片”；这样存片段时缩略图任务还没跑完、尺寸后补的情况也能显示对。不为 NULL 就是片段。前端只负责显示。
- **标题即名字：** 片段行的 `title` 存名字，这样现有的标题高亮、2 个字母只比标题首字母、拼音 `mark` 都直接作用在名字上（3.2）。
- **搜索文本：** 片段行的 `search_text` = 小写名字 + 换行 + **内容本身**的搜索文本，名字放在最前面。
  - “内容本身”只含 `text`、`link_title`、文件名与路径（`paths`）、`ocr_text`，**不含来源应用名和原记录的标题**。原因有两个：一是列表行不显示来源，搜“微信”时不该冒出片段；二是截图的自动标题“截图 ….png”是原记录的名字，不是内容，片段改名后旧标题不该还能搜到。
  - 在 `xpaste-core` 里加一个按这几列拼搜索文本的函数，`capture::build_record` 里对应的那几项改为调它，让两处口径一致。
  - 从历史存来的文件片段，不再带原记录读入的文本类文件内容（`search_file_text`，M05 规则 2）：这部分是复制时读的，库里没有单独存，片段里搜不到文件内容（我的决定，写进已知限制）。
  - 新建、存为片段、改名、改内容都按当前列（`title`、`text`、`link_title`、`paths`、`ocr_text`）整体重拼，不在旧文本上做替换。
  - `py_text` 用 `pinyin::index_text` 按新的 `search_text` 整体重算。名字在最前面，所以也总在拼音索引的前 4096 个字符之内。识别文字的拼音按 `set_ocr` 的做法另起一行追加，不受前 4096 个字符的限制，与历史记录一致。
- **hash 不撞历史：** `hash` 是 `NOT NULL UNIQUE`，采集靠它去重合并（`insert_or_merge`）。片段行的 hash 用 `randomblob(16)`；采集的 hash 是 32 字节，两者永远不会相同。
  - 好处：复制一段和片段内容相同的文字，会照常生成一条历史记录，不会合并进片段（反目标第 3 条）；
  - 好处：同一条历史可以存成多个片段。
- **片段按置顶存（`pinned = 1`）：** 所有自动清理和清空都经过 `LIVE_UNPINNED`（`store.rs`），条件里已经排除了置顶记录。片段在库里按置顶存，就能一次性满足反目标第 1 条，涉及的路径有：
  - `insert_or_merge` 里的容量裁剪
  - `clear_unpinned`
  - `count_unpinned`
  - `prune_retention`
  - `prune_preview`
  - `prune_capacity`

  这样做还有一个好处：用户换回旧版本时（M15 规则 6 已经把它当作真实场景），旧版本不认识 `snippet_body`，但同样跳过置顶，片段也不会被它清掉。旧版本里片段会显示成一条置顶的历史，标题是名字。

  对外则始终把片段当作“不是置顶”，需要改的地方有：
  - `summary_row` 给前端的 `pinned` 为 `pinned && snippet_body IS NULL`；
  - `set_pinned` 对片段返回错误；
  - `bump_use` 对片段总是更新 `copied_at`（片段的“上次使用”）；
  - 前端按 `snippetBody` 判断是否是片段，不看 `pinned`。

  每条清理路径都要有测试：放一条片段进去，确认它不被删、不被计数。“最多保存 N 条”只算历史记录。
- **软删除彻底清除**（`purge_all_soft_deleted` 和定时 purge）照旧作用于片段：用户删了片段、5 秒没撤销，就该真删。

### 4.2 Store 接口（`crates/xpaste-core/src/store.rs`，名字由实现定）

1. **从历史复制出一条片段**（`id`、名字、当前时间）→ 新 id：
   - 在一个事务里复制 `records` 行：新 hash、`title` = 名字、`snippet_body` 按 4.1 规则算、`search_text` 和 `py_text` 按 4.1 规则重算、`uses` = 0、`pinned` = 1、`copied_at` = 当前时间、`deleted_at` = NULL。`kind`、`text`、`paths`、`link_title`、`lang`、`size`、`meta`、`ocr_text`、`ocr_state`、`app_id` 原样带过去。
   - 原记录的缩略图、视频封面或图中文字识别还没做完时（`thumbs/` 下没有文件，或 `ocr_state` 是待识别），给新 id 也投一次后台任务（`enrich.rs`、`ocr.rs`），不然片段会一直没有缩略图或识别文字。
   - 复制 `flavors` 行。
   - **复制文件：**
     - `blobs/<旧 id>/` → `blobs/<新 id>/`，同时改 `flavors.file` 里的路径；
     - `images/<旧 id>.png`、`thumbs/<旧 id>.png` 有就复制。

     文件最后写，失败时回滚事务、删掉已经写出的文件，与 `insert_or_merge` 的做法一致。片段从此不依赖原记录（反目标第 2 条）。
   - 文件记录的 `paths` 指向用户自己的文件，不复制。文件不在时粘贴照旧报“文件已不存在”（M09）。
   - 原记录已软删除或不存在时返回错误。
2. **新建文字片段**（名字、内容、当前时间）→ 新 id：
   - 用 `text_flavor`（现在在 `src-tauri` 的 `commands/records.rs`，按需要挪到能共用的地方）造一个只有纯文本的快照，经 `detect::kind` 与 `capture::build_record` 得到类型、标题、语言、搜索文本，再按 4.1 的片段规则入库。
   - 不做容量裁剪，也不走 hash 合并。
3. **改片段**（`id`、名字、可选的新内容）：
   - 只改名：改 `title`，按 4.1 重拼 `search_text` 与 `py_text`。
   - 改内容（只允许文字类片段）：按第 2 条的方式重建类型、标题、语言、搜索文本、`snippet_body`，`flavors` 换成单个纯文本 flavor。原来从历史带来的富文本格式（HTML、RTF）不再保留，改过内容的片段粘贴出去就是纯文本（我的决定，写进已知限制）。`uses`、`copied_at` 不变。
   - 不是片段，或者是非文字类片段却改内容时，返回错误。
4. **批量软删除 / 批量撤销：** `soft_delete` 与 `undo_delete` 改成接收 id 列表，在一个事务里执行。单条删除也走这两个接口（传一个 id 的列表）。

`bump_use`：粘贴片段时使用次数 +1，`copied_at` 总是更新为现在（片段的“上次使用”），不受“复制后移到顶部”开关和 `pinned = 1` 的影响，由 SQL 按 `snippet_body` 判断。

### 4.3 模型与命令

- `RecordSummary` 加 `snippet_body: Option<String>`（前端 `snippetBody: string | null`），`SUMMARY_SQL` 带上这一列。同步改 `src/api/types.ts`。
- 新命令，放在 `commands/records.rs` 或新建的 `commands/snippets.rs`，并在 `src/api/commands.ts` 里封装：
  - `save_snippet(id, name)`：存为片段，发 `record-added`。
  - `create_snippet(name, text)`：新建，发 `record-added`。
  - `update_snippet(id, name, text?)`：改片段，发 `record-updated`。
- `delete` 与 `undo_delete` 改为接收 `ids`：
  - `schedule_purge` 每个 id 照旧排一次；
  - `emit_removed` 一次发全部 id；
  - 撤销时每条恢复的记录发一次 `record-added`。
- 名字、内容校验在命令里再做一遍，不信任前端：名字去空白后非空且不超过 100 个字符，内容非空；不合法时返回 `AppError::Invalid`，带中文提示。
- **日志：** 只记 id、类型和字节数，例如 `片段 新建 id=… kind=Code bytes=…`、`片段 删除 n=3`。不能记名字和内容（横切约束）。
