# 阶段 8：发布准备 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `make release` 在无界面环境下产出未签名的 `.dmg` 与中文 NSIS 安装程序（卸载可选删除数据），CI 两端跑通并上传安装包；用可重复的脚本在正式构建上测完规格说明 5.1 的全部性能指标、断网与崩溃恢复，结果写进验收记录；README 写清安装、快捷键、权限、签名步骤与已知限制。

**Architecture:** 不加功能、不加依赖。代码改动只有两处：唤起计时从“仅开发构建”改为由环境变量 `XPASTE_TIMING` 开启（两种构建同一套），并顺带记录搜索耗时；其余是配置（`tauri.windows.conf.json` + NSIS 钩子）、Makefile / CI、一个核心层示例程序 `seed`（造隔离数据）和一个测量脚本 `scripts/measure.sh`（macOS，用户离开电脑时运行），最后是文档。

**Tech Stack:** Tauri 2 bundler（dmg、NSIS `installerHooks`）、GitHub Actions、bash + macOS 自带工具（`osascript`、`sqlite3`、`lsof`、`footprint`、`ps`、`ioreg`、`perl`）、Rust example。

**Spec:** [docs/specs/2026-10-18-xPaste-实现设计.md](../specs/2026-10-18-xPaste-实现设计.md) §1（本期不做：自动更新、加密）、§2 回写项 4（Windows 卸载删除数据）、§7.1（平台配置文件）、§11（不联网，断网 + 抓包验收）、§12（版本号唯一来源；签名证书由产品负责人提供，之前只出未签名包）、§13（CI 矩阵与步骤；性能测量方法）、§14 阶段 7 行的“打包并记录体积”、§15。规格说明 5.1、5.2、5.3、5.5，AC-M03-04/05、AC-M04-07、AC-M05-06、AC-M08-06、AC-M16-04。

- 实现者与审查者子代理一律用 opus。只在 `dev`（或上面的 worktree 分支）提交，**不推送**；合并到 `main` 只在用户验收后由用户决定。
- 提交只按路径暂存（禁止 `git add -A` / `git add .` / `git commit -a`）：工作区有用户未跟踪的 `docs/brand/ip/`。
- **测量与验收运行规则**（每份派单都写明）：开发版只用 `make dev-isolated`；正式构建只用 `scripts/measure.sh` 启动（它把 `XPASTE_DATA_DIR` 指到 `mktemp -d` 的目录）；禁止 `make dev`、禁止打开安装好的正式版做测试；结束进程只许 `kill <自己记下的 PID>`，禁止 `pkill` / `killall` / 按名字结束；不得读取、复制或修改 `~/Library/Application Support/xPaste/`。测量用的剪切板内容只用自造字符串（`xpaste 测量 …`）。

- 标“用户”的步骤子代理做不了（加远程仓库并推送、Windows 实机、`sudo` 抓包、高速摄像、断网安装、重启系统），写进验收记录的待测行，带完整命令与预期。
- 不做：签名与公证（只写步骤）、自动更新、数据库加密、P2。

## Global Constraints

- 本期安装包不签名、不公证（设计 §12）；不接 `tauri-plugin-updater`，托盘不放“检查更新…”（设计 §1）。
- 平台配置：`tauri.macos.conf.json` = `bundle.targets: ["dmg"]`、`bundle.macOS.minimumSystemVersion: "13.0"`；`tauri.windows.conf.json` = `bundle.targets: ["nsis"]`、`bundle.windows.nsis.installMode: "currentUser"`（设计 §7.1），本阶段只在后者追加 `languages`、`installerHooks`。
- 版本号唯一来源 `package.json`（当前 `0.1.0`），`tauri.conf.json` 用 `"version": "../package.json"`，`pnpm check:version` 检查 Cargo 一致（设计 §12）。本阶段不改版本号。
- 性能目标照抄规格说明 5.1：冷启动到开始记录 ≤ 2 秒；唤起面板到可输入 ≤ 100 ms；复制到出现在历史中 ≤ 1 秒；搜索更新（5000 条）≤ 50 ms；后台空闲 CPU < 1%；后台常驻内存 ≤ 150 MB。空闲按“空闲 10 分钟后”读数，WebView 子进程计入（设计 §13）。
- 不联网（设计 §11）：不新增任何会发网络请求的依赖或资源；CSP 不放外部来源。
- 日志不写剪切板内容、标题、路径、搜索词。本阶段新增日志只有三行格式：`唤起计时已由 XPASTE_TIMING 开启`、`唤起耗时 N ms`、`搜索耗时 N ms，命中 N 条`。
- 用户可见文案为简体中文（规格说明 5.6），安装 / 卸载界面同样。
- 不新增运行时依赖；脚本只用 macOS 自带工具和仓库已有工具链。
- 每个任务结束 `make check` 必须通过（含 `cargo clippy -p xpaste-platform --target x86_64-pc-windows-msvc`）。

## Review Focus

1. 种子目录交给正式版启动时，启动清理按保留时长 30 天、最多 500 条删掉记录，测到的就不是 5000 条 → Task 4 `seed` 写入 `maxRecords = 5000`、`copied_at` 落在最近 7 天内；冒烟运行断言日志 `bootstrap 返回 5000 条记录`。
2. 正式构建在测量中出现引导或保存设置会改系统登录项（开发构建才有保护），用户的正式版同时持有 `⌘ ⇧ V` 会让按键两边都响应 → `seed` 写 kv `onboarded = 1`；脚本启动前 `pgrep -x xPaste` 非空即退出；Task 4 冒烟断言日志里没有 `设置已保存`、`~/Library/LaunchAgents/` 没有新增 xPaste 的 plist、真实数据库修改时间不变。
3. `XPASTE_TIMING` 为空串或只有空白时不得开启计时；未设置时正式版日志不出现任何计时行 → Task 3 `timing_enabled_only_when_non_empty`，Step 4 对未设置时的日志 grep。
4. 当前输入法是拼音时，`osascript keystroke "a"` 进入输入法候选，`input` 事件带 `isComposing`，搜索根本不触发，测到的是空集 → Task 4 搜索测量只用数字，并且用 `key code` 发送；冒烟断言 `搜索耗时` 行数 ≥ 发出的按键数。
5. Windows 覆盖安装（升级）或卸载时不勾选“删除应用程序数据”，`%APPDATA%\xPaste` 必须保留；勾选才删 → Task 2 钩子条件 `$DeleteAppDataCheckboxState = 1` 且 `$UpdateMode <> 1`；Task 2 Step 3 的三种情况写成 Windows 待测行（勾选、不勾选、覆盖安装），CI 打包（只在 `main` 推送或手动触发时运行）通过只证明钩子能编译。

### Task 2: Windows 安装程序：中文界面与卸载时删除数据（合并前即可做）

**Files:**
- Modify: `src-tauri/tauri.windows.conf.json`（`bundle.windows.nsis` 追加 `"languages": ["SimpChinese"]`、`"installerHooks": "./windows/hooks.nsh"`）
- Create: `src-tauri/windows/hooks.nsh`

**Interfaces:**
- 背景：Tauri NSIS 卸载程序自带“删除应用程序数据”勾选框，勾选时删除的是 `$APPDATA\com.xpaste.app` 与 `$LOCALAPPDATA\com.xpaste.app`（后者含 WebView2 数据）；xPaste 的数据目录是 `%APPDATA%\xPaste\`（规格说明 M03 规则 1），默认行为删不到，所以需要钩子。
- `hooks.nsh` 只定义 `NSIS_HOOK_POSTUNINSTALL`，内容固定为：

```nsh
!macro NSIS_HOOK_POSTUNINSTALL
  ; 开机启动项（tauri-plugin-autostart → auto-launch，值名为 productName）
  DeleteRegValue HKCU "Software\Microsoft\Windows\CurrentVersion\Run" "xPaste"
  DeleteRegValue HKCU "Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run" "xPaste"
  ${If} $DeleteAppDataCheckboxState = 1
  ${AndIf} $UpdateMode <> 1
    SetShellVarContext current
    RMDir /r "$APPDATA\xPaste"
  ${EndIf}
!macroend
```

- [ ] **Step 1: 写配置与钩子**；用 `node_modules/@tauri-apps/cli/config.schema.json` 核对两个键名与类型（`languages: string[]`、`installerHooks: string | null`），并在 Tauri 的 NSIS 模板源码（`@tauri-apps/cli` 自带或 tauri-bundler 仓库同版本）里确认变量名 `$DeleteAppDataCheckboxState`、`$UpdateMode` 存在；不一致时按源码改名并在报告写明。
- [ ] **Step 2: 验证** — `make check`（macOS 上不会打 NSIS，此步只保证没碰坏别的）；`dev` 的推送不打包，所以由用户在 GitHub Actions 页面对 `dev` 手动触发一次 CI（`workflow_dispatch`，或 `gh workflow run CI --ref dev`）：Windows 的 `make release` 产出 `target/release/bundle/nsis/xPaste_0.1.0_x64-setup.exe`，产物 `xpaste-windows-latest` 可下载（钩子编译通过的唯一证据，Task 2 的验收以此为准）。
- [ ] **Step 3: 写 Windows 待测行**（`docs/验收记录.md` 逐项记录，平台 Windows）：`阶段8-T2-a`：安装界面为中文，安装不弹 UAC，装到 `%LOCALAPPDATA%\xPaste`；`阶段8-T2-b`：开启开机启动后卸载、不勾选“删除应用程序数据”→ `%APPDATA%\xPaste` 仍在，`reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v xPaste` 找不到；`阶段8-T2-c`：重装后卸载并勾选 → `%APPDATA%\xPaste` 与 `%LOCALAPPDATA%\com.xpaste.app` 都不存在（规格说明 5.2.4）；`阶段8-T2-d`：已安装时运行同版本或新版本安装程序覆盖安装 → 历史记录保留。

### Task 3: 正式构建可开启的唤起与搜索计时（合并后）

**Files:**

### Task 4: 种子数据与测量脚本（合并后，依赖 Task 3）

**Files:**
- Create: `crates/xpaste-core/examples/seed.rs`
- Create: `scripts/measure.sh`
- Modify: `Makefile`（`.PHONY` 与新目标 `measure`）

**Interfaces:**
- Consumes：`Store::open(dir)`、`Store::save_settings(&Settings)`、`Store::kv_set("onboarded", "1")`、`Store::insert_or_merge(&NewRecord, now_ms, max_records)`、`detect::kind(&Snapshot)`、`capture::build_record(snapshot, kind, now_ms)`；Task 3 的三种日志行。
- Produces：
  - `cargo run -p xpaste-core --release --example seed -- <dir> <n>`：`std::fs::create_dir(dir)`（不是 `create_dir_all`；目录已存在就报错退出，这就是“不会写进已有数据目录”的保护）→ `Store::open` → `Settings { max_records: 5000, ..Default::default() }` 保存 → kv `onboarded = 1` → 写 `n` 条（`n` 可以为 0，用于空库测量）。第 `i` 条（从 0 起）按 `i % 4` 取 `xpaste 测量 {i:05} 文本`、`https://example.com/xpaste/{i:05}`、`fn seed_{i:05}() {{ let x = {i}; }}`、`#{:06x}`（`i * 2654435761 % 0xFFFFFF`），每 10 条有一条在文本后补 2 KB 的 `xpaste 测量 ` 重复串；`now_ms` 为当前时间减 `i * 120_000`（5000 条跨约 7 天，在默认 30 天保留期内）；`source` 为空。结束打印 `已写入 N 条，用时 M ms`。种子记录不带 flavor，只用于搜索、启动与内存测量，不用于复制。
  - `scripts/measure.sh <startup|latency|summon|search|crash|idle|all>`，macOS 专用。可覆盖的环境变量：`APP`（默认 `target/release/bundle/macos/xPaste.app/Contents/MacOS/xPaste`）。结果写 `target/measure/<YYYYmmdd-HHMMSS>.txt` 并同时输出到终端；每项汇总一行 `结果 <项目> n=<n> 中位数=<v> 最大=<v> 目标=<v> 达标=<是|否>`，之后附原始样本。
  - 公共前置（每个子命令都做）：不是 macOS、`$APP` 不存在、`pgrep -x xPaste` 有输出 → 打印原因退出（`检测到正在运行的 xPaste，请先从菜单栏退出`）；记下真实库 `~/Library/Application Support/xPaste/xpaste.db` 的修改时间（不存在则跳过），结束时比较并输出 `真实数据库未改动` 或失败；`pbpaste` 保存当前文本剪切板，`trap EXIT` 里恢复、`kill` 自己记下的 PID、删除 `mktemp -d` 的根目录、关闭脚本打开的文本编辑文稿（不保存）。启动被测程序统一为 `XPASTE_DATA_DIR=<副本> XPASTE_TIMING=1 "$APP" &`，记 `$!`；每个子命令结束时 `kill` 该 PID 并 `wait`，确认无残留后才进行下一项。启动后 5 秒内新出现的 `com.apple.WebKit` 进程（启动前后 `pgrep -f com.apple.WebKit` 的差集）算作它的 WebView 子进程。运行期间每 2 秒 `lsof -nP -i -a -p <主进程与 WebKit 子进程>`，行数累计到 `结果 网络连接 次数=<n> 目标=0`。
  - 需要按键的子命令（`summon`、`search`、`crash`）开始前要求 `HIDIdleTime` ≥ 20 秒，否则退出（`请在离开电脑时运行`）；先 `open -a TextEdit` 新建空白文稿，每批按键前确认前台进程是“文本编辑”，否则中止。按键一律 `key code`：`⌘ ⇧ V` = `key code 9 using {command down, shift down}`，数字 0–9 = `29 18 19 20 21 23 22 26 28 25`，退格 `51`，Enter `36`，`⌘ P` = `key code 35 using {command down}`。毫秒时间戳用 `perl -MTime::HiRes=time -e 'printf "%d\n", time*1000'`。
  - 各子命令（数据目录都是种子目录的 `cp -R` 副本，每次运行一份新的）：
    - `startup`：空库与 5000 条各 5 次。记启动时刻，之后每 100 ms `pbcopy` 一条新的 `xpaste 测量 启动 <轮次> <序号>`，直到 `sqlite3 <db> 'select count(*) from records'` 大于基线；差值为一次样本。目标 2000 ms。
    - `latency`：5000 条，面板隐藏，10 次：`pbcopy` 新串的时刻 → 每 50 ms 查到记录数 +1 的时刻。目标 1000 ms。
    - `summon`：5000 条，等日志出现 `bootstrap 返回 5000 条记录`；1 次预热 + 20 次：`⌘ ⇧ V` 唤起、等 600 ms、再按一次隐藏、等 600 ms；从日志取 `唤起耗时 N ms`。预热单列；汇总行输出中位数、p95（20 个样本排序后第 19 个）与最大值，`达标=是` 当且仅当最大值 ≤ 100 ms；最大值超标而中位数与 p95 都 ≤ 100 ms 时输出 `达标=部分`。目标 100 ms。
    - `search`：5000 条，唤起后依次键入 `0`、`0`、`4`、`2` 再退格 4 次，每键间隔 200 ms，共 3 轮；从日志取 `搜索耗时`。判定用最大值，目标 50 ms；同时检查样本数 ≥ 24。
    - `crash`：空库。`pbcopy` 3 条（间隔 1 秒）→ 记录数为 3 → `kill -9` → 重新启动 → 日志 `bootstrap 返回 3 条记录`、`sqlite3 <db> 'pragma integrity_check'` 为 `ok`（AC-M03-04）。接着唤起、`⌘ P` 置顶第一条、Enter 复制它（未授权辅助功能时只复制，`uses` 照样 +1）、隐藏；导出 `select id, pinned, uses, copied_at from records order by id` → `kill -TERM` → 重新启动 → 再导出，两次一致（AC-M03-05 的自动部分）。
    - `idle`：5000 条，唤起一次并隐藏，空闲 600 秒后每 10 秒采样一次、共 6 次：`ps -o pid=,rss=,pcpu= -p <主进程 PID>,<WebKit PID>,…`（RSS 单位 KB）与 `footprint --noCategories -f bytes -p <主进程 PID> -p <WebKit PID> …`（取每个进程的 `Footprint:` 行，字节）的合计。分别汇总 `内存(footprint)`、`内存(RSS)`、`CPU`；判定内存用 footprint 合计（活动监视器“内存”列的口径）≤ 150 MB，CPU 用 6 次中最大的合计 < 1%。
    - `all`：依次 `startup latency summon search crash idle`，约 15 分钟。
  - `make measure` 帮助文案：`macOS 性能与可靠性测量（先 make release-app；离开电脑时运行，约 15 分钟）`，命令 `bash scripts/measure.sh all`。

## 自查记录

- **正式构建怎么开计时**：选环境变量 `XPASTE_TIMING`，不选 cargo feature，也不选一直开。feature 要另编一个二进制，测的就不是发出去的那个；一直开会让每次唤起和每次按键都往用户日志里写一行。环境变量与 `XPASTE_DATA_DIR` 同一口径，测量时两个一起设；`make dev-isolated` 默认开启，开发时的唤起日志不丢。代价是删掉了 `cfg(debug_assertions)` 的保护，正式版多编译一个时间戳函数。
- 计时取第一个动画帧回调，比真正上屏早至多一帧，与阶段 1–5 的数据同口径，便于对比；真值用高速摄像补，这一项写成用户待测。
- 搜索计时放在前端从 `input` 到渲染后，包含 IPC 和后端 `search_ids`，这才是 AC-M05-06 的“每次更新”；不单测后端查询。
- 5000 条数据用核心层 example 写库，而不是 `pbcopy` 5000 次（太慢，而且一直占着用户的剪切板）或者 `sqlite3` 直接插表（绕过 `build_record`，表结构一变就悄悄写错）。“不写进已有目录”靠 `create_dir` 遇到已存在就失败，不另写路径判断。
- 种子必须写 `maxRecords = 5000`、`onboarded = 1`，`copied_at` 落在 7 天内：否则正式版一启动就按默认值清理，或者弹出引导，引导“完成”会让正式构建改系统登录项。
- **内存口径**：阶段 1 的 RSS 合计 174 MB 超过 150 MB，物理内存占用约 60 MB。设计 §13 写的是“活动监视器读数”，活动监视器“内存”列就是 phys_footprint，所以判定用 `footprint`，RSS 照记并在测量摘要里说明差别（控制者已确认此口径）。
- 唤起判定（控制者裁定）：1 次预热单列，20 次的最大值 ≤ 100 ms 才算通过；最大值超标但中位数与 p95 都达标时记“部分”，写出三个数并上报控制者，不算静默通过也不算静默失败。阶段 5 的 debug 数据里有 106、116 ms，正式构建应当更快；不达标时先上报，不在测量任务里改实现。
- “冷启动”在脚本里其实是热启动（二进制已在页缓存中）；真正的冷启动要重启系统，写成用户待测。“复制到出现在历史中”测到入库为止，不含界面渲染，因为面板隐藏时界面不渲染，打开时会重新拉数据（设计 8.4）。
- WebKit 子进程的父进程是 launchd，只能按“启动后新出现”来归属。用户的 Safari 若恰好同时新开进程会被多算，所以要求在用户离开时运行，并且只会让结果偏大，不会偏小。
- 断网：自动化部分用 `lsof` 采样（不需要 sudo），覆盖主进程与 WebKit 网络进程；`tcpdump -k`（pktap 带进程信息）要 sudo，写成用户步骤。断网时连接请求在本机就失败、抓不到包，所以抓包要在联网时做，断网另测功能是否正常。静态检查只做一次，不放进 `make check`：CSP 已经在 WebView 里挡住外部来源，后端正常依赖里没有 HTTP 客户端（`cargo tree -i reqwest -e normal` 为空）。
- AC-M03-05 的“退出”在脚本里用 `SIGTERM`（托盘菜单点不到），托盘退出留给用户。规格说明 5.3.3 的“崩溃后自动恢复（开机启动项保持）”理解为数据不丢加上登录项还在，不做 launchd `KeepAlive` 守护：那是新功能。
- dmg：用 `CI=true` 让 Tauri 自己加 `--skip-jenkins`，不必在 Makefile 里重写一遍 `bundle_dmg.sh` 的参数；丢掉的只有 Finder 里图标摆位，没有签名的包这一步本来就不重要。CI 的 macOS runner 自带 `CI=true`，本地与流水线因此一致。
- NSIS：Tauri 自带的“删除应用程序数据”只删 bundle id 命名的目录，删不到 `%APPDATA%\xPaste`，钩子补上；`$UpdateMode` 保证覆盖安装不删。开机启动的注册表值卸载时一律删除，否则卸载后登录会弹“找不到文件”。安装界面语言只放 `SimpChinese`，不显示语言选择。
- CI 不拆第二个 job：打包放在同一 job 末尾，只在推送到 `main` 与手动触发时运行（控制者裁定，省 CI 时间），缓存共用；代价是 NSIS 钩子在 `dev` 上不会自动编译，Task 2 的验收要用户手动触发一次。Windows runner 是否自带 `make` 不确定，用 `command -v make || choco install make` 兜底。Node 改 25 与开发机一致（Node 24 也能剥离类型，但本地从没用 24 跑过）。
- Windows 的测量没有脚本：子代理跑不了 Windows，`seed` 示例和 `XPASTE_TIMING` 两端通用，剩下的是任务管理器读数，写成步骤比写一个没人验证过的 PowerShell 脚本可靠。
- 设计 §14 现在把发布准备写在阶段 7 行。拆行由本计划 Task 6 负责（控制者裁定）：阶段 7 的计划只能在自己那一行追加状态文字，不得改表结构。
- 测量运行直接启动正式二进制并设置 `XPASTE_DATA_DIR`，依赖隔离模式的两个行为：不注册单实例（否则会与用户的正式版互相切换，或被它挡住直接退出）；对隔离目录的 `images/`、`thumbs/`、`icons/` 调 `allow_directory` 放宽 asset 作用域（设计 §13）。这两点任何一个被改掉，`measure.sh` 就会失效或误触真实实例。
