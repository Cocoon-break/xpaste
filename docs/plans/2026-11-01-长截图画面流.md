# 长截图画面流（阶段 0、1）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 长截图改用系统推送的区域画面流（macOS ScreenCaptureKit、Windows 11 Windows.Graphics.Capture，Windows 10 与出错时回退到逐帧截屏），并把排查用的逐帧存图与离线重放工具放进仓库。

**Architecture:** 平台层新增与平台无关的 `stream.rs`：只保留最新一帧的槽位 `Latest`、对外的 `AreaStream` 与逐帧截屏回退；两个平台各自实现“原生画面流”，往同一个槽位里放帧。`longshot.rs` 的截屏循环改为从 `AreaStream` 取帧，拼接（`xpaste_core::stitch`）不变。离线重放做成 `xpaste-core` 的 example 与回归测试。

**Tech Stack:** Rust、objc2-screen-capture-kit 0.3、windows 0.62（WinRT Graphics.Capture、D3D11）、image 0.25。

**Spec:** [长截图自动滚动设计](../specs/2026-11-01-长截图自动滚动-设计.md) 第 4.2 节、第 6 节阶段 0、1；规格说明 M23 规则 13。

## Global Constraints

- 日志不能出现画面内容、窗口标题、路径；只记尺寸、帧数、耗时、没接上的帧数（CLAUDE.md 横切约束、M23 规则 11）。
- 运行应用只用 `make dev-isolated`。提交前 `make check`（含 `x86_64-pc-windows-msvc` 交叉 clippy，必须装上 target）。
- 代码注释、日志、提交信息用中文，注释引用规格编号（M23 规则 13）。
- 第一帧仍按 `longshot::settled`（连续两帧相同，最多 0.6 秒）。
- 画面流帧率上限 60 帧/秒；帧到达快于处理时只保留最新一帧，不积压。
- 画面流输出 RGBA、sRGB、非预乘、行紧密排列，尺寸与 `capture_rect` 对同一区域的输出一致（宽 = round(w × scale)，高 = round(h × scale)），否则拼接会把帧当成尺寸变了而跳过。
- xPaste 自己的窗口（长截图边框、提示、预览）不进入画面：macOS 用 `SCContentFilter` 排除边框窗口编号，Windows 依赖边框已有的 `WDA_EXCLUDEFROMCAPTURE`。
- Windows 10（build < 20348）不用 Windows.Graphics.Capture（系统强制黄色边框），走逐帧截屏回退。
- 逐帧存图只在开发构建（`cfg!(debug_assertions)`）且设了 `XPASTE_LONG_DUMP=<目录>` 时生效。仓库里的回归帧不含个人内容（不放用户的壁纸、终端内容），每组几 MB 以内，不用 Git LFS。

## Review Focus

- 选区在副屏、两块屏缩放不同：画面流的源区域按该屏的本地坐标换算，帧尺寸与 `capture_rect` 一致（Task 4 的集成测试只能测主屏，副屏写进验收记录的待验收项）。
- 长截图中途拔掉显示器、改分辨率、撤销屏幕录制权限：画面流停止，`next` 不再出帧，`failed()` 为真；长截图按“完成”收尾、保留已拼好的部分并在日志里记一条警告，不卡住（Task 3、Task 6 的测试）。
- 画面不动时系统不推新帧：`next` 超时返回 `None`，不算没接上；回车、Esc 在 200 ms 内生效（Task 2、Task 6 的测试）。
- 处理慢于来帧：只拿最新一帧（Task 2 的测试）。
- 启动原生画面流失败（权限刚授予、系统接口报错）：自动回退到逐帧截屏并记一条日志，长截图照常进行（Task 3 的测试）。

**Interfaces:**

  ```rust
  pub struct StreamFrame { pub w: u32, pub h: u32, pub rgba: Vec<u8> }
  pub struct AreaOptions {
      /// 同 RecordOptions::display（macOS CGDirectDisplayID，Windows 显示器序号）
      pub display: u32,
      /// 显示器内的点：x, y, w, h（同 RecordOptions::rect）

      /// 同一区域的原生坐标（同 capture_rect），逐帧截屏回退用

  }
  pub(crate) struct Latest { /* Mutex<(u64 序号, Option<StreamFrame>, bool 已失败)> + Condvar */ }
  impl Latest {
      pub(crate) fn new() -> Arc<Self>;
      pub(crate) fn push(&self, f: StreamFrame);   // 覆盖旧帧，序号加一，唤醒等待者
      pub(crate) fn fail(&self);                    // 标记失败并唤醒
  }
  pub struct AreaStream { latest: Arc<Latest>, taken: Cell<u64>, stop: Option<Box<dyn FnOnce() + Send>>, pub(crate) mode: &'static str }
  impl AreaStream {
      pub(crate) fn new(latest: Arc<Latest>, stop: Box<dyn FnOnce() + Send>, mode: &'static str) -> Self;
      /// 等一帧比上次取走的更新的画面（中间的帧丢掉），最多等 `timeout`；超时或已失败为 None
      pub fn next(&self, timeout: Duration) -> Option<StreamFrame>;
      pub fn failed(&self) -> bool;
      /// 日志用："画面流" | "逐帧"
      pub fn mode(&self) -> &'static str;
      pub fn stop(self);   // 调用 stop 闭包；Drop 时也调用一次（只调一次）
  }
  ```
