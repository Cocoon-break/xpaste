# 阶段 2：采集与存储（macOS） 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把阶段 1 的"监听到变化、打一行日志"变成完整的采集链路：类型识别、去重、SQLite 存储、清理、软删除、设置持久化，以及 macOS 上读取全部剪切板格式、写回、应用图标与缩略图补全；前端用一个临时列表把记录显示出来，以便验收 AC-M01、M02、M03。

**Architecture:** 核心层 `xpaste-core` 新增 `detect`（类型识别与哈希）、`capture`（字段计算与采集流水线）、`store`（rusqlite，单连接）三个模块，全部纯逻辑、内存 SQLite 可测。平台层 macOS 的 `read_snapshot` 扩成读全部 item 的全部 UTI 数据、文件引用、位图转 PNG、链接标题，新增 `write(flavors)` 与 `app_icon`。应用层把 `Store` 放进 `AppState`，监听回调改为调用 `capture::process`，补全线程用 `mpsc` 队列生成缩略图和图标，命令层补齐记录相关命令，事件 `record-added / record-updated / records-removed` 驱动前端。Windows 平台层本阶段不动（阶段 6）。

**Tech Stack:** rusqlite 0.40（bundled）、sha2 0.11、image 0.25（png/jpeg/bmp/tiff/gif/webp）、serde_json、objc2-app-kit 0.3（NSPasteboardItem、NSBitmapImageRep、NSWorkspace、NSImage）、Tauri asset 协议。

**Spec:** [docs/specs/2026-10-18-xPaste-实现设计.md](../specs/2026-10-18-xPaste-实现设计.md) §3.2、§5 全部、§6（macOS 列）、§8.2–8.4、§11、§12、§13；阶段表第 2 行。规格说明 M01、M02、M03、M11（使用次数）、M12（删除与撤销的存储部分）。

## Global Constraints

- 核心层 `xpaste-core` 不依赖 tauri、不依赖系统接口；任何平台 `cargo test -p xpaste-core` 可运行。
- 访问数据库或剪切板的命令一律 `#[tauri::command(async)]`；数据库连接是 `AppState` 中的 `Mutex<Store>`，锁内无 `await`。
- 日志与事件只允许记录 id、类型、字节数、耗时、来源应用名、是否敏感；**不写内容、标题、路径**（`Snapshot`/`Record` 的 `Debug` 已脱敏；新类型同样处理）。
- 数据目录：`data_dir()/xPaste/`（不是 `app_data_dir()`）；子目录 `blobs/`、`images/`、`thumbs/`、`icons/`、`logs/`。
- 单条上限：纯文本 > 5 MB、位图 > 50 MB 不记录；单个格式 > 50 MB 跳过该格式不放弃整条；`flavors.data` ≤ 1 MB 入库，否则存 `blobs/<record_id>/<序号>`。
- 哈希：SHA-256，规范化前缀 `files\n` / `bitmap\n` / `text\n`（设计 5.4）。
- 常用阈值 3；首次复制 `uses = 0`，重复使用 +1。
- 保留时长 7 / 30 / 90 / 永久（`None`），默认 30；最多条数 50–5000 步长 50，默认 500；置顶记录不受清理影响。
- 软删除 5 秒后彻底删除；启动时清除残留软删除；记录删除时连带删除其 `blobs/`、`images/`、`thumbs/` 文件。
- 事件名 kebab-case，Rust 与 `src/api/events.ts` 各一份常量；类型字段 camelCase，`src/api/types.ts` 与 Rust 一一对应。
- `@tauri-apps/*` 只能在 `src/api/` 下 import；前端新增纯逻辑放独立文件并配 `*.test.ts`（`pnpm test` 自动发现）。
- 每个任务结束 `make check` 必须通过（含 Windows 交叉 clippy）。

## Review Focus

1. 剪切板里只有私有格式、没有文本/文件/位图（例如从某些应用复制对象）时，不能产生一条空记录 → Task 5 的 `skips_snapshot_without_presentable_content`。
2. 同一内容先以文件引用复制、再以纯文本复制同一路径字符串时，两者不能被去重合并（前缀隔离） → Task 2 的 `hash_prefix_separates_kinds`。
3. 写入 `records` 成功但写 `flavors` 失败时必须整体回滚，不能留下没有原始数据的记录 → Task 4 的 `insert_is_atomic`。
4. `kv` 里的设置 JSON 损坏（非法 JSON）时应用要能启动并回退默认值，而不是 panic → Task 1 的 `corrupt_settings_fall_back_to_default`。
5. 把"最多保存"从 500 改到 50 时，必须先经 `prune_preview` 报告将删除条数，`save_settings` 才执行删除；置顶记录不计入也不删除 → Task 4 的 `prune_preview_counts_only_unpinned_overflow` 与 Task 7 手动用例 AC-M03-02 变体。

  - `pub fn build_record(snapshot: Snapshot, kind: Kind, now_ms: i64) -> NewRecord`，字段规则为设计 5.3：
    - `title`：文本第一个非空行截 200 字符（按 char）；链接 `link_title` 否则 URL；颜色大写 HEX；文件类第一个文件名，多个时 `"{name} 等 {n} 个"`；位图 `截图 YYYY-MM-DD HH.mm.png`（本地时间，用 `now_ms` 换算，不引入 chrono：实现 `fn local_stamp(ms) -> String`，允许先用 UTC 并在报告中注明——见自查记录）。

    - `link_title`：`snapshot.url_title` → HTML 恰为单个 `<a href="同一 URL">标题</a>` 时的文字 → None。
    - `search_text`：`text`、`link_title`、所有文件名和完整路径、来源应用名，用 `\n` 连接后 `to_lowercase()`。
    - `lang`：`kind == Code` 时 `detect::lang(text)`。
    - `meta`：位图时 `{"w":..,"h":..}` 由补全线程填，这里为 None。

  - `Record*` 的 `Debug` 脱敏（title/text/paths 不输出）。
- Produces（`store.rs`）：
