# 阶段 14 片段 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 支持片段（名字 + 内容）：可以在设置里新建，也可以把历史记录存成片段；按名字或内容搜索，回车粘贴出来的是内容；片段在面板里改名、改内容、单条或批量删除；任何自动清理都不会删到片段。

**架构：** 片段就是 `records` 表里的行：
- 新增一列 `snippet_body`，不为 NULL 的就是片段；`title` 存名字；
- `hash` 用随机值，不与采集的记录合并；
- 库里按 `pinned = 1` 存，所有清理路径已经跳过置顶，因此自动豁免，对外再把它报成非置顶。

粘贴、预览、缩略图、图中文字识别、全文和拼音索引、软删除与撤销都照用现有代码。前端多一个“片段”分类，多一个片段对话框，并支持多选。

**技术栈：** Rust（rusqlite + FTS5）、Tauri 2、原生 TypeScript（Node 原生测试）。

**规格：** `docs/specs/2026-10-29-片段-设计.md`（下文称“设计”）。交互对照 `docs/specs/2026-10-29-片段-原型.html`。

## 全局约束

- 日志里不能出现片段的名字和内容，只记 id、类型、字节数、条数（CLAUDE.md 横切约束）。
- 代码注释引用规格编号。M25 在 Task 6 才写进规格说明，代码里先引用“设计 §x.y”，Task 6 再统一改成 “M25 规则 n”。
- 迁移只往 `MIGRATIONS` 末尾追加，并补一个从上一版本升级的测试。
- 改 Rust 侧的序列化结构时，同步改 `src/api/types.ts`。只有 `src/api/` 能调用 Tauri。
- 前端测试的 import 要带 `.ts` 扩展名。
- 名字：去掉首尾空白后非空，最多 100 个字符。提示文案：
  - 名字为空：`请填写名字`
  - 名字超长：`名字不能超过 100 个字`
  - 内容为空：`请填写内容`
- 分类顺序：全部 · 常用 · 片段 | 文本 · 链接 · 代码 · 图片 · 视频 · 文件（分隔线在“片段”之后）。
- 提示条文案：
  - 存为片段：`已存为片段“{名字}”，搜索这个名字就能找到`
  - 编辑：`片段已更新`
  - 批量删除：`已删除 {N} 个片段`
  - 单条删除：`已删除片段“{名字}”`
- 设置文案：
  - 设置里新建后，“片段”一行的说明：`已新建片段“{名字}”，在面板的“片段”分类里`
  - “历史记录”一行的说明：`置顶记录与片段会保留`
- 每个任务提交前跑 `make check`，完成后提交，按路径 `git add`。分支为 `feat/snippets`。

## 重点检查（没有现成测试覆盖、最可能出问题的地方）

1. 从历史存片段之后删掉原记录、等到彻底清除，片段的图片、缩略图、大块 flavor（`blobs/`）都还在，并且能粘贴 → Task 2 的 `snippet_survives_purge_of_source`。
2. 片段与历史内容完全相同：采集时不能合并进片段 → Task 1 的 `capture_never_merges_into_snippet`。
3. 每一条清理或计数路径都不碰片段，包括采集时的容量裁剪 → Task 2 的 `cleanup_paths_skip_snippets`。
4. 多选状态下记录被别处删掉（托盘清空、另一次删除）：多选集合里不能留着已不存在的 id，批量删除不能报错 → Task 4 的 `pruneMulti`，Task 5 接到 `records-removed`。
5. 片段对话框开着时，面板失焦或按唤起快捷键都不隐藏面板 → Task 5 把 `#snippet` 加进 `keepDlgs`，并按 AC-M25-11 手动验收。
