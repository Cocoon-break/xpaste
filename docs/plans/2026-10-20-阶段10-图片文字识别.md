# 阶段 10：图片文字识别（OCR）与截图标题本地时间 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 [图片文字识别方案 v0.1](../specs/2026-10-20-图片文字识别方案.md) 让图片记录能按图中文字搜索：系统自带离线 OCR（macOS Vision / Windows.Media.Ocr），后台异步识别、历史图片低速回填，预览可看可复制识别文字，设置可开关；顺带把截图自动标题从 UTC 改成本地时间（用户验收发现）。

**Architecture:** 平台层加 `ocr_available()` / `ocr_png()` 两个阻塞函数（类型定义在平台 crate 内，核心库不依赖）；核心库加迁移 4（`ocr_text`、`ocr_state` 两列）、`Store::set_ocr`、带命中片段的 `search_hits`、设置 `ocr_enabled` / `ocr_backfill`；应用层新模块 `ocr.rs`：一条低优先级工作线程 + 去重队列（新图插队首、回填排队尾）、面板可见暂停、启动 30 s 后回填；现有 `enrich` 线程做完缩略图后把 id 交给 OCR 队列；识别完成复用 `record-updated` 事件。前端在预览、列表、设置三处接线。

**Tech Stack:** Rust（tauri 2.12、rusqlite、`objc2-vision` 新增、`windows` 加特性、`chrono` 已在依赖树中）、TypeScript（`node:test`）、CSS。

**Spec:** [docs/specs/2026-10-20-图片文字识别方案.md](../specs/2026-10-20-图片文字识别方案.md)（§2 接口、§3 数据、§4 流程、§5 搜索、§6 界面、§8 错误、§10 验收）；[docs/xPaste-功能规格说明.md](../xPaste-功能规格说明.md) v0.1.11 → v0.1.12（新增 M22，回写 M05 / M07 / M08 / M15、附录、第 8 章）；[docs/specs/2026-10-18-xPaste-实现设计.md](../specs/2026-10-18-xPaste-实现设计.md) v0.12 → v0.13。产品已确认方案 §12 的四项取默认：默认开启识别与回填；Windows 缺语言包只提示不安装；列表缩略图加“T”角标；命中片段显示在行内元信息。

## Review Focus

1. 识别文字进入 `search_text` 后，搜索命中但标题不含关键词：用户要能看出为什么命中 → Task 2 `search_hits` 返回片段、Task 5 行内显示；测试 `search_hits_returns_snippet_only_for_ocr_matches`。
2. 面板打开时后台识别抢 CPU 会拖慢唤起与滚动 → Task 4 队列在 `panel-shown` 后不再取新任务、`panel-hidden` 后恢复；测试 `queue_pauses_while_visible`（纯逻辑：`Queue::next()` 在 `paused` 为真时返回 `None`）。

pub struct OcrText { pub text: String, pub confidence: f32 }

pub enum OcrError { Decode, Timeout, Engine(String) }
/// 本机是否有可用的 OCR 引擎（macOS ≥ 10.15 恒真；Windows 看是否能创建引擎）。探测一次由调用方缓存。
pub fn ocr_available() -> bool;

- 工作线程（`std::thread::Builder::new().name("ocr")`，macOS 用 `pthread_set_qos_class_self_np(QOS_CLASS_UTILITY)`，Windows `SetThreadPriority(THREAD_PRIORITY_BELOW_NORMAL)`，两者都通过平台层新增的 `lower_thread_priority()` 同签名函数）：
  ```
  loop { id = wait next();
    if !settings.ocr_enabled → set_ocr(SKIPPED) ; continue
    if !supported → set_ocr(UNSUPPORTED) ; continue
    path = data_dir/images/{id}.png；不存在 → set_ocr(FAILED)
    文件 > 20 MiB → set_ocr(SKIPPED)
    t0；r = ocr_png(path, 2000)；耗时 > 10 s 也记 FAILED（不中断调用，只按结果标记；真正的硬超时留给后续）
    Ok(Some(t)) && !t.text.trim().is_empty() && t.confidence >= 0.3 → set_ocr(TEXT, Some(text))
    Ok(Some(_)) → set_ocr(EMPTY)；Ok(None) → set_ocr(UNSUPPORTED)；Err(_) → set_ocr(FAILED)
    set_ocr 返回 true 时 emit_summary(RECORD_UPDATED, id)；日志 `ocr id={id} state={k} ms={t}`（不含文字）
    回填项之间 sleep 500 ms（队列项带 `backfill: bool`）
  }
  ```
- `schedule_backfill()`：启动 30 s 后（线程内 `sleep`）若 `ocr_backfill && ocr_enabled`，`ocr_pending_ids(&[PENDING, SKIPPED], 5000)` 全部 `push_back`；`UNSUPPORTED` 不回填。
- `supported = xpaste_platform::ocr_available()` 启动探测一次。
- `OcrProgress { done, total, supported }` 来自 `Store::ocr_progress` + `supported`。

## 自查记录

- 类型 `OcrText` / `OcrError` 放平台 crate 而不是核心库：核心库不调用 OCR，平台层已依赖核心库，反向依赖不必要；Task 3 因此能与 Task 1–2 并行。
- OCR 不并入 `enrich` 线程：单张识别 0.3–1.5 s，会拖慢缩略图与视频封面；独立线程并由 `enrich` 在缩略图完成后交接，保证列表先有图再有字。
- 暂停信号取自 `panel.rs` 发 `panel-shown` / `panel-hidden` 的同一处，避免再加一个可见性原子量。
- 硬超时需要可中断的 Vision 调用，本阶段只做“超过 10 s 按失败记”的软标记并在方案里注明，避免为超时开第二条线程。
- 命中片段由后端算：`search_text` 与 `ocr_text` 都在库里，前端拿不到 `ocr_text`（摘要不带正文）。
- 回填只处理 0 与 4：3（失败）不自动重试以免每次启动重复失败；5（不支持）在换了系统或装了语言包后由用户在设置里打开开关触发 `schedule_backfill`，此时把 5 也纳入——Task 4 的 `schedule_backfill` 在“由不支持变为支持”时额外包含 5（实现者据 `supported` 判断）。
- 截图标题本地时间：`chrono` 已在依赖树（`serde_with`），只加特性，不加新编译来源；夏令时边界用当前偏移，接受。
