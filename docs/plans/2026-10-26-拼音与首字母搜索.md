# 拼音与首字母搜索 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 搜索框里打全拼（`huiyi`）或首字母（`hy`）能找到含“会议”的记录，并高亮命中的汉字。

**Architecture:** 在 `search_text` 旁新增 `py_text` 列，存中文的拼音形式，配一张 FTS5 trigram 索引 `fts_py`。查询全是 ASCII 字母且不少于 2 个时，在原有字面匹配上再 OR 一路 `py_text` 匹配。只靠拼音命中的记录，`search_hits` 返回命中的汉字（`mark`），前端拿它代替输入的字母做高亮。

**Tech Stack:** Rust（`xpaste-core`，rusqlite 自带的 SQLite 与 FTS5 trigram）、`pinyin` 0.10（逐字转换，带多音字数据）、TypeScript 前端。

**Spec:** 没有单独的设计文档，决定写在下面的“设计取值”里。任务 5 把它们写回功能规格说明 M05（v0.1.19）与实现设计（v0.20）。

## 设计取值

- **多音字**：`pinyin` 0.10 没有词组词典。默认读音会把“银行”转成 yinxing、“重庆”转成 zhongqing、“音乐”转成 yinle（试验已确认）。所以索引另存每个多音字附近的短窗口，按它的每个其他读音各一行，`yinhang`、`chongqing`、`yinyue` 都能命中。
- **查询规则**：只有查询（小写后）全是 ASCII 字母、且不少于 2 个字符时才走拼音匹配。3 个字符及以上走 `fts_py`，正好 2 个走 `instr(py_text, …)`，与现有字面规则对称。含汉字、数字、空格或标点的查询与现在完全一样。
- **结果顺序**：不变。前端按返回的 id 集合过滤自己按时间排好的列表，拼音命中按时间混在其中。
- **体积上限**：只为来源文本的前 4096 个字符生成拼音（`PY_MAX_CHARS`）。
- **不加设置开关**：始终开启。

### Task 1: 核心层 `pinyin` 模块

**Files:**
- Create: `crates/xpaste-core/src/pinyin.rs`
- Modify: `crates/xpaste-core/src/lib.rs`（加 `pub mod pinyin;`）、`crates/xpaste-core/Cargo.toml`、`Cargo.lock`

**Interfaces:**
- Produces:
  - `pub const PY_MAX_CHARS: usize = 4096;`
  - `pub fn is_pinyin_query(q: &str) -> bool`：`q` 非空、每个字符都是 ASCII 字母、且 `q.len() >= 2` 时为 true。
  - `pub fn index_text(s: &str) -> String`：`s` 前 `PY_MAX_CHARS` 个字符的小写拼音索引；没有汉字时返回 `""`。
  - `pub fn find(s: &str, q: &str) -> Option<String>`：`s` 中被（小写的）`q` 匹配到的最靠前的一段汉字，返回原字。

**`index_text` 的格式。** 把输入切成连续段，段内每个字符的 `to_pinyin()` 都返回 `Some`。每段输出下面几行，用 `\n` 连接，与之前已输出的行完全相同的行丢掉：

1. **全拼**：默认读音 `plain()` 直接拼接，如“会议纪要”→ `huiyijiyao`。
2. **首字母**：每个默认读音的首字母，如 `hyjy`（zh / ch / sh 取 `z` / `c` / `s`）。
3. **多音字**：第 `i` 个字的 `to_pinyin_multi()` 去重后的 plain 读音里，除默认读音外还有其他读音时，取窗口 `run[i-2 ..= i+2]`（裁到段内）。每个其他读音输出一行全拼（第 `i` 个字用该读音，其余用默认），再加一行对应的首字母。

行不跨段，所以非汉字会切断匹配。

**`find` 的匹配。** 在每段汉字内，从每个起始字试两种方式；同一起点上全拼优先。每个字用 `to_pinyin_multi()` 去重后的全部读音。

- **全拼**：`q` 要被连续几个字的读音覆盖。第一个字可以从音节中间开始（它某个读音的任一非空后缀），最后一个字可以在音节中间结束（任一非空前缀），与对全拼行做子串搜索的结果一致。
- **首字母**：连续每个字的读音里，都要有一个读音的首字母等于 `q` 的下一个字母，直到 `q` 用完。

```sql
ALTER TABLE records ADD COLUMN py_text TEXT;
CREATE VIRTUAL TABLE fts_py USING fts5(py_text, content='records', content_rowid='id', tokenize='trigram');
CREATE TRIGGER records_fts_py_ai AFTER INSERT ON records BEGIN
  INSERT INTO fts_py(rowid, py_text) VALUES (new.id, new.py_text);
END;
CREATE TRIGGER records_fts_py_ad AFTER DELETE ON records BEGIN
  INSERT INTO fts_py(fts_py, rowid, py_text) VALUES ('delete', old.id, old.py_text);
END;
CREATE TRIGGER records_fts_py_au AFTER UPDATE OF py_text ON records BEGIN
  INSERT INTO fts_py(fts_py, rowid, py_text) VALUES ('delete', old.id, old.py_text);
  INSERT INTO fts_py(rowid, py_text) VALUES (new.id, new.py_text);
END;
INSERT INTO fts_py(fts_py) VALUES ('rebuild');
```

### Task 3: 搜索：拼音匹配与命中汉字 `mark`

**Files:**
- Modify: `crates/xpaste-core/src/store.rs`（`search_sql`、`search_ids`、`search_hits`、测试）、`crates/xpaste-core/src/model.rs`（`SearchHit`）

**Interfaces:**
- Consumes: `pinyin::is_pinyin_query`、`pinyin::find`，任务 2 的 `py_text` 与 `fts_py`
- Produces:
  - `SearchHit { id: i64, snippet: Option<String>, mark: Option<String> }`，序列化为 `mark`，沿用 `SearchHit` 现有的 serde 属性。
  - `fn search_sql(q: &str) -> (String, Vec<String>)`：WHERE 片段，加按 `?1`、`?2` 绑定的参数。

**匹配：** 字面部分就是现在的片段与参数，作为 `?1`。`is_pinyin_query(q)` 时片段变成 `(<字面> OR <拼音>)`：`q.chars().count() >= 3` 时 `<拼音>` 为 `id IN (SELECT rowid FROM fts_py WHERE py_text MATCH ?2)`，参数为 `"q"`；否则为 `instr(py_text, ?2) > 0`，参数为 `q`。

**`search_hits` 的 `mark` 与 `snippet`：**
- 在 SELECT 里加 `instr(search_text, ?N) > 0 AS lit`（参数为小写的 `q`）。
- 字面命中的 `snippet` 规则不变。
- `!lit` 说明靠拼音命中：`mark = find(title, q)`，没有再 `find(ocr_text, q)`。`mark` 来自 `ocr_text` 时，`snippet = snippet(ocr_text, &mark)`。
- 其余情况 `mark` 为 `None`。
