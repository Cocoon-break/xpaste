# 阶段 9：产品闭环 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按阶段 8 之后的使用走查（18 项发现，产品负责人决定全部处理）把产品收口：删掉没有价值的元素（标题栏最小化 / 关闭按钮、预览头部“更多”、无人调用的命令、“颜色”分类），修掉状态丢失（设置改到一半失焦被关、撤销被其他提示顶掉、暂停不跨重启、点光柱切分类不记忆），把频谱做成可收起并记住，外观改为点选即存，补齐文案与小功能（粘贴 / 复制按能力显示、状态栏提示随状态变化、敏感内容文案、托盘版本号、设置里清空历史、右键菜单按类型动作、录制快捷键时不被全局快捷键打断、拖动位置不记忆写进规格），最后把规格、实现设计、验收记录同步。

**Architecture:** 不加依赖、不改数据库表结构（只加一条迁移把已有 `color` 记录改成 `text`）。前端沿用“纯函数模块 + `main.ts` 接线”的分层：设置项的局部持久化抽成一个 `persistUi(patch)`（防抖、成功后合并），分类记忆、频谱收起、外观三处共用；“对话框打开时失焦不隐藏 / 快捷键不隐藏”由后端 `AppState.dialog_open` 一个原子布尔承担，前端在对话框开关时同步一次。所有删减先于新增，颜色迁移与颜色代码删除在同一提交里落地。

**Tech Stack:** Rust（tauri 2.12、rusqlite 迁移）、TypeScript（Node `node:test`）、CSS；不新增 crate 与 npm 依赖。

**Spec:** [docs/xPaste-功能规格说明.md](../xPaste-功能规格说明.md)（v0.1.9 → 本阶段 v0.1.10；涉及 M01、M04、M06、M07、M08、M12、M13、M14、M15、M16、M17、M19、第 8 章、附录）、[docs/specs/2026-10-18-xPaste-实现设计.md](../specs/2026-10-18-xPaste-实现设计.md)（v0.10 → v0.11；§1、§5.1、§5.3、§5.4、§5.7、§6、§7.2、§8.3、§9.5、§9.6、§9.7、§10）。走查原文在本机草稿 `stage9-audit.md`（F01–F18 编号沿用）。

## Review Focus

1. 老用户的库里已有 `color` 记录：新代码不认识这个类型，没有迁移会让 `bootstrap` 整体失败、历史全部不可见 → Task 2 `color_rows_become_text_after_migration`、`parse_rejects_color`。
2. 设置对话框打开时失焦不再隐藏：面板会留在屏幕上直到用户回来，Esc、取消、保存后必须恢复“失焦即隐藏”；对话框被 `hidden()` 直接关掉时标志也要复位 → Task 3 `toggle_action_keeps_panel_while_dialog_open`、Task 3 Step 4 的开发版检查。

- “粘贴 / 复制”文案按能力显示而不是统一写“粘贴”：未授权时写“粘贴”会让人以为点了没反应。Windows 从托盘打开时没有粘贴目标的降级仍由提示条说明（规格 M09 规则 3）。
- 版本号放托盘禁用项而不是设置对话框：托盘是用户查看“这是哪个 xPaste”的第一入口，且不占面板空间。
- 右键菜单按类型动作复用 `open_url` / `reveal_file`，不加新命令；不给它们快捷键，避免与 `Mod + O` 等系统习惯冲突。
- 拖动位置不记忆按规格补写而不是实现“记住位置”：面板按鼠标所在屏幕定位是 M04 的核心规则，记住拖动位置会和它冲突。
