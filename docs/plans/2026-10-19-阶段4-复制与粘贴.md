# 阶段 4：复制与粘贴（macOS） 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把阶段 3 已实现的 `copy(id, paste)` 收口成可验收的 M09 / M11：未授权辅助功能时在提示条里给出“前往授权”并触发系统授权对话框；补齐使用次数口径的测试与规格回写；给开发版加数据目录隔离，让自动化验收不再碰真实剪切板库。

**Architecture:** 后端只加一个命令 `request_accessibility`（平台层 `AXIsProcessTrustedWithOptions` 带 prompt；Windows 空操作）和一个启动时的 `XPASTE_DATA_DIR` 覆盖；前端 `toast()` 增加可选的操作按钮，复用撤销按钮的样式；其余是测试、隔离环境下的自动验收和三份文档回写。不新增依赖、不改数据库、不改事件。

**Tech Stack:** Rust（objc2 FFI 到 ApplicationServices）、Tauri 2 命令、vanilla TS；sqlite3 命令行与 osascript 用于隔离环境下的自动验收。

**Spec:** [docs/specs/2026-10-18-xPaste-实现设计.md](../specs/2026-10-18-xPaste-实现设计.md) §2（Q1、Q3、回写项 1、6）、§6（`can_paste`、`open_accessibility_settings`）、§8.3、§8.5、§10（日志规则）、§13；阶段表第 4 行。规格说明 M09、M11、M18 规则 1（仅“前往授权”部分，引导覆盖层仍在阶段 5）、附录文案。原型 [docs/xpaste-prototype.html](../xpaste-prototype.html) 的 `copy()` 与 `toast()` 是前端行为的对照基准。

**执行说明**

- 分支 `dev`，直接提交。实现者与审查者子代理一律用 opus。
- **开发版运行只许用 `make dev-isolated`**（Task 1 加入），它把数据目录指到仓库内的 `.xpaste-dev/`；禁止用 `make dev` / `pnpm tauri dev` 跑自动化按键或删除流程。结束进程只许 `kill <自己记下的 PID>`，禁止 `pkill -f`。每份实现者派单都要写明这两条。
- 自动按键（osascript）前先确认前台是文本编辑（TextEdit），整段脚本不超过 30 秒；验收完关闭文稿不保存。
- 阶段 5 的内容不做：设置对话框、权限状态显示、首次引导覆盖层。本阶段只做“复制失败提示条里的前往授权”。
- 前端提示条属于面板交互：Task 2 完成后除常规任务审查外，再做一次对照原型的交互复核（提示条弹入、换字、按钮样式与撤销按钮一致、5 秒后收起、减少动态效果下即时）。

## Global Constraints

- `@tauri-apps/*` 只能在 `src/api/` 下 import；`src/main.ts` 之外的前端模块不碰 DOM、不碰 Tauri，并配 `*.test.ts`（`pnpm test` 自动发现，测试内 import 带 `.ts` 后缀）。
- 日志与事件不写剪切板内容、标题、路径；`XPASTE_DATA_DIR` 生效时日志只写“数据目录已由环境变量覆盖”，不写路径。
- 文案与规格说明附录完全一致：`已复制，在目标应用中按 ⌘ + V 粘贴`、`这条已经用了 3 次，已加入“常用”`（及合并句）；按钮文字 `前往授权`。
- 所有访问数据库或剪切板的命令 `#[tauri::command(async)]`；锁内无 `await`；AppKit 调用在主线程。
- 平台层函数两端同名同签名（`crates/xpaste-platform/src/{macos,windows}.rs`），Windows 侧必须能过 `cargo clippy -p xpaste-platform --target x86_64-pc-windows-msvc`。
- 使用次数口径：首次复制生成记录时 `uses = 0`，之后每次重复使用（xPaste 复制 / 粘贴、外部重复复制）+1；`FAV_MIN = 3`（设计 §2 回写项 1）。
- 每个任务结束 `make check` 必须通过。

## Review Focus

1. `XPASTE_DATA_DIR` 设为空字符串或只含空白时必须退回默认目录，而不是在当前目录建库 → Task 1 `data_dir_override_wins_only_when_non_empty`。
2. Windows 上 `copiedOnly` 的原因是 `elevated` / `pasteFailed`，提示条不能出现“前往授权” → 现有 `copy-status.test.ts::只有缺少辅助功能权限时才需要“前往授权”` 覆盖判定；Task 2 的 `main.ts` 只在 `needsAccessibility(res)` 为真时挂按钮。
3. 带按钮的提示条还没收起时又来一条普通提示（例如用户紧接着置顶）：按钮必须立刻隐藏，不能留在“已置顶”后面 → Task 2 `toast()` 每次调用都重设按钮 `hidden`，由交互复核验证。
4. 外部复制同一内容 3 次时使用次数是 2，不进入“常用”；第 4 次才进入 → Task 3 `three_external_copies_count_two_uses`，并把 AC-M11-02 改为 4 次。
5. 关闭“复制后移到顶部”或记录已置顶时 `bump_use` 不改 `copied_at` → Task 3 `bump_use_moves_only_unpinned_when_enabled`。

```rust
#[test]
fn three_external_copies_count_two_uses() {
    // AC-M11-02 口径：首次复制生成记录不计使用，第 4 次外部复制才进入“常用”
    let mut s = mem();
    for t in 1..=3 {
        s.insert_or_merge(&rec("a"), t, 500).unwrap();
    }
    assert_eq!(s.list_summaries().unwrap()[0].uses, 2);
    s.insert_or_merge(&rec("a"), 4, 500).unwrap();
    assert_eq!(s.list_summaries().unwrap()[0].uses, 3);
}

#[test]
fn bump_use_moves_only_unpinned_when_enabled() {
    let mut s = mem();
    let (Upsert::Added(a), _) = s.insert_or_merge(&rec("a"), 1, 500).unwrap() else { panic!() };
    s.insert_or_merge(&rec("b"), 2, 500).unwrap();
    // AC-M09-08：关闭“复制后移到顶部”，次数 +1 但位置不变
    s.bump_use(a, false, 9).unwrap();
    let l = s.list_summaries().unwrap();
    assert_eq!((l[1].id, l[1].uses, l[1].copied_at), (a, 1, 1));
    // M09 规则 5：开启时回到最前
    s.bump_use(a, true, 10).unwrap();
    let l = s.list_summaries().unwrap();
    assert_eq!((l[0].id, l[0].uses, l[0].copied_at), (a, 2, 10));
    // 置顶记录位置不变
    s.set_pinned(a, true).unwrap();
    s.bump_use(a, true, 20).unwrap();
    assert_eq!(s.list_summaries().unwrap()[0].copied_at, 10);
}
```

- 设计 §14 把阶段 4 定为“辅助功能引导；M09、M11 验收与修正”。引导覆盖层（M18 规则 1）依赖阶段 5 的首次启动流程，本阶段只做复制降级时的“前往授权”按钮；设置页的权限状态与按钮留在阶段 5，`open_accessibility_settings` 命令因此保留。
- “前往授权”选用 `AXIsProcessTrustedWithOptions` 带 prompt 而不是直接打开系统设置：系统对话框会把 xPaste 加入“辅助功能”列表，用户只需勾选；直接打开设置页时列表里没有 xPaste，用户得自己点“+”找应用。
- 设计 §2 回写项 6“粘贴成功时如何告知已加入常用”定为不告知：面板已隐藏，再弹系统通知打扰大于收益；下次唤起列表元信息即显示“用过 N 次”。不引入 notification 插件。
- 使用次数口径按回写项 1（首次为 0），因此 AC-M11-02 改为 4 次而不是改成“首次记为 1”：后者会让 AC-M11-01 在第 2 次 xPaste 复制时就进入常用，与原型数据不符。这是产品口径，用户验收时可推翻，改动只是 `insert_or_merge` 的初值。
- `XPASTE_DATA_DIR` 不属于规格功能，是阶段 3 事故（子代理开发版运行删了真实记录）的直接修复；放在 Task 1 是因为后续任务的自动验收都依赖它。
- 开发二进制与正式 `.app` 在系统“辅助功能”列表中是两个条目（`xpaste` 与 `xPaste`）；验收记录里要写明测的是哪一个。
- 原型 `copy()` 把“已复制”与“加入常用”合成一句（`已复制，这条已经用了 N 次，加入“常用”`），正式版按规格附录与 v0.1.3 的合并句，不照搬原型文案。
