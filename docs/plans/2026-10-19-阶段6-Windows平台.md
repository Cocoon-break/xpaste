## Review Focus

1. 资源管理器复制文件时剪切板带 `DataObject`、`Ole Private Data` 等 OLE 私有格式和 GDI 句柄格式；原样写回会让资源管理器粘贴失败、读 GDI 句柄会读到垃圾 → Task 1 `formats_to_read_skips_gdi_synthesized_and_ole`。
2. 截图工具给的 32 位 DIB 常常 alpha 全为 0，直接转 PNG 是全透明图（缩略图空白）；DIB 行是自下而上存的 → Task 1 `dib_to_png_handles_bottom_up_and_zero_alpha`、`bgra_to_png_treats_all_zero_alpha_as_opaque`。
3. CF_HTML 的 `StartFragment` / `EndFragment` 是字节偏移，片段含中文时按字符切会错位，链接标题取不到 → Task 1 `cf_html_fragment_uses_byte_offsets`。
4. 面板可见时左键单击托盘图标：按下时面板已失焦隐藏，松开时 `toggle` 又把它显示出来（托盘永远关不掉面板）；引导中单击托盘被当成“试按快捷键成功” → Task 4 `toggle_action_by_trigger`。
5. 从托盘打开面板时前台窗口是任务栏，记成粘贴目标后按 Enter 会把 Ctrl + V 发给任务栏、提示“已粘贴”实际什么都没发生 → Task 3 `shell_tray_classes_are_not_paste_targets`（`foreground_window` 返回 None，`plan_paste` 降级为只复制并提示）。

**Interfaces:**
- Produces（`winfmt.rs`，全平台）：
  - `pub const STANDARD_FORMATS: [(u32, &str); 22]`：1 `CF_TEXT`、2 `CF_BITMAP`、3 `CF_METAFILEPICT`、4 `CF_SYLK`、5 `CF_DIF`、6 `CF_TIFF`、7 `CF_OEMTEXT`、8 `CF_DIB`、9 `CF_PALETTE`、10 `CF_PENDATA`、11 `CF_RIFF`、12 `CF_WAVE`、13 `CF_UNICODETEXT`、14 `CF_ENHMETAFILE`、15 `CF_HDROP`、16 `CF_LOCALE`、17 `CF_DIBV5`、0x80 `CF_OWNERDISPLAY`、0x81 `CF_DSPTEXT`、0x82 `CF_DSPBITMAP`、0x83 `CF_DSPMETAFILEPICT`、0x8E `CF_DSPENHMETAFILE`
  - `pub fn standard_format_name(id: u32) -> Option<&'static str>`、`pub fn standard_format_id(name: &str) -> Option<u32>`（Task 2 写回用）
  - `pub fn formats_to_read(all: &[(u32, String)]) -> Vec<(u32, String)>`：保持顺序；去掉 id ∈ {1, 2, 3, 7, 9, 14, 0x80, 0x82, 0x83, 0x8E}（GDI 句柄格式与系统合成的 `CF_TEXT` / `CF_OEMTEXT`，设计 §6）和名字 ∈ {`DataObject`, `Ole Private Data`}；`CF_DIB` 与 `CF_DIBV5` 只留先出现的那个（后出现的是系统合成的）
  - `pub fn cf_html_fragment(bytes: &[u8]) -> Option<String>`：读头部 `StartFragment:` / `EndFragment:` 的十进制字节偏移，切片后 UTF-8 解码（lossy）；缺键、偏移越界或 start > end → None
  - `pub fn parse_hdrop(bytes: &[u8]) -> Vec<PathBuf>`：DROPFILES（`pFiles` u32 @0、`fWide` u32 @16），`fWide != 0` 按 UTF-16LE、否则按字节 lossy；逐个 NUL 结尾，遇空串停；`pFiles` 越界返回空
  - `pub fn dib_to_png(dib: &[u8]) -> Option<Vec<u8>>`：`image::codecs::bmp::BmpDecoder::new_without_file_header` → `to_rgba8` → 全零 alpha 视为不透明 → PNG
  - `pub fn bgra_to_png(w: u32, h: u32, bgra: &[u8]) -> Option<Vec<u8>>`：自上而下的 BGRA 行；长度不等于 `w * h * 4` → None；同样的全零 alpha 规则（Task 3 图标用）
  - `pub fn bitmap_from_flavors(flavors: &[Flavor]) -> Option<Vec<u8>>`：有 `PNG` 格式时原样返回（与 macOS 优先 `public.png` 一致），否则第一个 `CF_DIBV5` / `CF_DIB` 经 `dib_to_png`
- Produces（`windows.rs`）：`read_snapshot(skip_sensitive)` 签名不变。枚举全部格式 → 每个 id 取名字（`standard_format_name`，否则 `GetClipboardFormatNameW`，取不到跳过）→ 敏感判断（已有逻辑不变）→ 对 `formats_to_read` 的结果逐个 `with_global`，`GlobalSize > MAX_FLAVOR_BYTES` 时只 `log::debug!("跳过过大的格式 {name} {size} 字节")` → `Flavor { item: 0, format: name, data }`（`CF_UNICODETEXT` 仍存截到 NUL 的原始字节）。关闭剪切板后：`text = normalize_newlines(utf16 解码)`、`html = cf_html_fragment(HTML Format)`、`file_paths = parse_hdrop(CF_HDROP)`（去重）、`file_paths` 为空时 `bitmap = bitmap_from_flavors`。整次读取超过 100 ms 时 `log::info!("读取剪切板 formats={n} bytes={total} ms={ms}")`（设计 §15 延迟渲染的观测点）。

fn standard_format_names_round_trip() {
    assert_eq!(standard_format_name(13), Some("CF_UNICODETEXT"));
    assert_eq!(standard_format_name(0xC0FE), None);
    assert_eq!(standard_format_id("CF_DIBV5"), Some(17));
    assert_eq!(standard_format_id("HTML Format"), None);
    for (id, name) in STANDARD_FORMATS { assert_eq!(standard_format_id(name), Some(id)); }
}
#[test]
fn formats_to_read_skips_gdi_synthesized_and_ole() {
    let all: Vec<(u32, String)> = [(1, "CF_TEXT"), (13, "CF_UNICODETEXT"), (16, "CF_LOCALE"), (7, "CF_OEMTEXT"),
        (17, "CF_DIBV5"), (2, "CF_BITMAP"), (8, "CF_DIB"), (14, "CF_ENHMETAFILE"), (3, "CF_METAFILEPICT"), (9, "CF_PALETTE"),
        (0xC013, "DataObject"), (0xC00E, "Ole Private Data"), (0xC0A1, "HTML Format"), (0xC0B2, "PNG")]
        .map(|(i, n)| (i, n.to_string())).into();
    let ids: Vec<u32> = formats_to_read(&all).into_iter().map(|f| f.0).collect();
    assert_eq!(ids, [13, 16, 17, 0xC0A1, 0xC0B2]); // DIBV5 先出现，DIB 是合成的
}
#[test]
fn cf_html_fragment_uses_byte_offsets() {
    let frag = r#"<a href="https://a.io">锚文本</a>"#;
    assert_eq!(cf_html_fragment(&cf_html(frag)).as_deref(), Some(frag));
    assert_eq!(cf_html_fragment(b"Version:0.9\r\n"), None);
    assert_eq!(cf_html_fragment(b"StartFragment:0000000010\r\nEndFragment:0000009999\r\n"), None);
}
#[test]
fn parse_hdrop_wide_and_ansi() {
    assert_eq!(parse_hdrop(&dropfiles(true, &[r"C:\a b\图.png", r"D:\x"])),
        [PathBuf::from(r"C:\a b\图.png"), PathBuf::from(r"D:\x")]);
    assert_eq!(parse_hdrop(&dropfiles(false, &[r"C:\a"])), [PathBuf::from(r"C:\a")]);
    assert!(parse_hdrop(&[0xFF, 0, 0, 0]).is_empty());

fn dib_to_png_handles_bottom_up_and_zero_alpha() {

    let png = dib_to_png(&dib(1, 2, 24, &[0, 0, 255, 0, 0, 255, 0, 0])).unwrap(); // 第一行在底部
    assert_eq!((px(&png, 0, 1), px(&png, 0, 0)), ([255, 0, 0, 255], [0, 255, 0, 255]));
    let png = dib_to_png(&dib(2, 1, 32, &[0, 0, 255, 0, 0, 255, 0, 0])).unwrap();
    assert_eq!(px(&png, 1, 0), [0, 255, 0, 255]);
    assert_eq!(dib_to_png(&[1, 2, 3]), None);

    assert_eq!(px(bgra_to_png(2, 1, &[0, 0, 255, 0, 0, 255, 0, 0]).unwrap()), [255, 0, 0, 255]);
    assert_eq!(px(bgra_to_png(1, 1, &[0, 0, 255, 128]).unwrap()), [255, 0, 0, 128]);

}

    assert_eq!(bitmap_from_flavors(&[f("CF_UNICODETEXT", vec![])]), None);
}

## 自查记录

- 应用层在 macOS 上交叉检查不可行是实测结论（libsqlite3-sys 找不到 Windows SDK 头文件；tauri-build 的资源编译同样需要 Windows 工具链）。`cargo-xwin` 可以下载 MSVC CRT / SDK 解决，但要接受微软许可、引入新工具，没采用；因此应用层的 Windows 改动都写成全平台可编译的代码，`windows_material` 用错误值注入测试。
- Windows 10 不透明的判定用 `apply_mica` 的 `UnsupportedPlatformVersion`，不读系统版本号：Acrylic 在 Windows 10 上其实可用，但规格 M16 规则 2 与 AC-M16-03 要求 Windows 10 不透明，且 window-vibrancy 文档说明 Acrylic 在拖动和调整尺寸时卡顿。
- 读取规则在设计 §6 基础上加了三条：跳过 `DataObject` / `Ole Private Data`（OLE 对象的令牌，写回后对象已不存在）；DIB / DIBV5 只读先出现的（枚举顺序里合成格式排在原始格式之后）；有 `PNG` 格式时直接用它作位图。Office 的 `Link Source`、`Embed Source` 是否要跳过留给 Windows 验收（阶段6-W7）决定，不预先跳过。
- `app_icon` 改用 `SHDefExtractIconW` 取 64 px，设计写的 `SHGetFileInfoW` 只有 32 px 的大图标，与 macOS 64 pt 档不对等；Task 6 回写设计。
- `write()` 用 `OpenClipboard(None)` 打开；若 Windows 上 `SetClipboardData` 因所有者为空而失败（W1 会暴露），退回用监听线程的 message-only 窗口作所有者。Office 的 OLE 格式（`Link Source`、`Embed Source`、`Object Descriptor`）不预先跳过，等 W7 证明有问题再加进跳过列表。
- 链接标题在 Windows 上只靠 CF_HTML 片段的锚文本（核心层已有 `anchor_text`），不解析 Firefox 的 `text/x-moz-url`。
- 托盘单击（控制者已裁定接受，并回写规格 M17、M09）：设计 §10 说调用 `toggle()`。Windows 上按下托盘图标时面板已因失焦隐藏，所以加了“隐藏后 300 ms 内的托盘单击不重新显示”；引导中只有快捷键算试按（阶段5-T6-c 记下的问题）；第二次启动应用同样不算。
- 从托盘打开面板时没有可用的粘贴目标（前台是任务栏），选择“Enter 只复制并提示”而不是“粘贴到隐藏面板后系统激活的窗口”：后者可能贴到错误位置，M09 失败处理与设计 §15 都要求不粘贴到错误位置。实现只改现有 `foreground_window()` 的 Windows 行为，没加平台函数，没改 `records.rs`。
- `toggle` 淡出途中重新唤起改为 `show_panel()`（之前记下的遗留项）：此时前台是面板自己，`show()` 会把面板记成粘贴目标。
- 混合 DPI：`place` 已按目标屏缩放换算物理像素（测试 `physical_space_hit_test_windows`）；另把非 macOS 分支改为先移位置再定尺寸，避免跨屏 WM_DPICHANGED 按比例改掉尺寸。是否真有这个问题以阶段6-W5 为准，改顺序本身没有副作用。
- `paste` 的等待逻辑已符合设计 §6 / §15（最多 100 ms，超时降级），不改。
- 忽略应用按来源名称（现在是 FileDescription，为空时退回现有代码已在用的不带扩展名的文件名）匹配，本阶段不加 exe 文件名的第二套匹配，核心层规则不动（阶段 7 拥有）；三个默认项的 FileDescription 预计就是 `1Password`、`KeePass`、`Bitwarden`，由 AC-M01-04 的 Windows 行核对。
- `HotkeyTaken` 的测试靠抽出 `commit_settings` 注入 `register`，以执行时 `dev` 上的 `save_settings`（含 `hotkey_action`）为准，不按本计划写作时的行号；`save_settings` 行为不变；真实的占用冲突在 Windows 上用“安装版占住快捷键 + 隔离开发版”复现（隔离模式不启用单实例，`RegisterHotKey` 独占）。
