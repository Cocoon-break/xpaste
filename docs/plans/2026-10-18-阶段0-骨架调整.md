# 阶段 0：骨架调整 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把模板生成的单 crate 骨架改成设计文档第 4 节的目录结构（Cargo 工作区 + 核心 / 平台 crate + 分领域命令 + 平台配置 + 日志 + CI），为后续各阶段打底。

**Architecture:** 仓库根目录建 Cargo 工作区，`crates/xpaste-core`（纯逻辑，不依赖 Tauri）、`crates/xpaste-platform`（系统接口，不依赖 Tauri）、`src-tauri`（唯一依赖 Tauri 的 crate）三个成员。本阶段只放类型、设置校验、错误类型、托管状态和一个 `bootstrap` 命令，剩余功能由后续阶段填充。前端建 `src/api/` 作为唯一引用 `@tauri-apps/*` 的目录。

**Tech Stack:** Rust 1.99（MSRV 1.90）、Tauri 2.12、tauri-plugin-log 2、thiserror 2、serde 1、TypeScript 6、Vite 8、pnpm 10、GitHub Actions。

**Spec:** [docs/specs/2026-10-18-xPaste-实现设计.md](../specs/2026-10-18-xPaste-实现设计.md)，第 3、4、5.7、8.1、8.3、10、11、12、13 节；阶段表第 0 行。

## Global Constraints

- `tauri = "2"`，`rust-version = "1.90"`，`edition = "2024"`（ADR-001 约定 1、2）。
- `crates/xpaste-core`、`crates/xpaste-platform` 的 `Cargo.toml` 不得出现 `tauri`（ADR-001 约定 3）。
- 前端不引入框架；`@tauri-apps/*` 只能在 `src/api/` 下 import（设计 4、9.1）。
- 访问数据库或剪切板的命令一律 `#[tauri::command(async)]`（设计 3.2）。
- 日志不写剪切板内容、标题、路径（设计 10）。
- 用户可见文案用简体中文，提示文案与规格说明附录一致（规格 5.6）。
- 命令错误序列化为 `{ "kind": "<camelCase>", "message": "<文案>" }`（设计 8.1）。
- 版本号唯一来源 `package.json`，`tauri.conf.json` 用 `"version": "../package.json"` 引用，工作区 `Cargo.toml` 的版本由 CI 检查一致（设计 12）。
- 每个任务结束时 `cargo check --workspace` 和 `pnpm build` 必须通过。

## Review Focus

1. 旧版本写入的设置 JSON 带有当前版本不认识的字段时，必须仍能读出，不能让应用启动失败 → Task 2 的 `unknown_fields_are_ignored`。
2. 快捷键字符串大小写不规范（例如 `alt+c`）时，校验要按不区分大小写处理，而不是拒绝用户按下的合法组合 → Task 2 的 `hotkey_modifier_check_is_case_insensitive`。
3. 最多保存条数的两个边界 50 和 5000 必须被接受，0 和 5050 必须被拒绝 → Task 2 的 `max_records_boundaries`。
4. 设置文件损坏导致面板尺寸小于最小值（720 × 520）时，校验要拒绝，避免创建一个无法操作的窗口 → Task 2 的 `rejects_panel_size_below_minimum`。
5. 核心层抛出的非设置类错误到达前端时，`kind` 必须是稳定的 `internal`，`message` 原样透传，前端才能统一兜底 → Task 4 的 `core_error_other_maps_to_internal`。

### Task 7: CI 流水线与版本一致性检查

**Files:**
- Create: `.github/workflows/ci.yml`、`scripts/check-version.sh`

**Interfaces:**
- Produces: `pnpm check:version` 脚本（加到 `package.json` scripts），CI 与本地共用。

- [ ] **Step 1: 写 `scripts/check-version.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail
pkg=$(node -p "require('./package.json').version")
cargo=$(cargo metadata --no-deps --format-version 1 | node -e '
  let d = ""; process.stdin.on("data", c => d += c).on("end", () => {
    console.log(JSON.parse(d).packages.find(p => p.name === "xpaste").version) })')
if [ "$pkg" != "$cargo" ]; then
  echo "版本号不一致：package.json=$pkg，Cargo=$cargo" >&2; exit 1
fi
echo "版本号一致：$pkg"
```

`chmod +x`，`package.json` 加 `"check:version": "bash scripts/check-version.sh"`。

- [ ] **Step 2: 本地验证脚本**

Run: `pnpm check:version`
Expected: `版本号一致：0.1.0`。

把 `package.json` 的 version 临时改成 `0.1.1` 再运行，Expected: 退出码 1、打印不一致信息；改回。

- [ ] **Step 3: 写 `.github/workflows/ci.yml`**

```yaml
name: CI
on: { push: { branches: [main] }, pull_request: {} }
jobs:
  build:
    strategy:
      fail-fast: false
      matrix: { os: [macos-latest, windows-latest] }
    runs-on: ${{ matrix.os }}
    defaults: { run: { shell: bash } }
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with: { node-version: 24, cache: pnpm }
      - uses: dtolnay/rust-toolchain@stable
        with: { components: "rustfmt, clippy" }
      - uses: swatinem/rust-cache@v2
      - run: pnpm install --frozen-lockfile
      - run: pnpm check:version
      - run: cargo fmt --all --check
      - run: cargo clippy --workspace --all-targets -- -D warnings
      - run: cargo test --workspace
      - run: pnpm build
      - run: pnpm tauri build --no-bundle
```

前端 `node --test` 在阶段 3 出现第一个 `*.test.ts` 时加入。
