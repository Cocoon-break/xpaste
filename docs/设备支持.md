# 设备支持

xPaste 在不同系统、芯片、显示器和权限设置下哪些功能可用；不可用时用户看到什么提示；还有哪些可以优化。功能的完整规则见[功能规格说明](xPaste-功能规格说明.md)（第 1.4 节目标平台、第 6 章平台差异汇总），未解决的问题汇总在[已知限制](已知限制.md)，真机验收进度见[验收记录](验收记录.md)。

梳理日期：2026-11-01（规格说明 v0.1.39）。“已验证”指在真机上验收过；“未验证”指只经过编译、单元测试或模拟。

## 1. 系统与芯片

| 设备 | 支持情况 | 不支持时的提示 |
| --- | --- | --- |
| macOS 13 及以上，Apple 芯片 | 全部功能。已验证（macOS 27，M1） | — |
| macOS 13 及以上，Intel | 全部功能，单独的 x64 安装包。未在 Intel 真机上验证；长截图的画面流在 Intel 上的帧率与是否更容易“没接上”待验证 | — |
| macOS 13.0 | 能用。界面用到 `color-mix()`，系统自带的 Safari 16.1 不支持：部分描边、选中高亮、光晕不显示。13.1（Safari 16.2）起正常；13.0 上更新 Safari 也能解决 | 没有提示（只是样式缺一部分） |
| macOS 12 及以下 | 不支持 | 安装包设了最低版本 13.0，系统直接提示“不能在这个版本的 macOS 上使用” |
| Windows 11 x64 | 全部功能（录屏除外，见第 2 节）。翻译、划词翻译在 Windows 实机上验收过（阶段 15，2026-10-31，没记 Windows 版本）；截图、贴图、长截图还没在实机上验收（验收记录“阶段12-W1”） | — |
| Windows 10 21H2 及以上 x64 | 同 Windows 11；面板为不透明背景（没有 Mica / Acrylic） | 不需要提示，配色不变 |
| Windows 10 低于 21H2 | 没有测试过。长截图排除边框需要 2004 起，截图、文字识别的系统接口在更早版本上行为未知 | 安装时提示“当前系统低于 Windows 10 21H2，xPaste 没有在这个版本上测试过……仍要安装吗？”，用户可以继续 |
| Windows 11 on ARM | 通过系统的 x64 模拟运行，没有测试过 | — |
| Windows 10 on ARM | 不能运行（系统不能运行 x64 应用） | 安装时拦下：“xPaste 在 ARM 设备上需要 Windows 11……” |
| Windows 没有 WebView2 运行时（部分 Windows 10） | 安装程序在线下载运行时 | 下载失败时由运行时安装程序报错；离线电脑装不上（README 已写） |
| Linux | 不支持（规格说明第 8 章） | 没有安装包 |

## 2. 功能与平台、版本

| 功能 | macOS | Windows | 不可用时的提示 |
| --- | --- | --- | --- |
| 剪切板历史、搜索、预览 | 全部版本 | 全部版本 | — |
| 回车自动粘贴 | 需要“辅助功能”权限 | 不需要权限；粘贴不进管理员权限的窗口 | 没权限时只复制，提示条带“前往授权”；Windows 目标是管理员窗口时只复制并说明原因 |
| 面板材质 | 毛玻璃 | Windows 11 Mica；Windows 10 不透明 | 不需要 |
| 图片文字识别（M22） | Vision，全部版本 | 需要系统装了 OCR 语言包 | 设置里显示“当前系统没有可用的文字识别语言，可在‘设置 > 时间和语言 > 语言’中为中文添加‘光学字符识别’” |
| 截图、贴图（M23） | 需要“屏幕录制”权限 | 不需要权限 | 没权限时不出遮罩，面板弹授权确认框，页名按系统版本（15 起“录屏与系统录音”） |
| 长截图（M23 规则 13） | 全部版本，截屏用 ScreenCaptureKit 画面流 | 全部版本，未在实机验证。Windows 11（build 20348 起）用 Windows.Graphics.Capture 画面流；Windows 10 与画面流启动失败时每 40 ms 逐帧截屏 | 自动滚动（设置里默认关，关着时按空格开始这一次）：macOS 需要辅助功能权限，Chrome 等网页已在实机验证（见验收记录“长截图自动滚动”），没有权限时手动并提示“滚动选区里的内容 · 授权辅助功能后可自动滚动”；Windows 不需要权限，也未在实机验证，滚动落在指针下的窗口；应用不响应时转手动并提示“这个窗口不响应自动滚动，请自己滚动”。接不上时提示“滚得太快没接上，往回滚到预览里的位置”；连续 3 秒接不上时提示“这里一直接不上（画面在变？），↩ 保留已拼好的部分” |
| 录屏（M24） | 13 起 | 不支持 | 设置里不显示录屏几项、不注册录屏快捷键；README、官网写明仅 macOS |
| 录屏麦克风 | 15 起 | — | 13–14 上工具栏麦克风开关不可用，悬停提示“麦克风需要 macOS 15” |
| 系统翻译（M26） | 26 起 | 不支持 | 低于 26 时设置里没有“翻译方式”，只用 OpenAI 兼容接口；没配置接口时提示去设置 |
| 划词翻译 | 模拟 `⌘C`，需要“辅助功能”权限 | 模拟 `Ctrl + Insert`，不需要权限 | 没权限时翻译剪切板里的内容并说明 |
| 开机启动 | LaunchAgent | 当前用户启动项 | — |

## 3. 显示器

| 情况 | 支持情况 | 说明 |
| --- | --- | --- |
| Retina / 高分屏、普通屏 | 支持；截图按各屏物理像素导出 | 已验证 Retina |
| 多块屏、缩放不同 | 支持：每块屏一个遮罩，选区只在一块屏内，吸附框按各屏缩放换算 | 混合缩放待实机验收（AC-M23-10） |
| Windows 125% / 150% 等小数缩放 | 截图、贴图支持。长截图：个别应用滚动时内容落在小数像素上，精确比对接不上，由近似比对接上（每次可能差不到 1 行） | 接不上时有提示（见上表）。待 Windows 实机确认 |
| 广色域（P3） | 冻结画面转换到 sRGB，前端按 sRGB 画，颜色不偏 | 实现见设计 §8 第 1 条，没有单独验收 |
| HDR（macOS EDR、Windows 开着 HDR） | 截图按 SDR 截取；Windows 开着 HDR 时 GDI 截图可能发灰或过曝 | 没有提示；见第 5 节优化方案 |
| 带刘海的 MacBook | 遮罩覆盖整块屏，包括菜单栏与刘海区域 | 按设计实现（设计 §4.3），没有单独验收 |

## 4. 权限与系统设置

| 设置 | 影响 | 提示 |
| --- | --- | --- |
| macOS 辅助功能 | 自动粘贴、划词翻译取选中文字、长截图自动滚动（没有时长截图改手动滚） | 提示条与设置里的“前往授权” |
| macOS 屏幕录制 | 截图、长截图、录屏 | 按快捷键时弹授权确认框 |
| macOS 麦克风 | 录屏带麦克风 | 第一次弹系统授权框；没权限时本次不录麦克风并通知 |
| 系统通知被关掉（或未签名的 macOS 版通知不出） | 原来录屏、长截图的结果，启动时快捷键被占用，都只靠系统通知，关掉后用户看不到 | 本次改为：录屏与长截图的结果、录制中按截图快捷键的提示，显示在屏幕左下角的提示条里（边框窗口，不依赖通知）；被占用的快捷键在打开设置时标红（“……快捷键被其他应用占用，没有生效，请换一个”），唤起快捷键另有托盘标记 |
| 减少动态效果 | 全部动效即时完成 | 不需要 |
| 键盘布局（Dvorak 等） | macOS 自动粘贴按物理键位发 `⌘V`，可能粘贴失败 | 没有提示（已知限制） |

## 5. 已做的优化与还能做的

**本次已做**

1. 录屏、长截图的结果显示在屏幕上（边框窗口左下角的提示条，停留 2.4 秒），失败或录制被中断时另发系统通知。不再完全依赖系统通知。
2. 打开设置时，启动时被占用、没注册上的快捷键在录制框下标红，所在标签出红点。
3. Windows 安装程序：Windows 10 on ARM 直接拦下并说明原因；低于 21H2 时提示风险，由用户决定。
4. 长截图：先在已拼好的长图最后 4 屏里找位置，找不到（近似比对也找不到）再在整张长图里找；先认像素完全相同的行，重叠至少 1/5、要明显胜过错开的位置；找不到时和上次接上的那帧近似比对（背景图不动的终端、半透明窗口、小数像素滚动），只有一个像样的位置才接，宁可接不上也不接错；连续 3 秒接不上时提示可以保留已拼好的部分。截屏改用区域画面流（macOS ScreenCaptureKit、Windows 11 Windows.Graphics.Capture，最多每秒 60 帧；Windows 10 逐帧），只有画面变了才出帧，不再每 40 ms 截一次。第一帧等画面稳定再截（遮罩淡出中截到的第一帧颜色差一点，之后每帧都接不上）。

**试过但不做**

- 长截图在已拼好的长图最后 4 屏里近似比对（亮度轮廓找候选、再逐像素核对）：“一行行只差几个字”的内容甩出已拼好的部分时会错开整行接上。现在的近似比对只和上次接上的那帧比，并要求只有一个像样的位置，见[验收记录](验收记录.md)“截图收尾去抖与长截图”“长截图在终端里接不上”。

**可以做的优化（没做，按价值排序）**

| 优化 | 解决的问题 | 代价 |
| --- | --- | --- |
| 普通截图与冻结画面改用 Windows.Graphics.Capture（长截图已用，见上） | HDR 下截图发灰、过曝；截一帧更快 | 中：要处理 D3D 纹理与 HDR 色调映射，Windows 10 1903 起可用；长截图的画面流只覆盖 Windows 11 |
| macOS 截屏改用 ScreenCaptureKit（`SCScreenshotManager`，14 起） | 普通截图与冻结画面仍用已废弃的 `CGDisplayCreateImage`、`CGWindowListCreateImage`（长截图已用 ScreenCaptureKit 画面流），系统哪天移除后截图失效 | 中：异步接口，13 上仍要保留旧路径 |
| Windows 录屏（Windows.Graphics.Capture 加 Media Foundation） | Windows 用户没有录屏 | 大：单独一期（规格说明第 8 章） |
| Windows ARM64 原生安装包 | ARM 设备上靠模拟运行，耗电与速度差 | 小到中：CI 加 `aarch64-pc-windows-msvc` 目标，平台层没有架构相关代码 |
| 最低版本提到 macOS 13.1 | 13.0 上部分样式缺失 | 极小：改 `minimumSystemVersion`；13.0 用户会被系统拦下，要先升级 |
| 检测通知权限 | 关掉通知时，启动时快捷键被占用也能当场看到 | 小：插件的权限查询在桌面端不可靠，现在用“打开设置时标红”兜底 |

## 6. 需要实机验证的

按优先级：

1. Windows 10 21H2 与 Windows 11 x64：截图、贴图、长截图（含画面流：Windows 11 无黄色边框、Windows 10 退回逐帧）（125%、150% 缩放各一次）、文字识别、安装程序的版本提示（验收记录“阶段12-W1”“长截图-Windows”）。
2. Intel Mac：长截图截一帧的耗时（日志“{mode} N 帧 平均处理 Tms，没接上 L 帧”）、录屏。
3. 两块缩放不同的显示器上截图与长截图（AC-M23-10）。
4. 系统里关掉 xPaste 的通知后：录屏、长截图的结果提示条，以及启动时快捷键被占用后打开设置的标红。
5. Windows 11 on ARM：能否正常安装运行。
