# 已知限制

当前版本已知的限制与未验证项，按类别列出。按系统、芯片、显示器与权限整理的支持情况与提示见[设备支持](设备支持.md)。真机验收进度见[验收记录](验收记录.md)。

**性能**（阶段 8 测量：macOS 27、Apple M1、release 构建、5000 条记录，见[验收记录](验收记录.md)“测量摘要（阶段 8）”）

- 唤起到第一帧 166 ms（中位数，最大 183 ms），目标 100 ms：5000 条时变慢，可能是每次显示同步重渲染列表。记录少（百条左右）时多在 100 ms 以内。
- 空闲内存与 CPU 待重测（阶段8-空闲测量）：那次采样被打断，内存 footprint（含 3 个 WebKit 子进程）最小样本 265.8 MB，均在操作期间或刚结束时采得，目标 150 MB；CPU 样本同样无效，目标 < 1%。
- 启动后第一次唤起时，第一个搜索按键约 110 ms（目标 50 ms），之后 20–40 ms。
- Windows 的性能还没有测。

- macOS 13.0 自带的 WebKit（Safari 16.1）不支持 `color-mix()`，部分描边、选中高亮与光晕不显示；13.1 起或更新 Safari 后正常。
- Windows 开着 HDR 时，截图（GDI 截屏）可能发灰或过曝，没在实机上验证；Windows 11 on ARM 靠 x64 模拟运行，没测过。

**发布与数据**

- 安装包未签名、未公证，首次打开要手动放行（见 [README“下载安装”](../README.md#下载安装)；拿到证书后的步骤见 [CONTRIBUTING“签名与公证”](../CONTRIBUTING.md#签名与公证)）。
- 没有自动更新，托盘菜单里也没有“检查更新…”，新版本要手动下载安装。
- 数据库没有加密（本机明文 SQLite，靠系统账户权限保护）。
- macOS 分 Apple 芯片（aarch64）与 Intel（x64）两个安装包，没有通用（universal）版本。
- dmg 打开后没有窗口图标摆位（无界面打包跳过了 Finder 布局），“应用程序”快捷方式还在，拖进去即可。
- Windows 安装界面只有简体中文。
- 崩溃后不会自动重启。已写入的记录不丢，开机启动项保留，下次登录或手动打开即可恢复。

**macOS**

- 其他应用占用同一快捷键时检测不到：`global-hotkey` 是非独占注册，两个应用会同时响应，xPaste 不会提示“快捷键被占用”。
- 卸载时无法询问是否删除数据（拖进废纸篓没有卸载程序），数据要手动删，见 [README“卸载”](../README.md#卸载)。
- 开机启动用 LaunchAgent（`~/Library/LaunchAgents/` 下的 plist），不是 SMAppService；系统设置的“登录项”里同样显示 xPaste。
- 开发版（`xpaste`）与正式版（`xPaste`）在“辅助功能”列表里是两个条目，要分别授权。重新构建开发版后签名会变，要删掉旧条目再添加。
- 未签名包每次升级后，临时签名的身份都会变，“辅助功能”授权多半要删掉旧条目再重新添加。
- 自动粘贴按物理键位发送 `⌘ + V`（`kVK_ANSI_V`）：Dvorak 等 V 不在这个键位上的键盘布局下，可能粘贴失败。
- 毛玻璃材质下，隐藏与显示的整窗淡入淡出改过之后还没在实机上目视确认（阶段7-T7-a）。主线程卡顿时，面板可能在淡出完成前就消失。

**Windows**

- Windows 端的代码在 CI 的 Windows 机器上编译并跑通全部单元测试，但还没有在真机上手动验收，以下几条来自实现与审查。
- 覆盖安装时选了“安装前卸载”，或者卸载时保留数据再重新安装：设置里“开机时启动”仍显示开启，但卸载已经删掉注册表 Run 值，实际不会开机启动。在设置里关掉保存、再打开保存即可恢复（自动重新同步是后续工作）。
- 从托盘图标或托盘菜单打开面板时没有可粘贴的目标窗口，Enter 只复制并提示。
- 标题栏没有关闭按钮。从托盘打开面板时，如果系统没把前台焦点交给面板，Esc 和点击面板外部可能都隐藏不了它，这时再按唤起快捷键或单击托盘图标（还没在 Windows 上验证，见验收记录 阶段9-F04）。
- 目标窗口以管理员身份运行而 xPaste 不是时，系统拦截模拟按键，Enter 只复制并提示（规格说明 M09 规则 3）。
- 托盘左键单击按松开计：面板隐藏后 300 ms 内的单击不重新显示；按住超过 300 ms 再松开，会把面板重新打开。
- Windows 10 上面板为不透明背景，不用 Acrylic。
- 链接标题只取浏览器复制时附带 HTML 里的锚文本，不解析 Firefox 的 `text/x-moz-url`。
- 没有透明通道的老式应用图标按不透明处理，可能显示为带底色的方块。
- 图片文字识别要用系统的 OCR 语言包：一个都没有时图片显示“本机不支持”，设置里会提示到“设置 > 时间和语言 > 语言”为中文添加“光学字符识别”。装好后重启 xPaste，开着“为已有图片补识别”时会补上之前的图片。Windows 端的识别在 CI 上通过了测试（含连续多次识别），识别效果还没有在真机上验证。

**截图与贴图**（阶段 12，规格说明 M23）

- 选区不能跨显示器，只能在一块屏内框选；要截两块屏，分开截两次。
- macOS 截图需要“屏幕录制”权限（macOS 15 起系统设置里叫“录屏与系统录音”），授权后要退出并重新打开 xPaste。macOS 15 起系统会定期再次询问是否继续允许，这是系统行为，xPaste 关不掉。
- 录屏只在 macOS 上有（见下文“录屏”），Windows 录屏另做一期。
- 贴图只在本次运行内有效：退出 xPaste 后全部消失，重启不恢复，也没有贴图库。
- 贴图拖出屏后，按松开鼠标时所在显示器的工作区拉回，顶边不能超出工作区：上下排列的多块显示器之间，贴图顶边过不了所在屏的上沿；macOS 上贴图拖不进菜单栏那一行。
- Windows 上遮罩页面的进程（WebView2）意外退出后，遮罩在 3 秒内自动撤下并尝试重新加载页面；进程已退出时能否重新加载还没在 Windows 实机上验证，之后截图不出现时要重启 xPaste（macOS 上会自动重新加载）。
- 进程里第一次识别文字要加载系统模型，约 8–13 秒。第一次按截图快捷键时会在后台预加载，预加载完成后按 O 不再等；按截图快捷键后马上按 O 时仍可能要等（期间显示“正在识别文字…”，等多久待真机确认），之后每次通常不到 1 秒。
- 唤起与截图两个快捷键成对注册：其中一个从启动起就被其他应用占用时，只改另一个保存也会失败（错误显示在被占用的那一行），要把被占用的也换掉。macOS 上同一快捷键被其他应用占用时检测不到（见上文 macOS 第一条），默认的 `⌥ ⇧ A` 与其他截图工具冲突时两边会同时响应。
- macOS 每块 2880 × 1800 的屏冻结约 55–78 ms（要把画面转换到 sRGB），接多块大屏时离 300 ms 的上屏目标会更近。
- 还没在真机上验证的：Windows 端的截图与贴图（只在 CI 上编译并跑通单元测试）；多块屏时在光标所在屏以外的屏上框选后，回车与 Esc 是否落到这块屏；贴图能否接收键盘（Esc、`Mod + C/S/0`）；贴图的系统阴影、Windows 11 自动圆角与 6 px 圆角是否冲突；贴图拖动结束的判断；滚轮缩放的手感。见[验收记录](验收记录.md)“阶段 12 截图与贴图”。

**长截图**（规格说明 M23 规则 13）

- 默认自己滚；设置“长截图自动滚动”开着时自动滚动（只发滚动事件，不发按键、点击，不动指针），关着时可按空格开始这一次的自动滚动。自动滚动不知道用户想停在哪，只会滚到底（所以默认关）。只往下拼接。自动滚动的限制见下面几条。截屏用画面流（最多每秒 60 帧；Windows 10 每 40 ms 逐帧，一帧约 50–80 ms），触控板用力一甩会在两帧之间滚过一整屏，这时接不上，要往回滚到与预览重叠的位置；往回超过 4 屏也接不上。
- 先按行精确比对，找不到时只和上次接上的那帧近似比对，宁可接不上也不接错。以下情况可能一直接不上（连续 3 秒接不上时提示可按 ↩ 保留已拼好的部分）：选区里有一直在变的大块内容（视频、动画）。背景图不随文字滚动（终端背景图、半透明窗口）时能接上，但长图里的背景是一段段拼起来的。近似比对只往下找：这类画面往回滚时报没接上，滚回来接着拼；小数像素滚动时每次接上可能差不到 1 行。一行行很像的内容（代码、表格、列表）在滚得很快、两帧只重叠一点时会报接不上，慢一点滚即可。
- 自动滚动：
  - 完全周期的内容（一行行完全相同）里，学到的比例若差了整整一个周期，预期位移会把位置指到错的周期上。预期只在测到比例之后才给，且只缩小范围，范围内仍要明显胜出；这类内容本来就可能接不上。
  - Windows 滚轮作用于指针下的窗口，并依赖系统设置“鼠标悬停在非活动窗口上时滚动它们”（默认开）；关掉后只滚前台窗口，选区不在前台时表现为不响应。指针移出选区时暂停，不会替用户移动指针。
  - Windows 上经远程键鼠软件（Mouse Without Borders 等）注入的输入认不出来，用户通过它操作时不会触发让出。
  - 忽略合成滚动的应用和管理员权限窗口：转手动并提示“这个窗口不响应自动滚动，请自己滚动”。macOS 没有辅助功能权限时也是手动，边框窗口不接收点击，没有“前往授权”按钮，要到设置或提示条里授权。
  - macOS 上按住空格不放会自动重复，重复的按键会被当成用户接手，并多次切换暂停与继续。
  - 能自动滚动时（macOS 有辅助功能权限、Windows），即使设置关着、手动滚，空格也被长截图占用（用来开始自动滚动），不能用空格给被截的应用翻页。
  - 平滑滚动动画超过 1 秒的应用，会被提前判为画面停下，测得的位移偏短（比例只学预期一半到两倍内的位移，影响有限）。
  - macOS 滚动是否落在选区中心下的窗口（而不是指针下的窗口）、本进程发的滚动是否不被算作用户输入，还要真机确认，见[验收记录](验收记录.md)“长截图自动滚动”。
- 闪烁的光标、悬停高亮等零星变化的几行可能接不齐；整页渐变背景、视差滚动、滚动时位置会变的吸顶栏可能对不上或重复。区域右侧 24 逻辑像素（滚动条）不参与比对，长图右边那一列来自不同的帧，滚动条会断断续续。
- 长截图期间回车、Esc 被注册成全局快捷键，在其他应用里按也只会完成或取消长截图；期间在设置里改快捷键（重新注册全部快捷键）后回车、Esc 失效，只能再按截图快捷键完成。
- Windows 11 的画面流在 24H2 之前按屏幕刷新率送帧（高刷屏上 CPU 占用高一些）。选区跨屏或关不掉系统黄色边框时退回逐帧；拼接过程中显示器分辨率变化会使画面流中断，按回车处理、保留已拼好的部分。
- Windows 10 与画面流启动失败时的逐帧截屏不带 `CAPTUREBLT`（带上它每秒截 10 次光标会闪），分层窗口（WPF 透明窗口、部分 Electron / Qt 透明窗口、贴图）截不进去，这类窗口里的内容不能长截图。
- 预览只显示长图最下面的一段（高同选区），缩小后小字看不清，用来看接缝是否连续；完整的长图在完成后从历史里看。
- 完成后只写剪切板（进历史），不能直接保存、标注、贴图；PNG 超过 M01 的大小上限时不会进历史。
- macOS 普通截图、冻结屏幕和画面流退回逐帧截屏时用 `CGWindowListCreateImage`（只截边框窗口之下的内容），是已废弃的接口，系统真正移除时要换 ScreenCaptureKit；长截图的画面流已经用 ScreenCaptureKit。
- 长截图期间 macOS 会显示系统的屏幕录制指示（ScreenCaptureKit 的行为），结束后消失。
- 还没在真机上验证：Windows 端（边框窗口用 `WDA_EXCLUDEFROMCAPTURE` 排除，需要 Windows 10 2004 及以上；更早的系统上边框和提示可能被截进去）；Retina 屏上触控板惯性滚动、网页平滑滚动时是否都能逐帧接上。

**录屏**（阶段 13，规格说明 M24）

- 只在 macOS 13 及以上提供。Windows 没有录屏：不注册录屏快捷键，设置里也没有录屏几行，Windows 录屏另做一期。
- 麦克风要 macOS 15 及以上；macOS 13–14 上麦克风开关不可用，只能录画面和系统声音。
- 同时录系统声音和麦克风时，视频里是两条音轨（系统声音在前），没有混成一条。QuickTime 会两条一起播，部分播放器和网页只播第一条，听不到麦克风。
- 输出的长边最多 3840 像素：5K、6K 屏全屏录制会等比缩小到 3840 × 2160，不是原生分辨率。
- 帧率只有 30 和 60 fps 两档，清晰度只有高、标准、小文件三档（不能自定义分辨率或码率）；只输出 MP4（H.264 + AAC）；没有 GIF、没有暂停后继续、不显示按键和鼠标点击。
- 录完的结果显示在屏幕左下角的提示条里（不带缩略图），失败与中断另发系统通知；录制被中断且被录的显示器已拔掉时，只有系统通知，系统里关掉了 xPaste 的通知就看不到，视频照常保存。
- 选区不能跨显示器；录制中被录的显示器断开、屏幕录制权限被撤销时，最多 1 秒后停止，已录的部分照常保存。
- 录制中不能截图（截图遮罩会被录进视频），要先停止录制。
- 录制中改了录屏快捷键，托盘“停止录制（…）”显示的仍是旧快捷键，下次录制才更新。
- 只有从菜单栏“退出 xPaste”会先停止录制、写完文件再退出。录制中注销、关机，或用 ⌘Q 让系统结束 xPaste 时，系统不给推迟退出的机会，正在录的视频会缺少收尾信息、无法播放。
- 录制中退出 xPaste 时会先把视频写完、等约 1 秒让它进入历史再退出；写文件卡住时退出最多推迟 45 秒，这期间再退出一次会立即退出，视频可能打不开。极少数情况下（开始录制的那一两秒里退出、又恰好卡住）可能留下一个打不开的文件。
- 还没在真机上验证的：麦克风那一路（macOS 15 起，两条音轨）；录制边框是否真的没被录进视频（取决于系统能否马上列出刚显示的边框窗口）；铺满整块屏的透明边框窗口在调度中心、菜单栏、其他显示器上的表现，以及是否抢焦点；设置页录屏几行的显示。见[验收记录](验收记录.md)“阶段 13 录屏”。

**片段**（阶段 14，规格说明 M25）

- 改过内容的片段只保留纯文本：原来从历史带来的富文本格式（HTML、RTF）不再保留，粘贴出去就是纯文本。只改名字不影响格式。
- 截图等位图图片片段是独立拷贝；来自文件的图片、视频、文件片段引用原文件，文件被移动或删除后，片段还在，但粘贴不了（提示“原文件已移动或删除，无法粘贴”）。
- 从历史存来的文件片段搜不到文件里的文字（“搜索文本文件内容”读入的部分不带进片段），只能按名字、文件名和路径搜。
- 片段在库里按“置顶”存，所以任何清理都不会动它。换回旧版本后，片段会显示成一条置顶的历史记录（标题是名字），旧版本不认识它。

**翻译**（阶段 15，规格说明 M26）

- 翻译要联网：OpenAI 兼容接口把要翻译的那段文字发到你配置的地址，请求按系统代理设置发出。接口地址是本机的服务（如 `http://localhost:11434/v1` 的 Ollama，主机为 `localhost`、`127.*`、`::1`）时不出本机、不走代理；系统翻译在本机完成。
- 系统翻译需要 macOS 26 及以上；macOS 26 以下设置里没有“翻译方式”，只能用 OpenAI 兼容接口。缺语言包时可在设置、面板提示条或划词卡片里点“下载语言包”，由系统弹出下载确认（阶段 15.1）；截图译文卡片上没有这个按钮，要到设置或面板里下载。系统确认框弹不出来时，退回打开“语言与地区”页，要自己在这一页最下方的“翻译语言…”里下载。
- Windows 上没有系统翻译，设置里没有“翻译方式”，只能用 OpenAI 兼容接口。
- 只支持 OpenAI 兼容的 Chat Completions 接口，只能配置一个服务；Anthropic、Google 等其他格式的接口要经兼容层转换。
- API Key 存在本机数据库里，和其他设置一样是明文，没有放进系统钥匙串（见上文“数据库没有加密”）。
- 每条记录只存最新一份译文；改了目标语言后旧译文照常显示，要点“重新翻译”。译文不参与搜索。原文最多 10000 个字符。
- 截图的译文卡片不能钉在屏幕上，复制后作为一条文本记录进历史。
- 系统翻译不能用提示词约束：命令、路径、代码里的单词也可能被翻译（实测 “Run pnpm install” → “运行pnpm安装”）。需要原样保留时换用 AI 翻译（OpenAI 兼容接口）。
- 升级到阶段 15.1 之前存下的译文没有记下翻译方式：标题行不写“系统翻译 / AI（…）”，也没有“换用…”按钮；点“重新翻译”后照常标注。
- 下载语言包期间收起面板或划词卡片会结束等待（按取消处理），已经开始的下载可能由系统在后台继续，xPaste 这边不提示，要重新打开设置看状态。
- 系统翻译的源语言由系统识别：几个字的短文本可能识别不准或识别不出（提示“系统翻译不支持这种语言”）。
- 还没在真机上验证的：系统翻译下载语言包后的实际耗时；下载确认框弹不出时退回打开的“语言与地区”页能否看到“翻译语言…”；中途切换系统代理后翻译是否立即跟随；Windows 上的 `Ctrl + T` 与 WebView2 自带快捷键是否冲突。见[验收记录](验收记录.md)“阶段 15 翻译”。

**划词翻译**（阶段 15.1，规格说明 M26 规则 18、19）

- macOS 上划词翻译要“辅助功能”权限（和自动粘贴是同一个）：没有时不能模拟复制，翻译的是剪切板里的文字，卡片上带“前往授权”。
- 取词靠模拟一次“复制”，不读其他应用的选区：选中的文字会作为一条普通复制进历史；应用不支持复制（或复制出来的不是文字）时，翻译的是剪切板里原有的文字。
- Windows 上模拟复制用 `Ctrl + Insert`（终端里 `Ctrl + C` 会中断命令）：个别不认 `Ctrl + Insert` 的应用里，翻译的是剪切板里原有的文字，而不是选中的文字。
- 按快捷键后 500 ms 内没松开修饰键时不模拟复制，直接翻译剪切板里的文字。
- 划词卡片不能钉住、不能拖动，点别处就关闭；卡片里不能改目标语言或编辑原文。卡片翻译的结果不存进任何记录。
- “密码管理器”按“不记录这些应用”判断（默认列表里有 1Password、钥匙串访问等），不在列表里的密码管理器靠剪切板的敏感标记拦下。
- 下载确认框弹不出、退回打开“语言与地区”页时，卡片会拿回键盘；用户回到系统设置操作时卡片随失焦关闭，提示随之消失。
- 还没在真机上验证的：卡片能否拿到键盘且前台应用不变、关闭后打字回到原应用；面板开着（含设置对话框）时弹卡片面板不隐藏；Windows 上提示不抢前台、2 秒后收起，`Ctrl + Insert` 在 Windows Terminal、PowerShell、cmd、浏览器、VS Code、记事本里是否都是“复制”；混合缩放的多屏上卡片位置。见[验收记录](验收记录.md)“阶段 15.1 划词翻译与语言包下载”。

**两端通用**

- 首次引导中，只有按唤起快捷键算“试按成功”；托盘单击、再次启动应用、从访达重开都不算（阶段 6 起的规则）。
- 拖动面板只在本次显示有效：下次唤起仍按鼠标所在屏幕定位，不记住拖到的位置。
- 设置或确认对话框打开时，点面板外部不会隐藏面板（切出去查东西时修改不丢）；要隐藏，先按 Esc 关掉对话框。
- 视频：`mkv`、`avi`、`wmv`、`flv` 不能在预览里播放，预览显示“无法在预览中播放这个格式”（macOS 上这几种也读不出时长和封面）。视频获得焦点时按 `Space` 切换播放 / 暂停，已实现，还没在实机上验证。
- 面板打开时外部连续复制多条，新记录只插入列表、不改选中项，选中行可能被推到可视区外（阶段7-T4-a，待确认）。
- 亮色主题下，几处用类型色的文字对比度低于 4.5 : 1，如标题栏“正在记录”、频谱最后一个刻度、“用过 N 次”、代码高亮、选中行序号（阶段7-T6-c，待定）。
- 截图记录的标题（`截图 YYYY-MM-DD HH.mm.png`）阶段 10 起按本地时间生成；之前录下的截图标题仍是 UTC 时间，不回改。
- 图片文字识别：应用启动后第一次识别要加载系统模型，约 8 秒（开发构建实测 13 秒），之后每张通常不到 1 秒，所以刚启动时截的图要稍等才能按文字搜到。面板打开时不开始新的识别（点“重新识别”除外），隐藏后继续。大于 20 MB 或长边超过 8000 px 的图片不识别，显示“已跳过”。一次复制多张图片时最多识别前 10 张。不识别视频和 PDF。
- 设置里打开“搜索文本文件内容”（默认关）后，复制文件时文本类文件（txt、md、csv、json、代码等）的前 64 KB 内容会进入搜索范围，但不显示；二进制文件不读。内容只在复制时读一次，之后文件改了搜不到新内容；打开前复制的文件不会补读。
- 搜索 3 个字符以上的词走本地全文索引，历史再多也是毫秒级；1–2 个字（如两字中文词）按顺序扫描，历史里文本总量很大时会慢一些。索引会让数据库文件增大约一半，首次升级时建索引需要几秒。
- 选中行被鼠标滚轮滚出可视区后，按菜单键或 `Shift + F10` 不弹菜单；用方向键移动会把选中行滚回来。
- 读屏：列表行的 DOM 顺序不一定等于视觉顺序（行不可聚焦，读屏通过 `aria-activedescendant` 跟随选中项）。
- 启动瞬间删除的记录，可能被启动快照带回列表，下一次删除事件或重启后消失。
